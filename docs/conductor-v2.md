**一句话**：打开 iPhone 控制中心里的遥控器，选这台 Mac；往下滑展开刘海那一排，点一下编程会话走进去；在触控区画一个声调选思考档位，打几拍选更高的档；按住侧边按钮说一句，
松开是草稿；按播放键发出去。每一步刘海都即时说清：画到哪、认出了什么、后端真的接受了没有。不动光标，不碰前台窗口。

## 和 v3 不同的地方

1. **按 Aaron 给的真实遥控器截图排键。**iOS 控制中心的遥控器上是：静音、选择电视、电源；触控区；播放/暂停、返回、电视键。
   **没有 Siri 键**：Apple 的说明是按住 iPhone 侧边按钮用 Siri（[Apple 支持](https://support.apple.com/en-us/102337)）。音量是 iPhone 侧面的音量键。
2. **声纹进高风险放行**（Aaron 2026-10-03 定：声纹作辅助因素）。v3 原来不让声纹产生授权。
3. **加了两条新路**：静音键管 Mac 上的提示音；iPhone 键盘（含听写）可以改草稿（要实验 E3）。
4. **没有模式切换，只有层**（Aaron 2026-10-08 定）。手机上看不出现在是遥控还是指挥，所以不再用一个键换模式：
   - 遥控器碰到刘海那一排里的会话格，点一下**走进去**就是指挥模式；返回、往上滑或电视键退回那一排。遥控模式是在那一排里走动。
   - 同一次配对、同一条连接、同一套键。设置里遥控模式是总开关，指挥模式是它下面的一项，打开后那一排才出现会话格。
   - 去掉“档位 / 模型”两个域：手势只管档位；模型在会话里往下滑，在四个位置里挪焦点选。
   - 每个键有一句不随层变的意思：播放键“开始或停下眼前这件事”，电视键“回到刘海那一排”，电源“收工”，返回“取消眼前这一件，没有了就退一层”。

## 手势

手势只管档位。模型不用手势选（见键位表“往下滑”）。

| 手势 | 档位 |
| --- | --- |
| 一声 → | low |
| 二声 ↗ | medium |
| 三声 ˇ | high |
| 四声 ↘ | xhigh |
| 一到四拍 | low…xhigh |
| 五拍（3+2） | max，点一下确认 |
| 六拍（3+3） | ultra：后端有原生值才给；Claude 是“ultracode · xhigh · 工作流程开启”；都没有就“没有 ultra，保持原设置” |

四个模型位置在设置里定（provider + model ID），不随后端列表的排序变；在会话里往下滑选。判定规则、拒识条件照 `ConductorGesture.swift` 和 v3 §5；
五拍画到第四拍只亮第四个点，不先切到 xhigh。速度不改档位。

## 放行

- **普通**（读文件、跑测试、改工作区里的文件）：审批出现后点一下 = 允许这一次；返回 = 不允许。
- **高风险**（推送、删除、联网、改工作区外的文件、关安全设置）：点一下后刘海给一句随机短语，按住侧边按钮念。
  **配过对的 iPhone（持有）+ 声纹 + 短语（活体）**三样都对才放行；或者到 Mac 前按 Touch ID。声纹不单独放行。
- 审批出现前的那一下不算；遥控器上没有“始终允许”；每次放行绑定请求号、命令、范围，走授权账，用一次作废。

## 提示音（静音键开关）

每完成一拍轻敲一下；认出声调回一个同走向的短音（一声平、二声升、三声先降后升、四声降）；没认出一声低闷的“咚”。跟系统音量走。

## 结构

> 2026-10-03 补：协议层优先用 Swift，零件取自 itsytv-core（MIT），atv-core 只当参考；实体 Siri 遥控器是第二个输入来源（触控面经 MultitouchSupport、麦克风在 `0xFA`），可能先于 iPhone 那条路跑通。见 [input-devices.md](input-devices.md)。

```text
Swift 独立接收器（prototype/Support/WS2Companion*、WS2PairSetupServer 管配对与通道；App/WS2RemoteHost 接进应用。宣告、配对、原始事件；不碰任何项目和模型）
   ↓ 版本化、验过签名的事件：touch(begin/move/end/cancel)、button(down/up/cancel)、connection
按层分发（和遥控模式共用）：第 0、1 层走焦点导航与刘海那一排；走进会话后才交给 ↓
prototype/Core/ConductorSession.swift（纯逻辑：状态机，输入事件 → 新状态 + 要做的事）
   ├─ ConductorGesture（已有）
   ├─ ConductorCapabilities（后端能力 → 允许的档位、ultra 的含义、高开销确认票据）
   ├─ 已有活动协调器（新增活动种类，不另起浮层）
   ├─ 语音采集 + 转写（来源可选）
   └─ Agent 适配器：Codex App Server（initialize、model/list、thread/start|resume、turn/start|steer|interrupt、审批）；Claude Agent SDK 持续会话
```

协议层不接收 shell 字符串、项目路径或模型密钥；它崩了不影响 WindowShade 找回窗口。

## 隐私登记（进 privacy-page 的登记表）

遥控器的触摸轨迹（只在遥控模式开着时，不存；画档位只在会话里）；按住侧边按钮时的声音（转写后丢弃，不写日志）；声纹模板（加密存本机）；配对密钥（钥匙串）。

## 能耗

只在遥控模式开着时宣告和监听；遥控器没连时不轮询；Mac 收到输入到刘海有反应 p95 ≤ 50 毫秒、抬手到结果 p95 ≤ 100 毫秒是目标，实测前不写进宣传。

## 2026-10-19 定案（优先于上文旧描述）

- **语音草稿识别在这台 Mac 上做**：系统语音识别，`requiresOnDeviceRecognition`，不做云端回退；
  触发是指挥页的「按住说话」，不是 iPhone 侧边按钮——系统遥控器不能替我们转写或传文字。
  最长 60 秒，松手出草稿，不自动发送；空结果／超时／未授权／中断各有提示。
- **Claude 后端走本地 `claude` CLI 的 stream-json 会话**，由 App 拥有进程，不把 API key 放进 App。
  先用只读（`--permission-mode plan --permission-prompts none`）接通发送与流式回复；
  工具审批的 host 协议之后单独做。
  指挥页有 Codex／Claude（只读）切换；Claude 一次只跑一轮（回答中不能再发），停止即结束本轮，
  再发送用 `--resume` 接回同一段对话；转写区显示模型、被拒工具；语音草稿与 Codex 共用。
  机器验收：`tests/run-claude-wire-tests.sh`、`tests/run-claude-session-tests.sh`、
  `tests/run-claude-conductor-tests.sh`（假 CLI，不发真实模型请求）；页面级可用
  `WINDOWSHADE_CLAUDE_EXECUTABLE` 指向假 CLI。
- **这一轮先把「指挥模式端到端」接成可真机试用**；所有 WS2 面继续藏在
  `WindowShade.Preview.WS2` 后面，验收过的才逐项露出。
