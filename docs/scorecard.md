## 性能做了什么（2026-09-28）

第一版数字（6.51%）是在机器被别的程序压满时量的，而且当时的归因是错的：我拿 `sample` 的采样行数当成了
CPU 占用，那其实是每轮都会记一次的线程数量，不是耗时。改成受控实验后结论是：

| 做法 | 60 秒平均 CPU |
| --- | --- |
| 加速度计 1000 µs（原来） | 4.55% / 5.42% |
| 同一构建、只把间隔改成 16000 µs | 1.68% / 2.85% |
| 改成 16000 µs 后的正式构建 | 2.70% / 2.25% / 2.18% |
| 关掉倾斜效果与传感器 | 0.10% / 0.75% |

这么做安全的理由：设备认 `ReportInterval`（实测 1000 µs → 807 次/秒、8000 → 134、16000 → 62），
而倾斜效果本来就按 80 毫秒低通、按屏幕刷新率渲染，62 次/秒的输入远在需要之上；改完回读设备，
报告率确实是 62.0 次/秒。
