# 画中画：调研与超越方案

2026-09-28。Aaron：“画中画是 iPadOS 多任务的重要组成部分，请你调研「神奇画中画」和「PiP」这两款 App，并且提出超越他们的方法。”

资料来自两款 App 的 App Store 资料（Apple 的公开查询接口 `itunes.apple.com/lookup`，美区、台区、国区各查一次）和它们在商店里的 iPad 截图，2026-09-28 读取；没有下载试用。

## 它们是什么

| | 神奇画中画（Magic PiP） | PiP - Picture in Picture |
| --- | --- | --- |
| 开发者 | Jinyu Meng | Supagarn Pattananuchart |
| 平台 | iPhone、iPad（iOS 15 以上） | iPhone、iPad（iOS 17 以上） |
| 价格 | 美区 $1.99、台区 NT$60；国区商店已查不到 | 免费（商店页没写内购） |
| 版本 | 3.8.0，2025-08-26（“支持放大展示”），之后没有更新 | 3.0，2026-09-20（“修正错误”），一直在更新 |
| 评分 | 美区 4.7（18 个） | 美区 4.5（329 个），台区 4.7（36 个） |
| 能放进画中画的 | 图片、视频（相册可多选翻页）、PDF、TXT（可自动翻页，适合看小说）、PPT / PPTX、剪贴板里的文字、网页、时钟 / 秒表 / 计时器、计数器 | YouTube 和 Safari 里的视频（Safari 扩展一键、分享链接）、后台播放、照片 / 相机 / 文件里的图片和视频、PDF、文字，自带一个有画中画按钮的浏览器 |
| 入口 | 分享菜单、快捷指令“打开文件” | Safari 扩展、分享链接、App 里打开 |

**两家用的是同一个办法。** iOS 的画中画只给视频用。它们把 PDF、文字、网页、时钟先画成一段视频，塞进系统的画中画窗口里。
神奇画中画的截图说得很直白：翻页用画中画自带的“快退 / 快进 15 秒”按钮，“播放”键改成截图，双指缩放，推到屏幕边藏起来。

所以它们的画中画**只能看，不能点、不能滚、不能打字**；能放的只有它们认得的那几种文件和视频，别的 App 里的东西（聊天、终端、表格、会议）放不进去；窗口的样子、大小几档、藏到边上，都是系统画中画给的，它们自己一样也没加。

## iPadOS 的画中画本身是什么样（我们要对上的手感）

- 浮在所有 App 上面，切 App、回主屏幕都在。
- 拖着走，松手按速度甩到最近的一个角落。
- 捏合改大小（几档之间跳）。
- 推到屏幕左右边外藏起来，边上留一小片带箭头的把手，往里一拉就回来。
- 点一下出控制：关掉、回到原 App、播放 / 暂停、快进快退。
- 同一时间只有一个。

macOS 自己的画中画也只给视频（Safari、TV、QuickTime），同样只有一个。

## 我们已经有的底子

“置顶”（PinnedPreview.swift）就是任意窗口的实时画面浮在最前：平时每秒 15 帧、指针在上面时 30 帧；指针一进去，真窗口交到前面，第一下点击也传过去，所以能直接点、滚、打字；多个置顶互相让位；“暂时取消全部置顶”一下让开，再按原来的前后顺序放回。
缺的是 iPad 画中画那套形态：缩小、甩到角落、推到边上藏起来、点一下出控制。

## 超越的方法

一句话：**任意窗口的实时画中画，手感照 iPad，滚动和翻页直接作用到原窗口，再加上它们都没有的“只看窗口里的一块”。**

| 它们 | 我们 |
| --- | --- |
| 只能放它们认得的文件、视频；别的 App 放不进去 | **任意窗口**都能进画中画：视频、会议、聊天、终端、构建日志、表格、文档 |
| 画面是它们重画的一段“视频”，不能点、不能滚、不能打字 | **实时画面**；滚轮直接滚原窗口；要点、要打字时双击，画面放大回原处、真窗口交到前面（缩小的画面和真窗口大小不同，不能在小画面上直接点） |
| 翻页靠“快进 15 秒”按钮，只对它们自己画的页 | 悬停出控制条：**上一页 / 下一页**直接发给原窗口（Page Up / Page Down，不抢焦点），对预览、图书、网页、任何 App 都有效；**播放 / 暂停**走系统媒体键 |
| 整个画面都进画中画，看 YouTube 连浏览器的边框、侧栏一起缩小 | **只看窗口里的一块**：框出视频播放器、会议里的发言人、终端最后几行、一张图表，只把这一块放进画中画（截取时直接裁，不多费电） |
| 系统给的形态：一个、四个角、几档大小 | iPad 的手感全有（甩到最近的角、滚轮 / 捏合三档大小、推到边上藏起来留箭头小片，和侧拉同一个样子），而且**可以同时开几个**，同一角落排成一列不叠 |
| 切到别的桌面、全屏 App 时由系统决定 | 跟着你到**每张桌面**、盖在**全屏 App** 上 |
| 藏起来只能藏到屏幕边 | 也能**收进刘海**：刘海那一排里有它，停一下看实时画面（刘海现有的看一眼） |
| 双击回原 App | 双击**回到原处、原大小**（真窗口从画中画的位置滑回去）；排布那本账照样能撤 |
| 视频、PDF 各一套入口 | 一个入口：拖着标题栏到屏幕**角落**停一下（和拖到边上进侧拉对称）、快捷键、窗口浏览菜单、刘海落点 |
| 小画面也按视频帧率画 | 小画面**每秒 10–15 帧**，指针在上面才 30 帧；藏到边上、收进刘海、被全部让开时**停掉画面** |

不做的：时钟、秒表、计数器、剪贴板文字这类小组件（神奇画中画有），和“让窗口让开、留下位置”不是一件事；也不在画中画里自己放视频文件（交给 QuickTime 的系统画中画）。

## 做到了哪一步（9 月 28 日晚，本地未发布）

- 代码：`App/PictureInPicture.swift`（控制器：进出、让开、吸附、藏起来、换大小、只看一块、发给原窗口）、
  `App/PictureInPictureViews.swift`（画面、控制条、边上小片、角落落点）、`Core/PiPLayout.swift`（纯算法，70 项单元测试）。
  截取复用置顶的 `WindowStreamCapture`，只加了一个画中画专用的输出设置（小尺寸、可裁一块），置顶、侧拉不受影响。
- 入口：菜单“画中画当前窗口”、快捷键（默认不占，设置 → 快捷键 → 当前窗口里录）、拖着标题栏到屏幕角落停一下。
  用过置顶的人，刘海上会教一次“拖到角落”。
- 真机探针 `bash tests/run-glance-probe.sh --pip`（临时 App 的长文窗口）：见下面“验证”。

## 怎么做（落到现有代码）

- **同一套画面**：复用置顶的截取和显示（ScreenCaptureKit 每扇窗一路流、AVSampleBufferDisplayLayer），只加一种“缩小到角落”的摆法；“只看一块”用 `SCStreamConfiguration.sourceRect` 裁。
- **iPad 手感**：拖动一比一跟手，松手用 `FluidMotion.projection` 推算落点吸到最近的角；推算落点出了屏幕边就藏起来，边上挂侧拉那片玻璃小片（`SlideOverEdgeTab`）。滚轮或捏合在三档大小之间跳（宽 240 / 360 / 520 点，按窗口比例）。
- **控制条**：指针停上去时浮出：回到原处、上一页、下一页、播放 / 暂停、关掉。播放 / 暂停发系统媒体键。
- **滚动和翻页**：原先打算把滚动事件定向发给那个 App（`CGEvent.postToPid`），9 月 28 日实测系统会把这种滚动事件丢掉
  （窗口在屏幕内、App 在前台也一样）；全局的滚动事件能滚，但会落到指针下别的窗口上。改成用辅助功能：
  找到原窗口里对应那一点的滚动区，读它的文档高度和看得见的高度，把像素换算成竖向滚动条的位置写进去——
  窗口推到屏幕外也有效（临时 App 的长文窗口实测 0 → 0.20）。没有滚动条的内容（有些网页里的内嵌区域、游戏、
  自己画的界面）滚不动，那时双击回到原处再滚。
- **入口**：标题栏拖到屏幕角落停 0.25 秒（仿 `SlideOverDropHint`，出现角落的虚影）；快捷键默认不占；窗口浏览菜单和刘海落点各加一项；菜单里“画中画当前窗口”。
- **名字**：界面上叫**画中画**（系统和 iPad 的叫法），动作是“画中画当前窗口 / 回到原处 / 只看一块…”；和“置顶”分开：置顶是原地原大小浮在最前，画中画是缩小到角落。
- **验收**：探针用临时窗口走一遍：进画中画后缩到角落、甩到另一个角、推到边上藏起来再拉回、上一页真的翻了原窗口、只看一块的画面尺寸对、双击回到原处原大小、藏起来时截取停了（帧数不再增加）；另量一次开着两个画中画时的常驻 CPU。

## 验证

```sh
bash tests/run-pip-layout-tests.sh           # 纯算法：三档大小、角落与同角成列、甩的落点、藏到边上、只看一块、真窗口让到哪、屏幕没了放回哪
cd prototype && ./build.sh --stage           # 签名隔离构建
cd .. && bash tests/run-glance-probe.sh --pip # 真机探针：临时 App 的长文窗口，不碰你的窗口
```

单元测试 70 项全过（9 月 29 日）。真机探针在修完审查问题后的签名构建上 **9/9 通过**（9 月 28 日 22:51）：
缩到最近的角、原窗口让到屏幕边外；松在另一个角就停在那个角；甩出屏幕边藏起来、留一小片、截取停了（帧数 23 → 23）；
点小片回到角上、画面又是实时的；大一档是 360 点宽；“下一页”翻了原窗口一屏，没把它带到前面；
“只看一块”只显示右半边；同一角的第二块排在旁边不叠；两扇都回到原处、画面收掉。

逐行审查在画中画这边查出 7 处，都改了：

- 退出动画那 0.28 秒里再进画中画，会把停在屏幕外的位置当成原处，窗口回不来。现在退出途中不再接受进入，
  放回后读回位置、确认到位才删恢复记录。
- 拖到屏幕角落进入时，把松手的位置当成原处，回到原处后窗口大半在屏幕外。现在原处记按下标题栏那一刻的位置。
- 收在屏幕边外的侧拉窗口进画中画，会把收起的位置当成原处。现在先要拉出来，刘海上说“先拉出侧拉的窗口，再放进画中画”。
- 显示器变了（拔掉、改排列）不处理，回到原处可能落在已经没有的屏幕上。现在所在的屏幕没了就退出画中画；
  放回时标题栏还露在某块屏上就原样放回，否则挪到最近的屏幕上，大小不变。
- 真窗口只看自己那块屏往边外让，旁边还有显示器时整扇出现在那块屏上。现在往没挨着显示器的那一边让；
  两边都挨着时不进，说“这扇窗放不进画中画”。
- 同一角有两块时，拖一块再松回原来的角，两块叠在一起。现在松回原角就回自己那一格。
- 移到另一块屏幕、键盘排布会去动画中画里的窗口：真窗口被拉回屏幕，画中画还开着，回到原处时大小也被改了。
  现在不动它，刘海上说“先让这扇窗回到原处”，后面接“再排”“再移到另一块屏幕”或“再移到上一块屏幕”；放回窗口时位置和大小都复原。

还没做的：开着两个画中画时的常驻 CPU 没量；视频、会议窗口实际看一遍要 Aaron 亲手试。
