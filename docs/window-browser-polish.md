# 窗口浏览：正确性、界面与材质改版（1.0.12 之后）

本文记录本轮窗口浏览改版实际实现并验证过的行为、样式、材质回退、操作方式与兼容
限制。性能数据见 [窗口浏览性能报告](window-browser-performance.md)，截图与视觉检查
见 [窗口浏览视觉验收](window-browser-visual-qa.md)，任务书 T01–T60 的逐条覆盖见
[自动化覆盖对照](window-browser-test-coverage.md)。

## 结果概览

- 截图调度改为显式记账：每个物理任务有不可复用的 JobID，只有 `drainQueue` 能把
  任务从 queued 变成 running；被取消但仍在运行的系统调用继续占用并发额度，直到
  真实完成回调按 JobID 结算。缓存失效不再让额度永久泄漏，也不会让同一任务被
  重复启动。
- 视图所有权修好：卡片/列表行只用 `weak delegate` 回传动作，右键闭包不再被控件
  自己持有。网格换成 `NSCollectionView` 复用单元，列表换成 view-based
  `NSTableView`，集合变化按 ID 差异更新，只刷新内容不销毁视图树。
- 实时预览只有一个明确挂载点（卡片或列表详情）。样式切换只迁移现有 NSView，
  不新开捕获流；旧任务的失败、超时、找不到来源都只清理自己的租约。
- Dock 检测拆开“应用身份”和“图标几何”：同一应用图标放大/移动只更新锚点与过渡
  区域；所有检测入口（AX 通知、鼠标回退、失效复检）共用一个排队器，最多一个
  在途加一个最新待处理位置。
- 布局结果统一：`WindowBrowserGeometry` 返回一份完整布局计划，面板、内容视图、
  方向键、可见项计算与截图目标尺寸都读它；单窗口面板不再继承 520×460 的强制
  下限，列表宽度不再等于整屏可用宽度。
- 新增真实系统玻璃路径（macOS 26+ 的公开 `NSGlassEffectView`）、旧系统
  `NSVisualEffectView` 与不透明纸面三条路径，并提供减少透明度、提高对比度、
  减少动态效果的回退。
- 新增可预览、可撤销的基本窗口排布：左半/右半/四角/居中/填满可用区域/移到另一
  显示器/撤销最近一次排布。

## 行为

### 入口

- Dock 悬停（默认关闭，保留用户选择）：鼠标停在已运行应用的 Dock 图标上，经过
  200–250 ms 意图延迟后面板出现；面板不激活 WindowShade、不抢键盘焦点、不改变
  源窗口层级。
- 菜单栏 **选择窗口…** 与可选快捷键：用户明确打开后获得键盘焦点，顶部是搜索框，
  Return 激活、Escape 关闭。
- 只在悬停、选择、键盘移动时不会对源窗口执行任何写操作；写操作只发生在明确的
  点击、Return 或菜单命令之后。

### 动作与状态

- 卡片、列表、右键菜单、菜单命令与 VoiceOver 自定义动作读取同一份
  `WindowBrowserActionPresentation`，能力判断只来自 `WindowBrowserActionPolicy`，
  所以不会出现“一处能点、另一处置灰”。
- 卡片底部是一条 28 pt 的信息行：左侧状态，右侧紧凑操作按钮（折叠/展开、置顶/取消
  置顶、末尾固定的“更多”入口，与右键菜单完全相同）。按钮命中区 28 × 28、间距 4，
  悬停或键盘选中时显示，状态文字为按钮让位，不会挤动标题。关闭窗口只放在菜单里（危险动作）。
- 悬停卡片出现一层很轻的系统填充色（按下更深一级，约 100 ms 淡变）；选中由强调色描边环
  表达，不只靠颜色。Dock 面板收不到键盘，**不画键盘选中环**：当前项由悬停决定，
  缩略图升档与实时预览挂载都跟着悬停项走。悬停追踪使用 `.activeAlways`，不依赖 key window。
- 键盘面板支持方向键、Home/End 与 **PageUp/PageDown**（按视口可见行数 − 1 翻页）；
  Tab / Shift-Tab 在搜索框、列表/网格与显示方式之间循环。
- 列表选中行与系统列表一致：面板是 key 时强调色实心圆角底 + 白字，否则非强调灰底；网格卡片
  用强调色描边环。操作按钮悬停/按下有 6 pt 圆角的系统填充底；动作执行中按钮前方出现转圈。
- 搜索无结果时列表区中央显示“没有匹配的窗口”。缺少屏幕录制权限时，页脚说明一次并给出
  “打开‘屏幕录制’设置…”入口（走现有的系统设置深链，悬停不弹授权框），卡片里只留应用图标。
- 状态文案不再使用 emoji 或杂字符：已折叠、置顶预览、预览已暂停、已最小化、
  应用已隐藏、屏幕外、正在展开各自使用系统符号 + 中性文字。已折叠且物理离屏是
  正常状态，不使用警告色；只有真实失败与权限缺失使用警告色。
- 卡片按下不立即激活：拖出取消，松开提交。悬停从不改变源窗口焦点。
- 文本编辑走系统派发：应用提供标准最小主菜单，搜索框里的 ⌘X/⌘C/⌘V/⌘A/⌘Z 正常工作，
  ⌘W 关闭面板（若正在显示排布预览则先取消预览）。
- Space 打开当前窗口的**只读大图预览**（macOS Quick Look 习惯）：只用已经拿到的画面
  （视图缓存 / 折叠快照 / 应用图标），不激活、不展开、不移动源窗口，也不会为预览去
  截图；窗口按图片比例放进当前屏幕可见区域的约 70%，没有画面时给出具体原因。
  取图顺序是「新鲜缓存 → 过期快照（标注） → 折叠快照 → 图标 + 原因」，
  Escape 先关大图、再取消排布预览、最后才关闭面板；点击大图任意位置也会关闭
  （与系统 Quick Look 一致），大图本身对 VoiceOver 是一个图像元素。
- 键盘习惯贴近系统：⌘F 把焦点交给搜索框；搜索框里按 Escape 先清空文本、再按一次
  才关闭面板；如果正在显示排布预览，Escape 先取消预览；键盘面板可以像系统浮动面板
  一样拖背景移动，Dock 面板保持锚定在图标下方。
- VoiceOver：焦点会随方向键/搜索移动，VO-Space 的“按下”与鼠标点击走同一条激活路径；
  卡片、行与菜单动作来自同一份能力模型；动作结果只在真实操作结束后播报
  一句（完成、失败原因、缺少的权限或“可能仍在执行”），悬停、列表刷新与缩略图到达
  都不逐条播报。
- 激活成功以“应用报告的焦点窗口确实等于目标窗口”为准；目标仍存在但无法确认焦点
  时返回“无法确认”，不把存在当成功。

### 排布与撤销

- 右键菜单 → **排布**：左半屏、右半屏、四角、居中、填满可用区域、移到另一显示器，
  以及 **预览**（只画目标轮廓，不移动窗口）和 **撤销上次排布**。
- 执行顺序：重新核对完整窗口身份 → 读取原 frame → 写入位置与尺寸 → 读回验证
  （容差 2 pt）→ 验证成功才登记撤销记录。验证失败按“无法确认”报告，不登记撤销。
- 已折叠窗口先走既有的展开与恢复验证，展开未确认就停止后续步骤。撤销前再次确认
  窗口仍在排布完成时的位置；用户已经手动移动时拒绝回放并说明原因。
- 填满可用区域使用工作区域（不含菜单栏/Dock），与系统全屏不同，不搬运 Space。

### 阴影分工（审计结论）

`WindowBrowserPanel` 把它自己的 `hasShadow` 交给 `PaperSurfaceStyle.installShadow(on:)`：
该入口会先关闭窗口原生阴影，再挂一个鼠标穿透、不能成为 key/main 的子窗口画纸面阴影。
因此面板只有一层阴影，阴影不改变窗口 frame（也就是不破坏“图标与面板对齐”的合约），
关闭面板时子窗口随父窗口一起消失，不会留下孤立影子。本轮没有为卡片再创建任何
NSWindow，静态卡片只画自己的边线与背景。

### 首次说明

第一次打开窗口浏览（Dock 或键盘入口）时给一次简短说明，说明 Dock 悬停与菜单/快捷键
两个入口，并明确“悬停与搜索都不会改动窗口”；之后不再反复打断。说明通过现有
`quietNotice` 与页脚提示呈现，不注入任何示例窗口行——示例数据的预览入口保留在隔离
展示（`--window-browser-fixture` 与 `--window-browser-shots`），避免把示例行混进用户
真实窗口列表。

## 视觉规则

- 分层：面板根视图是**唯一一层液态玻璃**（`NSGlassEffectView(.regular)`，不上色），页眉、
  搜索框、列表/网格、详情与页脚全部挂在它的 `contentView` 里（AppKit 头文件：只有
  contentView 保证位于玻璃之内）。卡片、列表行与详情栏不再叠 `NSVisualEffectView`，
  只用系统填充色（quinary / quaternary / tertiary）表达分组、悬停与按下；窗口画面不叠任何效果。
- 间距使用 4/8/12/16/24 序列，面板内边距 12、卡片间距 12；圆角：面板 13、卡片/行/详情 8
  （`SystemCornerRadius.item`，严格同心 13 − 12 = 1 不可用）、画面 4（8 − 卡片内边距 8，下限 4）。
  画面按比例缩放后，圆角与细线落在实际画面矩形上。
- 卡片：画面区 272 × 144 → 标题（1 或 2 行，占满卡片宽度）→ 状态行（这一批窗口里真有状态才留）；
  单行标题、无状态的卡片 288 × 186。操作按钮悬停/选中时浮在画面右上角（窗口底色 0.9 + 细边的
  圆角底托），不占卡片高度，也不挤动标题。
- Dock 面板与系统应用名气泡融为一体、不重复信息：底部 Dock 面板贴近图标（图标区域上方 4 pt），
  最下方留一条 38 pt 的标签带。指针停在图标上时，系统气泡（画在面板上层）正好落在带里，尖角指向
  图标，成为面板自己的标签；指针移进面板、系统收起气泡后，面板在同一位置用同样字号显示应用名
  接替它，两者从不同时出现。页眉不再写应用图标与名称：单窗口时没有页眉（312 × 236），多窗口时
  页眉只有“N 个窗口”与显示方式（高 32）。左/右 Dock 的气泡在图标侧面，面板仍让开 36 pt、不留标签带。
  可见区域不含 Dock 那条带，面板下沿因此允许伸进图标上方的空白（其余方向照常受可见区域约束）。
- 阴影：玻璃面板用系统窗口阴影（按窗口实际形状计算，贴合玻璃圆角）；纸面与旧系统面板用纸面阴影。
  自绘的纸面阴影放在玻璃下会在四角露出楔形暗影，已不再用于玻璃路径。
- 尺寸与内容的唯一来源：面板 frame 由布局计划给出，内容视图永远等于同一个 frame——换尺寸时也一样。
  动画换尺寸时不要把内容视图提前设成终点尺寸（窗口还在半路，系统会把偏小的内容视图摆到窗口中间，
  露出“面板宽而空、卡片被裁掉标题”的中间帧）；让窗口动画带着内容一起走，收尾再对齐。指针停在面板里、
  Dock 目标已被清除的那段时间里内容仍会变化，面板 frame 也必须按同一份记录继续跟随，不能冻结。
  底部 Dock 3 个窗口单行三列（912 × 274），4 个 2×2，5 个以上三列；左/右 Dock ≤ 2 列。
- 列表：`NSTableView.style = .plain`、行距 4、选中由行自己绘制（不再有系统灰块，行也不再
  因 inset 样式超出列表被裁掉）；无状态时标题垂直居中；详情栏画面在上、标题与状态在下。
- 排版跟随系统字号（正文 13 pt 起、标题中等字重、次级信息 11–12 pt），中文与
  拉丁字母混排基线一致；卡片标题最多两行，列表标题单行截断并保留 tooltip 与
  可访问性标签。
- 面板尺寸由内容决定，且只留必要留白：卡片标题按实际行数取高（短标题不占第二行），
  没有状态文字时状态行不占位（有状态才长出来，120 ms 过渡，减少动态效果下不动画）。
  单窗口面板 312 × 236 pt（有状态 312 × 253），底 Dock 多窗口面板另有 38 pt 标签带
  （见上文“面板与系统应用名气泡融为一体”）。
- 颜色统一由语义颜色驱动，动态 `NSColor → CGColor` 只在 `refreshAppearance()` /
  `viewDidChangeEffectiveAppearance()` 一处写入；浅深色、强调色、提高对比度变化
  时重算，不在 `init` 里永久缓存。

## 材质与回退

| 条件 | 实际使用 |
| --- | --- |
| macOS 26+ 且跟随系统、未开启减少透明度 | 面板根视图是公开 `NSGlassEffectView`（唯一一层，内容在其 contentView 内）；卡片用系统填充色 |
| macOS 14/15 或旧 SDK 构建 | `NSVisualEffectView(.popover, .behindWindow)`，`state = .active`（Dock 面板不会成为 key，不能跟随窗口激活状态） |
| 用户选择“纸面”或开启减少透明度 | 不透明纸面背景 + 语义边线 |
| 开启提高对比度 | 边线加粗、选中不只靠颜色 |
| 开启减少动态效果 | 面板不位移/缩放，动画时长压到 0 |

- 编译条件与运行条件分开：`build.sh` 探测本机 SDK 是否包含
  `NSGlassEffectView.h`，探测结果作为 `WINDOWSHADE_SDK_HAS_GLASS` 编译条件；
  旧 SDK 构建时玻璃分支不参与编译，运行时再判断 `#available(macOS 26.0, *)`。
- 不使用私有 CALayer filter、KVC、动态 selector 或整屏截图伪造玻璃。
- 面板永远只有一个玻璃形状，因此不使用 `NSGlassEffectContainerView`（它只为合并多个相邻
  玻璃形状存在）；原来的控制层表面与协调容器已删除。
- 设置 → 窗口浏览 → 外观提供“跟随系统 / 纸面”两个明确选择；不支持玻璃的环境
  不会出现一个实际不起作用的玻璃开关。
- 设置 → 窗口浏览 → **默认显示方式** 提供“自动 / 缩略图 / 列表”：自动按窗口数量
  判定（多则紧凑列表），面板内的显式切换只影响本次会话，不会被后台窗口数量变化
  覆盖。

## 兼容与限制

- 最低运行目标仍是 macOS 14；本机验证环境为 macOS 27.0（26A428）、Xcode 26.6、
  macOS SDK 26.5、Apple M5。
- 保留原有 WindowCatalog、完整 WindowKey、动作协调器、目标解析、恢复验证、异常
  救援与镜像租约；本轮没有另写隐藏/恢复系统，也没有改动折叠截图缓存的用途。
- 普通窗口实时预览仍默认关闭，最多新增一路；借用已有固定预览不再捕获第二路。
- 工作区分组、跨重启布局恢复、跨 Space 搬运、系统 Dock 替换、Command-Tab 接管
  都不在本轮范围。
- Dock 内部 AX 结构不是稳定公开协议：通知不可用时退化为仅在候选区域触发的节流
  命中检测；观察器失效只停用 Dock 入口，菜单与快捷键入口仍可用。

## 未验证项

- 实机窗口发现/身份解析/几何与能力读取已用 1.0.13 已安装构建的只读探针验证
  （15 个应用、17 个窗口、0 失败、最慢 42 ms、主线程最大停顿 6 ms）。
- 真实 Dock 悬停的目标产出（合成坐标不返回应用图标）、真实焦点、真实折叠/排布
  仍需要人工把指针停在图标上、手动操作窗口来验证，见视觉验收文档的手工步骤。
- 真实玻璃的折射观感需要屏幕录制权限截取整窗；本轮的组件截图只能证明控制层确实
  由 `NSGlassEffectView` 承载。
- 多显示器（上下排列、混合缩放）与 120 Hz 的实机行为缺少对应硬件样本，只保留
  纯几何测试与手工步骤。
