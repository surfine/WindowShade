# WindowShade：已有功能的体验完善顺序

> 后续历史核对已修正本报告的部分建议：近期执行以 [结合修改历史后的计划](near-term-plan-after-history-2026-09-13.md) 为准。此报告中更广的重构、交互改动与校准能力不属于当前实施范围；已有设计选择不能仅凭源码形态判为缺陷。

2026-09-13。用户约束：完善整个 App 的已有功能，减少使用负担，不复杂化，不牺牲性能。本文是基于当前源码的产品与工程判断，未修改运行功能，未进行新的性能基准测试。原貌专项详见 [原貌卷帘审视](native-shade-review-2026-09-13.md)。

## 核心判断

目前最值得投入的不是更多模式，而是让用户能准确预测每次操作的结果。WindowShade 会暂时改变用户桌面，因此“窗口回来时还是我放的位置”“点这个只会做这一件事”“没有动静时我知道原因”，比增加动画、按钮和自动化更重要。

完善顺序应是：行为正确 → 操作一致 → 反馈清楚 → 减少打断 → 视觉细节。性能贯穿每一步，不能最后补救。统一体验不要求先重写整个架构，先修入口和局部行为，再整理确实重复的底层工作。

## 一、先让已有承诺成立

### 原貌与恢复属于同一级核心质量

原貌裁切仍未修好，不能被一轮界面改版掩盖。建立失败图片和几何的回放，修正边界与轮廓；必要时提供一次可记忆校准，而不是反复让用户切模式。

同样重要的是恢复位置：普通拖动卷帘意味着用户改变了窗口位置；系统自动整理卷帘不应改变用户原来的窗口布局。现有 `restoreReferenceFrame` 已区分整理位置和恢复位置，这应成为跨原貌、标准样式、专注和置顶的共同规则，并以实机情景验证。源屏幕断开时才做必要的可见区修正，不要在正常恢复中“好心地”重新排版。

连续触发以最后一次明确意图为准，避免重复窗口和重复动作。项目已有状态机、代次与恢复验证，应沿用；仅对可逆的折叠／展开合并意图，关闭等动作不能按同样方式自动重试。

### 说明必须对应实际行为

当前 `DuoSettingsWindow.makeEffectsPage` 把“窗口卷帘”说明为随设备开合，但 `DuoController.receive` 的角度链路驱动桌面效果，`WindowFoldEffects` 则拦截窗口折叠／展开动作播放动画。

建议保留现有功能，改名并准确分组：

- “窗口折叠动画”：折叠和展开窗口时播放动画。
- “合盖时的桌面效果”：随铰链角度变化。
- 暂停项按实际范围命名：当前 `pausedByUser` 影响 `allowsAnimation`，不能只靠“自动”两个字解释暂停范围。

不为匹配旧文案去新增“合盖批量折叠窗口”。此外 README 的“它没有最小化”与实际隐藏回退冲突，应描述用户看见的行为，而不是保证底层从不使用最小化。

## 二、把操作含义固定下来

### 外观不应改变功能

目前菜单中的 `⌃⌘0` 随 `appearanceMode` 改为专注或整理。用户只改外观，却改变了快捷键行为，这是比颜色不一致更大的割裂。

建议让“整理卷帘”和“专注当前 App”成为稳定的两个命令，外观只决定如何显示。先把两个命令的适用条件与菜单入口固定；快捷键迁移不要静默改变已有用户习惯，也不必因此新建复杂的快捷键编辑器。

专注模式目前有“显示卷帘条原位”“恢复专注前状态”的分阶段循环。保留底层行为，但提供明确的“退出专注并恢复”，让用户无需猜下一次快捷键落在哪一阶段。既然现有代码已能恢复专注前状态，优先把这个能力变得易发现，不另造一套全局撤销系统。

### 窗口名称用于找到窗口，取消动作应写明

折叠菜单点窗口名称会展开，置顶菜单点窗口名称却调用 `cancelPinnedPreviewMenuItem`。建议窗口条目统一用于显示／定位对应窗口，取消置顶使用有明确名称的动作。可用小型子菜单保留管理操作，避免在窗口标题里塞满图标。

菜单打开后列表与编号应保持稳定；会话增删或标题刷新不要让正在选择的项目跳位。现有折叠列表按名称排序，先验证实际的重建时机，再决定是否采用会话固定顺序；不需要额外的收藏、标签和窗口搜索系统。

## 三、减少预览和置顶的打断

### 预览不应抢在操作意图前面

`TitleStripView.mouseDown` 先弹出预览，再判断后续是拖动还是双击。这会让拖动和展开夹带一次并不需要的预览。

建议保持已有主手势：单击预览、双击展开、拖动移动。预览优先使用已有快照；在确认拖动时取消，第二击时立即撤去。具体显示时机需用实机比较，避免为消除闪烁而给所有单击强加过长延迟。不要此时再默认加入一套自动悬停触发，增加误弹和捕获请求。

折叠菜单预览与卷帘单击预览共享布局、关闭规则和图像来源；它们可以出现在不同位置，但不应表现成两个不同产品。首次快照不可用时按需请求，失败给可理解状态，避免反复点击无反应。

### 置顶应先稳定，再追求无缝

已有置顶采用镜像与真实窗口交接，包含捕获启停、焦点切换和首击转发；这些能力有价值，暂不重做成另一套交互模式。优先验证第一次点击是否执行一次、快速移入移出是否反复启停、原生菜单和输入法是否正常。

当前交互退出条件主要是鼠标越过源窗口边界，延迟 120ms 后退出。该规则有打断窗外弹出菜单／子窗口的风险，尚未实测确认。应结合正在按下的鼠标、拖动、菜单／模态关系和当前交互代次判断，不能单凭越界立即夺回画面。

多个置顶窗口的避让只改变必要的遮挡关系，稳定时不反复改透明度或顺序。不能为了“聪明”让参考窗口追着鼠标变化。源窗口最小化或停止产出帧时保留最后有效画面并显示清楚状态；不把静止画面一律判作卡死。

## 四、反馈足够清楚，但保持安静

成功时，窗口自身变化通常就是反馈，不额外加 toast。失败时应在相关入口保留一句可理解的原因，直到下一次相关动作或用户关闭：找不到窗口、该窗口暂不支持、缺少哪项权限，以及能做什么。不要把技术日志直接当产品文案。

`quietNotice` 目前把错误文本塞进菜单栏标题，1.4 秒后恢复：短消息可能看不清，还会改变状态项宽度。建议菜单栏图标位置稳定，失败摘要放在打开后的菜单内；只有耗时明显超过正常操作时才显示进行中反馈，快速成功不闪加载状态。

菜单第一行始终展示铰链角度，但用户常用任务是折叠、置顶、恢复。角度读数更适合效果设置／诊断。菜单优先展示当前动作和必要异常；“暂停效果”“恢复窗口”等操作只在有关状态下出现，不增加常驻状态面板。

权限和硬件不可用时明确限制到受影响的功能：没有屏幕录制权限不意味着整个 App 不可用；缺少铰链传感器不应让手动窗口折叠看起来失效。系统设置返回后刷新授权状态，不在常规无关操作中反复检查。

## 五、设置页做收敛，不做扩张

沿用四个页面，统一窗口材质、标题、分组、控件尺寸和深浅色表现；以系统设置为实际对照，不再堆一层自制装饰。对照内容还包括非激活态、滚动、最小窗口及减少透明度，而非只验收一张浅色静态图。

把同一行的功能说明和动态状态分开：现有顶部状态串把传感器、角度、权限、暂停和实验信息拼在一起，阅读成本高，也可能随更新变化。日常页面只显示相关异常；详细读数留在校准／高级区域。

设置打开、切页、拖动预览时才做必要工作。当前传感器需求条件包括 `settingsWindow != nil`；关闭窗口会清理，但打开“卷帘”或“权限”页面也可能维持与该页无关的采样。可按可见页和实际预览需求细化，不能仅为显示一个数值持续启动硬件。

## 性能约束如何落实

“没有额外后台开销”需要测量，而不能只靠设计承诺。优先减少无效工作，不降低必要的恢复与安全校验。

| 场景 | 应保持的原则 | 当前可检查的入口 |
| --- | --- | --- |
| 没有折叠／置顶、效果关闭 | 不新增常驻计时器、捕获或扫描；保留必要的事件入口 | `Reconcile.updateReconcileTimer` 已按会话启停，应沿用 |
| 一组静态卷帘闲置 | 不为了标题更新或预览常驻视频流；有效状态变化才刷新菜单 | 截图缓存、菜单重建合并、恢复 observer |
| 1／多个置顶闲置 | 不无条件逐窗口增加轮询；稳定状态减少几何／Space 查询 | 已有共享 0.2s watchdog，先保留可靠性再测量优化 |
| 多置顶的鼠标避让 | 研究由交互活动驱动，必要时短期开启高频跟踪，配合低频兜底 | `updatePointerDuckingTimer` 当前在会话数大于 1 时建立 30Hz timer；不是声称每拍都修改窗口 |
| 静态设置页 | 不启动与可见内容无关的传感器和实时捕获 | `DuoController.settingsChanged`，设置可见页与实时预览需求 |
| 折叠／展开 | 以最后有效状态防止重复工作；不把深度 AX 扫描放进事件回调 | 已有状态机、事务预热、捕获去重和主线程边界 |
| 睡眠／锁屏／切 Space | 取消或暂停过期操作，醒来按需要恢复；不集中重放旧动作 | 现有 suspend／resume、epoch、Space 过渡门 |

建立固定场景的前后对照：空闲、10 条静态卷帘、1／3 个置顶、设置静态页、单次折叠和展开。记录 CPU、wakeups、内存、捕获会话数、动作到可见结果的 P50/P95，以及焦点／位置是否正确。以同机同窗口的多次基线分布判断回归，不编造统一的 CPU 百分比或延迟数字。只针对被改动的场景重测。

暂不因为用户界面调整拆大框架。只有捕获身份、状态代次或需求判断确实重复且导致问题时，才抽取小型共用组件。

## 推荐执行顺序

1. **正确性与信任**：原貌裁切、恢复位置、首击／重复触发、名称和说明对应真实行为。这是当前版本的交付门槛。
2. **入口和反馈**：外观不改变动作，置顶列表取消有明确名称，专注退出可直接找到，预览不干扰拖动，错误可见但不抖动菜单栏。
3. **按需工作与视觉收尾**：针对多置顶轮询、无关传感器工作做实测；完成设置及预览深浅色、焦点和缩放验收。

本阶段不增加新的卷帘材质、手势体系、自动归类、工作区管理、全局搜索、复杂快捷键编辑器或“任意按钮远程点击”。它们会增加学习和维护成本，对眼前的核心体验帮助有限。

验收应回答三个具体问题：用户是否需要多试一次；是否出现意外的位置、焦点或状态变化；不用它时是否仍在做本可避免的工作。解决这些，已有功能就会明显更成熟。
