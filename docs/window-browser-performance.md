# 窗口浏览性能：本轮实测、设计预算与未达项

本文只记录实际执行的测量。区分“本次实测”“设计预算”“仍未验证”，不把设计目标
写成已达到的宣传数据。

## 环境

| 项目 | 值 |
| --- | --- |
| 机型 | MacBook Air（Mac17,4，Apple M5，10 核，24 GB 内存） |
| 系统 | macOS 27.0（Build 26A428） |
| 工具链 | Xcode 26.6（17F113） |
| SDK | macOS SDK 26.5（含公开 AppKit 玻璃 API） |
| 构建 | `swiftc -O -target arm64-apple-macosx14.0`，同一进程内渲染离屏组件 |
| 数据 | 确定性内置记录；不打开、不操作任何真实窗口 |

测量口径：同一进程内对同一操作重复取样，先预热（≥10% 次），再报告 p50/p95。
这是**扣除输入与人为意图延迟后的处理时间**，不是端到端悬停延迟。

## 本次实测：改版前后对照

原始输出：[`.build/window-browser-perf/2026-09-18-release-before-after.txt`](../.build/window-browser-perf/2026-09-18-release-before-after.txt)
（交付前的背靠背复测）、[`.build/window-browser-perf/2026-09-18-before-after.txt`](../.build/window-browser-perf/2026-09-18-before-after.txt)
（同一天较早的一次，统一外观策略落地之前）。基线都是新 Worktree 中的 `05e5472`，
同一台机器、同一脚本、同一组数据。

### 冷启动：新建内容视图 + 第一次数据填充与布局（交付前背靠背复测）

| 窗口数 | 基线 p50 / p95 | 本轮 p50 / p95 | 变化 |
| --- | --- | --- | --- |
| 1 | 4.2 / 5.2 ms | 7.2 / 8.8 ms | +72%（复用容器与玻璃/材质层的建立成本） |
| 3 | 7.6 / 8.2 ms | 11.7 / 12.5 ms | +53% |
| 8 | 16.1 / 16.8 ms | 19.3 / 20.8 ms | +20% |
| 120 | 271.8 / 342.8 ms | 24.2 / 30.4 ms | **−91%**（不再为每条记录立即创建整棵视图树） |

### 暖刷新：同一批数据再次 update + layout

| 窗口数 | 基线 p50 / p95 | 本轮 p50 / p95 | 说明 |
| --- | --- | --- | --- |
| 1 | 0.009 / 0.012 ms | 1.29 / 1.46 ms | 基线在内容签名未变时几乎不做工作；本轮仍重算布局计划 |
| 3 | 0.015 / 0.020 ms | 2.61 / 2.82 ms | 同上，本轮的刷新路径包含动作/状态重算与集合视图布局 |
| 8 | 0.026 / 0.032 ms | 0.97 / 1.09 ms | 列表模式 |
| 120 | 0.308 / 0.340 ms | 1.28 / 1.42 ms | 列表模式，视图复用以外的成本稳定 |

结论：本轮的刷新路径成本比基线高，但**全部落在 4 ms p95 的主线程预算内**；换来的是
120 条记录冷启动从 272 ms 降到 24 ms，以及“滚动/开关不随访问次数线性增长”。

关于两次测量的差异：复测期间机器本身有后台负载（WindowServer、浏览器、音乐），
所以**基线自己**也从早先的 200 / 249 ms 变成 272 / 343 ms，同一条 120 窗口冷启动
从 17.8 / 19.7 ms 变成 24.2 / 30.4 ms。这段差异是“机器更忙”加“统一外观策略落地后
每个视图都要解析一次动态颜色”，相对变化（约 −91%）在两次测量里一致。报告发布数字
时一律用同一次会话内的背靠背对照，不用跨会话的最好成绩。

### 设计稿落地后的同会话对照（2026-09-19）

`docs/design-proposal-claude.md` 落地后，与改动前的 `a1a0a01` 在同一会话里交替运行 6 轮、
取每项 p50/p95 的中位数（机器负载波动大，单轮数字不可比）。原始输出：
`.build/window-browser-perf/2026-09-19-head-vs-design-proposal.txt`。

| 场景 | 窗口数 | a1a0a01 p50 / p95 | 落地后 p50 / p95 |
| --- | --- | --- | --- |
| 冷启动 | 1 | 11.50 / 20.47 ms | 11.50 / 14.05 ms |
| 冷启动 | 3 | 17.69 / 22.65 ms | 16.76 / 20.87 ms |
| 冷启动 | 8 | 26.06 / 35.57 ms | 26.52 / 32.90 ms |
| 冷启动 | 120 | 27.86 / 32.03 ms | 28.52 / 34.46 ms |
| 暖刷新 | 1 | 1.09 / 1.29 ms | 1.08 / 1.29 ms |
| 暖刷新 | 3 | 2.27 / 3.05 ms | 2.40 / 2.94 ms |
| 暖刷新 | 8 | 0.92 / 1.19 ms | 0.70 / 0.79 ms |
| 暖刷新 | 120 | 1.33 / 1.58 ms | 1.10 / 1.32 ms |

结论：两者在噪声范围内持平，暖刷新 p95 全部在 4 ms 预算内。第一版实现曾把暖刷新 p95 推到
4.7–6.6 ms，查明原因后改掉：离屏视图的细线宽度每次查询 `NSScreen.main`、卡片布局时逐次
取字体算行高、页眉每次布局调用 `fittingSize`、同一张缩略图重复投递时也触发重排、静止的
操作按钮也做颜色解析。与基线 `05e5472` 的对照仍以上文的发布前表格为准（本轮未重测基线）。

### 面板出现延迟：建窗挪进意图延迟（2026-09-23）

真实日志（197 次 Dock 悬停，`/tmp/windowshade.log` 的 `perf:` 行）：意图延迟结束到面板出现
p50 49 ms / p90 77 ms / 最长 158 ms；面板出现到第一张新截图 p50 77 ms / p90 164 ms。

离屏基准（同机，Command Line Tools / Swift 6.4，`-O`，丢弃前 3 次）：新建一个 Dock 面板
（窗口 + 玻璃层 + 内容视图 + 首次布局）p50 23.6–28.5 ms、p90 约 31 ms。每次 Dock 停留都在
意图延迟结束那一刻付这笔钱，约占上面 49 ms 的一半。

改法：第一次悬停后的下一轮 runloop 就建好面板，放在 `prewarmedDockPanel`，不赋给 `panel`，
所以延迟期间不刷新内容、不截图；延迟结束时接过来刷新并显示，关闭时一并释放。预期延迟结束
到出现降到约 20–25 ms。**还没有改动后的真机数字**，下次看日志时用上面同一口径复算。

## 仍未验证

- **端到端悬停延迟**：需要真实 Dock 悬停、辅助功能授权与真实截图，本机未在带授权
  的新构建上运行，因此没有 p95 端到端数字。
- **单元视图的实际创建数量**：离屏回归里 AppKit 不会为不可见条目创建复用单元，
  因此自动化只能断言“视图侧图像字节有界”；“只创建可见单元”的证据来自冷启动
  对照（120 条 24 ms vs 272 ms，同一次会话内背靠背）与实机滚动步骤，缺少逐单元
  计数的实机采样。
- **WindowServer / 能耗**：本轮没有做 WindowServer CPU、能耗与 60/120 Hz 掉帧的
  实机采样。
- **真实进程 footprint**：只测了视图侧图像引用字节与服务缓存字节，没有用
  `phys_footprint` 采样长时间会话。
- **多显示器与混合缩放**：只有纯几何测试覆盖，缺少第二块显示器的实机样本。

## 运行时会话的计数（§17.1）

关闭面板或退出功能时，`/tmp/windowshade.log`（5 MB 自动轮转）会写一条
`perf-summary:` 记录，包含：物理截图启动/投递数、queued 取消数与占比、过期结果数
与占比、重复完成、停滞降级批次、仍在运行与排队的截图数、缓存条目与字节数、
逻辑 AX 发现请求数与真实 AX 调用数、Dock 检测次数、被丢弃的过期检测结果数、
当前检测排队长度。阶段耗时另有 `perf: input-arrival / intent-delay-end /
first-panel-show / first-catalog-publish / first-new-screenshot / live-first-frame /
action-submit-* / action-verified-* / panel-resources-released`。

单帧更新耗时不在运行时逐帧记录（避免日志本身影响帧率），由本文的离屏
`content.update+layout` 测量代表。

```sh

bash tests/run-window-browser-tests.sh

# 前后对照（需要先取出基线 worktree）
git worktree add /tmp/ws-baseline 05e5472370e199e92b147f1e0af72175c6429288
/tmp/run-perf-release.sh   # 含 SystemAppearance.swift 的完整源文件清单；
                           # 新实现与基线在同一会话内先后编译运行，避免跨会话比较

cd prototype && ./build.sh --stage
cd .. && .build/duo-validation/WindowShade.app/Contents/MacOS/WindowShade \
  --window-browser-shots .build/window-browser-shots
```
