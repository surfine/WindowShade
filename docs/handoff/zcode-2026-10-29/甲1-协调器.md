## 做了什么

队列并进协调器第 4 层 + 面板本地输入报给协调器：

1. **Core/InteractionCoordinator.swift**
   - `AlertItem` 加 `priority`（大的先说）、`holdMilliseconds`（这一条自己的停留，0 用 alert.hold）、`expiresAt`（原队列的 ttl）。
   - 新增 `admit(_:on:at:) -> ReminderOutcome { showing, merged, queued, dotOnly, dropped }`：露面位子空着就说、正在说且在 0.6 秒合并窗口里就并进那一次露面、过了窗口就按优先级排队（`pendingAlerts`，同 key 只留最新，8 条上限）、撞上第 1–3 层变成点并消耗。露面结束（`expire`）由 `promoteReminders` 把队首顶上来，过期的跳过。
   - `issue()`（租约开始）时把排着没说的提醒整队消耗（点已由露面记下）；`barrier`/`removeDisplay` 清队。
   - 新增 `hostInteraction(on:at:deadline:)` / `endHostInteraction(on:)`：面板本地输入（音量亮度两耳、拖放落点）不占租约，但提醒要让（`remind`/`admit` 撞上就只留点）。期限是宿主忘报收尾时的兜底。
   - `hasReminderWork(on:at:)` 给插电那一下当「撞上就不出」的账。
2. **App/NotchLeases.swift**：hub 暴露 `admitAnnouncement` / `currentAlertItem` / `hasReminderWork` / `noteHostInteraction` / `endHostInteraction` / `clearReminders` / `now`。
3. **App/Notch.swift**：`announceWhenFree` 改为协调器的薄客户端（展示属性按 key 存宿主，先后、过期、准入全归协调器）；本地 `pendingAnnouncements` 数组、按优先级的本地排序、`drainPendingAnnouncements` 删除；0.4 秒兜底钟保留（问协调器轮到谁了）；`holdAnnouncements` 走 `clearReminders`；`showPowerFlash`/`isBusyForPowerFlash` 的账换成协调器的（还排着、还露着的提醒都算忙）；面板 `alert()` 加 `admitted:` 参数（队列路径不重复记账）；面板 `presentLevel`/`setDropState`/`setStripLanding`/`confirmDrop`/`endFileDrop`/`setInteraction` 报告宿主输入开始/结束。
4. **App/WS2AppRuntime.swift**：编程会话 bloom 优先级 0 → 4（排在离开摘要 5、日程 8 之后，不再跟电量这类默认 0 的排一队）。

## 行为变化（点名要改的）

- **提醒撞上第 1–3 层（展开、认证、拖放、两耳）从「排队等空再说」改为「变成次区域的点并消耗，不补说」**。这是派单点名的规则（design-grammar 层序），直发 `announce` 路径本来就如此；排队路径现在对齐。列入真机看护。
- 编程会话 bloom 不再垫底（0 → 4）。
