## 候选方向

### A. 收敛 1.0.16 范围

**候选判断**：1.0.16 ＝ 已过签名探针的窗口线 + 已定随版四件（实时活动、配件电量、Touch ID、锁屏开合／面部动作）。其余（电量全家、CarPlay、指挥模式、刷脸解锁／系统解锁、隐私全核）移出为独立的 WindowShade 2 轨，每条有自己的门槛。

- **依据**：170 个提交、0 次发布；七条线里只有窗口线接近收尾，CarPlay 连本体都没写；「已定随版四件」只到「已进 App」。
- **立刻动作**：把 `docs/releases/v1.0.16.md` 草稿的功能集按「保留／移出」逐条标注；移出的另建一页记门槛。
- **验收信号**：1.0.16 的范围表定稿，且每条保留项都有「源码／单测／真机探针／人工」四类状态。
- **风险与退路**：砍太狠会让 1.0.16 显得单薄；若如此，把「移出」项公开写成「下一版」，不让用户以为已经做了。

> 待 GPT-6 回填：**采纳并发扬**（裁定 1、2）。GPT-6 判定 1.0.16 必须收敛，并给出比我方更长的延期清单：CarPlay、指挥模式、全设备电量、系统／刷脸解锁、多设备确认、防盗，**外加图标重做与设计系统余项**（候选 A 原先只列到「系统解锁」，图标与设计余项是 GPT-6 追加的）。**分歧**：候选 A 把「面部动作」列入保留的随版四件，GPT-6 判 2 明确把面部动作移出本版（缺阈值校准、活体与防重放证据），Touch ID 也只承诺应用内授权、不承诺系统解锁。**追加约束**：已启用来源的隐私登记、依赖许可核验不能随功能范围一起砍掉。

### B. 一次真机会话（runbook）

**候选判断**：把「人工未验」清单排成一份 60–90 分钟的 runbook：先跑不需要人手的探针（趁电脑空闲），再一次性坐完需要 Aaron 在手的那些（Touch ID、配对、相机、真拔插、手感）。

- **依据**：探针在有人用电脑时必须自停；人工未验清单十余项且都在等 Aaron。
- **立刻动作**：写 `docs/handoff/gpt6-review-2026-10-06/runbook-manual-session.md`（本包不含，待定稿后另开），按「不需人在场／需要人在场」分两段，逐项写操作步骤与通过判据。
- **验收信号**：一次会话后，「人工未验」清单里每一项都有「通过／失败／blocked」结论，不再是空白。
- **风险与退路**：会话中途探针互相干扰（如 gesture 在有人用时超时）→ 先做互不干扰的顺序，失败项当场记 blocked 不重试。

> 待 GPT-6 回填：**采纳并收紧**（裁定 4）。GPT-6 把会话**封顶 90 分钟**，要求人工段与无人探针**不混跑**、现场不改代码，每项都要拿到「通过／失败／阻塞」及证据。**分歧／追加**：候选 B 把「相机」列入 Aaron 现场项，GPT-6 判相机校准随面部功能一起延期；第三方（Marvin／Newlearner）只在**确认意愿与设备后**接鼠标、多指、Swish、会议／慢 App 等通用测试，**不能预设有人接单**；选配项阻塞就延期，核心阻塞修好后只补相关验收，不重开整张清单。

### C. 发布门槛（选定路线 + 走通一次真更新）

**候选判断**：先选定发布路线（等 Developer ID／公证，或走开发证书 + 首次安装麻烦一次），在隔离 store 里走一次真实的应用内 Sparkle 更新，并备份更新私钥。

- **立刻动作**：Aaron 决定路线；决定后补线上的 appcast，并在隔离环境跑一次下载 → 安装 → 坏包回退。
- **验收信号**：一次真实更新成功，且坏包回退也走过；私钥离线备份确认存在。
- **风险与退路**：公证流程可能卡壳；退路是先用开发证书发一版，把「首次安装麻烦」写进说明。

> 待 GPT-6 回填：**路线已定，候选的「二选一」被裁定**（裁定 5、6）。GPT-6 判正式发布走 **Developer ID + 公证**，开发签名只作**封测退路**（不是并列选项）；并且把「真实更新、坏包拒收、安装后恢复」**拆成三件分开验**（候选 C 原本混为一件事）。**追加**：缺异机安装证据，不能承诺「首次只麻烦一次」，第三方要从下载页实测首次安装；未获准就停在自愿封测，不要求用户关闭系统整体防护。**再由 GPT-6 抓到的一处矛盾**：候选 C 与 GAP-REVIEW／BRIEF 一度写「更新私钥未备份」，但 `DEVELOPMENT.md` 记「已有一份离线备份」——真正的缺口是**恢复能力从没验过**，不是备份不存在；已按此更正三处文档。

### D. 风险回滚（稳版）

**候选判断**：针对 W00 的主线程隔离执行期风险，先出一版「稳」的给 Aaron 日用并观察崩溃；用既有的坏包换回通道兜底。

### E. 「已发布」的一条定义

**候选判断**：把「已发布」定义成四件事同时成立——tag + GitHub Release + 官网部署 + 你日用 App 换版；停止把「本地已做」算进进度。

- **依据**：ledger 里「做成，不是本地已做」；网站/README 仍是 1.0.15；0 tag。

- **验收信号**：这一页成为唯一真相，其他文档的状态格向它对齐；「改了被探针覆盖的代码 → 旧绿自动标要重跑」有机制。
- **风险与退路**：多文档同步成本高；退路是只保留这一页对外、其余标注「细节」。

> 待 GPT-6 回填：**改判**（裁定 8、9）。GPT-6 要求**复用现有 `v1.0.16` ledger 作唯一事实来源**，**反对再建一套进度系统**（与候选 E「在 `docs/` 建一份新的单一事实来源」直接冲突）。ledger 每条记四类状态、源码 SHA、包哈希、环境、证据与发布 tag；扩展既有检查把文件映射到探针，被改动的已覆盖文件自动标「待重跑」，全局构建变更全量失效。节奏定为**每周一 10:00 定范围、周五 17:00 放行裁决（东京时间）**，状态变化即时登记。另：**发布负责人＝主模型**，发布闭环（tag + Release + appcast + 官网／README 同步）完成才算结项；88／89 分与异口径内存比较不单独挡版。
