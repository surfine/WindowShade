## 背景与时间线

WindowShade 是一个 macOS 应用（单人项目，产品经理 Aaron 同时是唯一开发者与主要验收人）。产品主张：**把「看不见的窗口」都放进 Mac 的刘海里**——收起的、侧拉的、最小化的、隐藏的、别的桌面上的；指针停在某一格就能在它自己的位置看一眼，点一下才过去。目标人群包括刚从 Windows 或 iPad 换到 Mac 的人。

- **2026-09-26**：发出 `v1.0.15`（tag `v1.0.15`）。
- **2026-09-26 → 2026-10-06**：分支上 170 个提交，`main` 上 141 个提交；**没有新 tag、没有 GitHub Release**（`git tag` 最新仍是 `v1.0.15`）。
- 这期间并入的第十份收尾包把建构参数改成 Swift 6 完整并发 + 警告视为错误，W00 合并进 `main`（提交 `cc6c938`），`prototype/build.sh --check` 现在退出 0。
- 日常使用的 `/Applications/WindowShade.app` 仍是 2026-10-03 04:31 的 build 16。
- 网站与 README 仍是 1.0.15 的说法。

## 理想是什么

1. **方向**：刘海是 Mac 的新入口。
2. **总图**：七条产品线一起走到能发布——① 窗口折叠／窗口浏览、② 实时活动（灵动岛）、③ 设备电量、④ CarPlay 接收、⑤ 指挥模式、⑥ 身份认证与解锁、⑦ 隐私登记。分 0–7 阶段推进。
3. **1.0.16 草稿承诺**：看不见的窗口都在刘海里；侧拉／分屏／画中画／启动台；排窗；按窗口切换；更省电；实时活动、配件电量提醒、Touch ID、锁屏开合效果、面部动作随这一版发。
4. **验收尺子**：每个领域都到 90 分以上，特别是超过竞品 Wins。自评表显示多数格子已在 90–95，三个例外：刘海 88（对竞品 Alcove 重打）、盒盖动画 88（手感等真人确认）、性能 89（物理占用约 100 MB，对手 Wins 自称 30 MB）。
5. **一句话目标**：**做成，不是「本地已做」——发布才算数。**

## 差距的本质（我方判断）

1. **瓶颈不是工程产能，是「一个人的验收漏斗」**：探针在有人用电脑时必须自停；Touch ID、配对、相机、真插拔都等 Aaron 在场。工程一次能产出十条线的代码，验收一次只能过一件。
2. **范围比收敛快**：每开一条新线都是往同一个漏斗里加东西，从没有一次是从漏斗里拿走东西（砍需求、把线移出去）。
3. **「本地已做」被当成了进度**：源码落地后没有紧跟「验过」或「发出」。
4. **发布不是一次动作，是一条没人负责的线**：从 9/26 至今没有跑通过一次完整的「打标签 → 发 Release → 部署官网 → 换日常 App」。

## 约束（不能违反的边界）

- **一步一主模型**：一个阶段由一个主模型主导；执行模型按写明的工单做，不自行发明前九份的基础设施。
- **私有 API 大胆用，但要登记**：读到什么就登记什么；未知就是未知，不猜、不用占位实现冒充身份、防伪、系统解锁、防盗能力。
- **每次改动留证据**：源码／单测／真机探针／人工 四类状态分开写；没有真机证据不能用「已支持」「安全可靠」代替。
- **许可干净**：依赖许可要核过；更新私钥永不进仓库、不导出。
- **能耗预算**：常驻 CPU 与内存有预算；效果关着约 0.3%，开着约 0.45%。
- **不发布除非 Aaron 点头**；不替换日常 App；不把编译通过当成能在真机跑。
- 参考：`AGENTS.md`、`docs/blueprint.md` 的 12 条硬要求。
