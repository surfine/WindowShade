## 2. 任务二：动效重制（HIG × Chan Karunamuni × 现有令牌）

先把现有底子读一遍：`docs/design-system.md` §4.6（弹簧令牌：response/阻尼，100% 阻尼为默认、
回弹上限 0.2）、§4 第 4 条（跟手、随时可打断）、§4.9（减少动态效果路径）。Chan 的主张与这些
不冲突，且补了三件系统令牌没写死的事：

1. **打断即改道，速度不归零。** 每个新增动效（会话活动切换、审批卡进出、看一眼浮层、认你指示
   收放、录脸卡出溜）都要过「中途换目标」测试：动画进行到 40% 时换目标，位置与速度必须连续，
   不许跳变、不许先停在终点再走。现有 `Notch.swift` 的卷帘/卡壳路径已这么做，新表面照抄
   `FoldSpring`/`spring.advance(to:dt:)` 的接法，不要用 `NSAnimationContext` 时长动画。
2. **进出对称。** Chan 常批评「进场精致、退出潦草」。清单化处理：每个新表面的 dismiss 与
   preempt（被更高层挂起）都要有明确的收尾曲线，且 preempt 时**不重播**（挂起≠取消）。
   现有租约系统（NotchLeases 的 suspended/preempted）已经区分了语义，动效要跟上。
3. **动效=空间记忆。** 看一眼浮层必须从会话卡的方向长出来、收回去也回那个方向（anchor 已传）；
   审批卡从右耳琥珀点放大；「过去」跳终端时刘海收合的方向要指向那扇窗的方向。
   不做无方向的淡入淡出。
4. **每个动效填进令牌表**：response/阻尼/是否带初速度/是否可打断，逐条写进 design-system
   §4.6 的新小节（§4.6.1「WS2 表面」）。超出令牌的（例如回弹>0.2）走 §6 改值账，单列单验。
5. **减少动态效果**：每个新动效给出 reduced 姿态（停关键帧/直接位移），列入 §4.9 清单。

验收方式沿用项目惯例：动效样片（交互 HTML）＋真机探针的帧间隔记录（`perf-ledger` 口径），
不以「看起来流畅」收工。

## 4. 建议的动手顺序

1. 读 §0 的五份文档＋design-system §4/§5/§6（半天）。
2. 任务一第 1 项（会话四态稿）——它同时决定任务二一半的动效对象。
3. 任务二先做「打断即改道」的公共件（若 `FoldSpring` 不够用，提最小扩展，不另起动画系统）。
4. 审批卡稿 → 认你指示稿 → 指挥页稿 → 露出方案稿。
5. 全部稿登记进 design-drafts/README，动效令牌回写 design-system，差异进 design-grammar 对账。

有拿不准的：设计事实以旧稿+design-system 为准；规格事实以 conductor-v2 / agents-in-notch 为准；
两者冲突时记 design-grammar 对账并在交接文档里标出，不要私下改规格。
