## 请你交付的结构（严格按此输出）

### 1. 落地优先级表（两周可见 + 60 天）

对每个条目给：

- **名称**（沿用 A2/A3/A4/A5 或 B1…；可新增编号但说明映射）  
- **用户一句话**（不说实现）  
- **依赖**（租约 / 私有 API / 权限 / 真机）  
- **最小切片**（一周内能演示的最小竖切）  
- **完成定义**（可勾选；含「真机 / 外接屏 / Reduce Motion」至少各一条）  
- **刻意不做**（防 scope creep）  
- **与 Alcove 的对照**：追上 / 并列 / 用独门绕开  

至少覆盖：音量亮度同岛、媒体最小岛、持续活动横滑、动效能耗习惯、窗口三住处闭环、放行独占演示。日历是否进主线要单独给砍或缓的理由。

### 2. 「不必再装 Alcove」验收剧本

写一条 **6–8 镜** 真机脚本（同一颗岛一天）：悬停 → 音量 → 提醒 → 放行或启动台 → 收窗进岛 → 看一眼放回。每镜写：操作、期望画面、失败判据。不要锁屏 widget 镜。

### 3. 工程与发布纪律

给 Cursor / 执行模型可执行的节奏建议：刘海专项看板、stutter/energy 门槛、什么进周更什么进大工单。不要发明第五套协调器或第二宿主。

### 4. 风险与决策题（最多 5 个）

只列需要 Aaron 点头的题（例如：日历是否进持续活动主线；媒体是否接第三方播放器；pill 是否允许「强制假刘海」开关）。每题给推荐选项 + 一句代价。

### 5. 反建议清单

明确写出：**不要**做的三到五件事（抄 Alcove 皮肤、假刘海、改 slogan、为波形开设置页等），各配一句「为什么会输」。

## 硬约束（违反则建议作废）

- 唯一刘海宿主 + 六层仲裁；不另开浮窗当岛。  
- 文法：不学锁屏小组件、假刘海、私有绘制与代码；界面不叫灵动岛。  
- 不改 `MotionSpring` 令牌数字，除非单独论证并标「要 Aaron 点头」。  
- 文案跟 copy-guide；内部词（岛、肩、硬件层）不上界面。  
- 不签名、不发布、不替换 `/Applications`（除非 Aaron 另说）。  
- 私有 API：可用但要进隐私登记与失效退路叙事。  
- AirBattery 等 AGPL 只作研究，不拷代码。
