WindowShade 2 · 设计稿 · 2026-10-08 · 遥控模式与指挥模式合成一件事

一个遥控器，碰一下刘海

不要两个模式，只要一个地方。看不见的东西都在刘海那一排：收起的窗口、正在播放的、在跑的 Codex 和 Claude。遥控器碰到什么，就操作什么。碰到窗口，点一下放回；碰到正在播放的，按播放键暂停；碰到一个会话，点一下走进去，触控区就变成画档位的地方，侧边按钮变成说话。返回永远退一层。遥控模式是在那一排里走动，指挥模式是走进一个会话：同一次配对、同一条连接、同一套键。

触控区：往下滑、左右滑、点一下、往上滑；走进会话后，从左往右画一横、↗、ˇ、↘ 选档位。也可以点一下左边的 Mac 画面，用方向键、回车、Esc。

为什么不要两个模式

手机上没有我们的画面。控制中心的遥控器是 Apple 的界面，看不出现在是“遥控”还是“指挥”。如果同一个键在两个模式里意思不同，又要靠“按住播放键 1 秒”来换，用户每按一下都得先想自己在哪个模式：这就是模式错误，而且是看不见的那种。

所以把“模式”换成“位置”。tvOS 一直这样做：遥控器只有几个键，焦点停在什么上，键就作用在什么上；进一个 App 是往里走一层，Menu 是退一层。WindowShade 的设计文法第一句本来就是“看不见的东西都在刘海里，碰一下就回来”。遥控器只是又一只碰刘海的手。

两个名字都留着，但不再是两个开关之间的切换。遥控模式 = 在刘海那一排里走动；指挥模式 = 走进一个编程会话。会话本来就在刘海里（《看与指挥》），指挥模式“选会话”的列表就是那一排里的会话格。

四层，返回永远退一层

越往里走，能做的事越重，要的确认越多。刘海左耳一直告诉你在哪一层：遥控器符号是前两层，指挥棒是后两层。

0 · 连着

左耳一个遥控器符号

持续活动，退成最小。屋里的人都看得见这台 Mac 正被遥控。

能做：往下滑或点一下展开那一排；播放键控制正在播放的；音量。不能做别的。

1 · 刘海那一排

遥控模式

左段是收进刘海的窗口，竖线右边是正在进行的：正在播放的、编程会话。和指针停在刘海上打开的是同一页。

能做：挪焦点；点一下打开亮起的那一项（窗口放回、播放的去那扇窗、会话走进去）。都看得见、能撤回。不放行、不打字。

2 · 会话里

指挥模式

刘海写着项目 · 助手 · 档位。触控区变成画档位的地方，侧边按钮变成说话。不动光标，不碰前台窗口。

能做：画档位（只管下一轮）、说一句出草稿、播放键发出去 / 补一句 / 停下、刘海里问的那一次普通放行。高风险的到 Mac 前用 Touch ID。

3 · 会话里的选择

选模型、确认候选

往下滑展开四个模型位置；五拍的 max 等你点一下。

和第 1 层一样挪焦点、点一下选中、返回关掉。没有新的手势要学。

一个键一个意思

每个键先有一句不随层变的意思，再看它在每一层落到什么。表里每一格都是这句话的具体化，没有一格例外。2026-10-08 从 atv-core 读到了键码（返回 5、确认 6、电视键 7、播放 / 暂停 14、静音 18、电源 19；iOS 26/27 的控制中心遥控器把 18、19 复用成静音和电源），松开那一下才算；触控区是 1000×1000，移动小于 60 算点、至少 150 算滑。所以“待识别”改成“已知键码，待真机核对”。

竖着滑在指挥手势里本来就判为“没认出”，所以往上滑、往下滑在会话里不会和画档位撞车。

互通有无

指挥从遥控那里拿到的

  • 配对、连接、断开、锁屏、撤销：一套，遥控的第一段先验完
  • 选会话：不再要“按住电视键”和第二套列表，就是那一排里的会话格，挪焦点也是同一套
  • 选模型：变成第 3 层的一排，和挪窗口焦点同一个手感
  • “结果出来之前不说话”“从沙发上看得清”：同样的规矩，同样的刘海

遥控从指挥那里拿到的

  • 会话格本身：在跑、等你、完成，把编程会话放进沙发上的那一排
  • “开始或停下眼前这件事”：播放键在媒体上是播放暂停，在会话里是发出去和停下，同一句话
  • 提示音：静音键管的是 WindowShade 的提示音，两边共用
  • 放行的边界：遥控层永远不放行；只有走进会话、刘海问了那一次，才点得了

原来的矛盾怎么收

四份文件各写过一种键位。这一张收成一种；2026-10-08 Aaron 点头，conductor-v2、input-devices、《手边的每一样》《指挥模式》已照这一张改。

矛盾原来这一张理由
怎么换模式《手边的每一样》：按住播放键 1 秒换；《指挥模式》：设置里打开才宣告不换。走进会话就是指挥，返回就出来手机上看不出模式；也不用等 E2 证明播放键有按下和松开
开关两个平行开关 / 一个开关加手势遥控模式是总开关；指挥模式是它下面的一项，打开后那一排才出现会话一次配对、一条连接；指挥多出的只是一种能走进去的东西，以及助手会真的执行这件事的同意
电视键遥控：启动台 / 按住开那一排；指挥：换档位和模型 / 按住选会话回到刘海那一排和 Apple TV 上“回主屏幕”同一个直觉；选会话、选模型都改成挪焦点
“档位 / 模型”两个域点电视键换域，拍子在模型域里选位置 1–4没有域：手势只管档位，模型在第 3 层的一排里选“现在在哪个域”又是一个看不见的模式
播放键遥控：媒体播放暂停；指挥：发出去 / 停下一句话：开始或停下眼前这件事原来两个意思其实是同一个
侧边按钮遥控：听写到当前输入框；指挥：说话出草稿只对会话说话遥控不往前台窗口打字
电源遥控：让显示器睡眠；指挥：退出指挥模式收工：全部收回第 0 层，会话照跑一个键一个意思；睡眠显示器有系统自己的办法
放行遥控稿：遥控不点审批；指挥：点一下允许第 1 层不放行；第 2 层只放行刘海问的那一次普通请求风险随层加深，两句话都成立
那一排里有什么窗口那一排和会话那一排是两个主人一排：左段窗口，竖线右边正在进行的指针和遥控看到同一页。实现上要把两个主人合成一页，记进设计文法的对照账

分四段交，每段一次真机

同一根管道，一段只加一层。每段都能单独验收、单独停在那里不坏。

段加什么要的真机证据现在
一第 0、1 层，只有窗口：配对、连上、展开那一排、挪焦点、放回、收起、断开、锁屏。顺便做按键识别触控方向；每个键的键名和按下 / 松开触控已收到 接收器还没进 App

已定的三件事（2026-10-08）

  1. 不要切换模式，指挥模式就是走进一个会话。已定。代价是去掉“按住播放键 1 秒”这个手势，conductor-v2 和《手边的每一样》的键位表已跟着改。
  2. 去掉“档位 / 模型”两个域：手势只管档位，模型在一排里选。已定。代价是拍子不再选模型位置；好处是会话里没有第二个看不见的状态。
  3. 窗口和会话放进同一排，竖线隔开。已定，指针和遥控看到同一页。另一个选法是两排，往下滑再进一排；更清楚，但多一层要记。
