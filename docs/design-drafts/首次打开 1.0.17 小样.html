设计稿 · 2026-10-17 · 目标版本 1.0.18（1.0.17 照现在的发） · 小样，不是 App 本身

首次打开 1.0.17

新装的人先用 10 秒学会一件事：双击标题栏，窗口收成卷帘条；再双击，原样展开。然后才问辅助功能，因为那时他已经知道它是拿来干什么的。第二页同时问辅助功能（必需）和屏幕录制（可选）。最后一页用不到一分钟演四样招牌：收进刘海和刘海教你、窗口浏览、标题栏手势和卷轴、菜单栏图标，每样一组“手上怎么做 / 屏幕上发生什么”的演示，随时能跳过。设置 → 手势用同一套演示。升级上来的人看两页以内：缺授权先把两项再打开一次，再用一页说这一版新开了什么。整个设置窗口也用同一套讲解动画（E 节）。

文件名沿用第一版（1.0.17 小样），内容已按 Aaron 10-17 的两轮补充改成 1.0.18。起点是现在发的三步欢迎窗口（prototype/App/Welcome.swift、WelcomeFlow.swift）和旧稿《欢迎使用 WindowShade》。画板里的窗口按 pt 原尺寸画；顶上能切语言、浅深色、减少动态效果和 macOS 27 的辅助功能新名字。画板里的按钮能点。

这一版改了什么（第 4 版，2026-10-17 晚）

  • 整窗小样九页的每一行都接上讲解：循环的行指上去就演，静图摆一帧，页默认回到这一页默认讲解的关键帧；新加 40 段帧数据，分镜表的时长都是脚本照帧数据现算的。
  • 讲解之间改成两块一起淡出 0.10 s、淡入 0.18 s，指针一进到行上就开始换（实测从进入到开始变化 0 ms 起跳，100 ms 后新内容淡入）；每轮之间、复位时也走同一个淡入淡出，不再跳帧。按下 / 松开从线性改成 ease-out；位移全走弹簧曲线（calm、settle、flyOut、bloom、pop、expand）。
  • 整窗小样和手势页画板按真窗口量：900 × 680、侧栏 204、内容 640、两边各 28；行改成同一张卡片里方角相接，补了行图标。
  • 三种语言：设置小样的行名、副标题、分段、手指一行都取自产品目录里的真文案；讲解块里的字也有英文、繁体。
  • 按全尺寸截图逐页查过简体、英文、繁体 × 浅色、深色，以及减少动态效果和 400 宽；修了：A1 / A2 / T 窗口太空（各降 20–30 pt）、英文侧栏“实验”折行、U1 的屏幕录制行补“可选”、组合行副标题只取第一句、减少动态效果时右块箭头看不清、400 宽下工作单横向溢出与表格挤成一字一行。

为什么要改现在这一版

Aaron 拍板 2026-10-17：1.0.18 起这些默认开（新装和升级上来没动过的都开；已经自己改过的照旧）：刘海主功能（Notch.enabled、Notch.changeAlerts、Notch.teach），刘海实时活动（Notch.activitiesEnabled、Notch.activities.musicEnabled、Notch.activities.nowPlayingStream、Notch.mergedRow、Notch.minimalPresentation、Notch.deviceBattery.enabled、Notch.levelKeys.enabled），Dock 悬停查看窗口（WindowBrowserDockEnabled），文件架和再点一下 Dock 图标让开（FileShelf.enabled、Dock.clickToHide）。这改了“只有真机验过的才默认开”那条纪律：这一批默认开的依据是 Aaron 的决定，不是验过。目的是让新用户一装上就看到 WindowShade 的长处，所以引导要把这几样领出来。

现在的欢迎窗口第一步讲“卡住时刘海告诉你怎么做”，第二步问“你之前常用哪个？”，第三步一次要三项授权。它没有教真正每天用的那一下（双击标题栏收起），也没说图标在菜单栏；而且 1.0.17 里刘海默认关，前两步讲的东西打开后看不到。1.0.18 刘海开了，前两步讲的东西有了，但仍缺核心动作和“去哪找”。

  • 启动时 ensureAccessibility() 带着 AXTrustedCheckOptionPrompt: true，每次没授权就启动都弹系统框，新用户会同时看到欢迎窗口和系统框，两件事抢一个注意力。
  • 授权页一次要三项，而且两项都开才能“开始使用”。屏幕录制只管实时画面（R29 已在虚拟机里验过：没有它，收起、展开、窗口浏览的列表与动作、分屏都照常），所以改成可选、不卡“继续”；日程只给刘海里的“快开会”，等他第一次碰到再问。
  • 手动从 1.0.16 装上来的人没有更新日志（签名换了，Sparkle 不走一键安装），showPermissionOnboardingIfNeeded(force: false) 又因为“看过引导”已经是 true 提前返回。按代码读，他启动后只会看到系统那个弹框，看不到“再打开一次这两项”那一页（推断，没在真机上走过）。

流程

页码点只数 A1、A2、T（三页，HIG 上限）。U1 和 C1 不是引导的一页。欢迎窗口在“设置 → 高级 → 关于 → 欢迎使用 WindowShade…”里随时能再打开，从 A1 看起。整段时长：A1 演示 8 s + 自己试约 5 s，A2 看授权快慢（系统设置里点开关、按 Touch ID 约 15 s），T 约 45–55 s（画板标题旁有现算的数）。

规则（定一次，各页照用）

项定法
尺寸设置窗口 900 × 680，侧栏 204，内容区卡片宽 640。讲解带 640 × 200：两块各 312 × 200，间距 16，圆角 12（system.card），讲解带下面 14 pt 接第一组。帧数据统一用 312 × 200 的坐标，欢迎窗口按 326 / 312 放大。左块底色 quaternarySystemFill，右块是缩小的桌面（菜单栏、刘海、Dock 按需要出现）。
页循环每页有一个默认讲解（列在下面各页表的第一行）。打开这一页时演 2 轮，然后停在它的关键帧（不加箭头）。
行循环指针一进到行上（不等停留）或键盘焦点进到行上，就换成这一行的讲解，一直循环；0 ms 开始淡出，100 ms 后新的一段开始淡入，所以换讲解的反应在 120 ms 以内；指针扫过几行时，每进一行就改目标，不排队；点一下行（不是控件）把它选住，指针移开也接着演。移开且没选住时回到页循环的关键帧，不重新播页循环。同一行最多连演 6 轮（约 25 s）就停在关键帧，指针重新进来再演。
两段讲解之间两块一起淡出 0.10 s、淡入 0.18 s（fade），块本身不动、不换尺寸。块里的东西照各自的弹簧：手指、指针 calm 0.34 / 1.0；窗口尺寸 settle 0.38 / 1.0；飞出刘海 flyOut 0.38 / 0.90；刘海说话 bloom 0.42 / 0.84；小确认 pop 0.30 / 0.75；按下 / 松开 0.08 s 直接切换。中途换讲解时，正在走的弹簧不等停稳，直接淡出（§4.6 不等停稳）。
开关关着时照样演，但两块降到 55% 不透明、去掉饱和度，右块左上角一枚小标签“关着”。他在看的时候把开关打开，用 calm 回到全彩，标签淡出。
有几个选项的行每个选项一段讲解（例如“收起后的样子”：跟原来一样 / 统一标题栏 / 缩略图）。讲解带演的是当前选中的那一项；指针停在分段控件的另一段上，先演那一段（不改设置），移开回到选中的那一项；选了就淡入新的那一段。
只是选项、没有屏幕上变化的行两种处理：静图（这一行有一张值得看的画，例如“窗口之间留缝”的三种缝、隐私的私人窗口、界面语言三种文字）——左右两块摆一帧、不动；页默认（这一行和屏幕上看到的无关，例如诊断日志、导出导入设置、接收器地址）——讲解带保持页循环的关键帧，不为它换画。各页表里逐行标了是哪一种。
什么时候停设置窗口不是最前、被挡住（occlusionState 不含 visible）、最小化、切到别的桌面：立刻停在当前段的关键帧，回来从这一段开头演。低电量模式：页循环不自动播，行循环只演 1 轮。
电量与 CPU只用 CALayer 动画（渲染进程播，不占主线程）；一个窗口里同时只有一个讲解带在动；每段讲解在主线程上只有十来次换帧回调，没有逐帧计时器。目标：演的时候 CPU 不到 1%，停下来是 0；验收时用 Instruments 的 Core Animation 和 Energy 两条量一次，数写回这一节。
减少动态效果不循环。两块摆关键帧，左块画手指 / 指针走向的箭头，右块画结果加原来位置的虚线框（顶上切换能看）。行、选项照样能换画，换的时候直接替换。
VoiceOver讲解带是一张图，名字就是这段讲解的说明句（每段帧数据带一句，例如“演示：在标题栏上双击，窗口收成卷帘条”）。换讲解时发 polite 播报；同一句也挂在这一行的 accessibilityHelp 上，用读屏的人不用悬停也听得到。
