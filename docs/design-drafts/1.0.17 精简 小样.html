右段一次最多放 3 件（NotchRow.swift:50）。编程会话和遥控器的来源本来默认关；旗标关着时它们的开关看不见，这一排不会冒出它们。拷贝只有在实验里打开后才出现。出厂默认值（ReleaseDefaults.swift:26-44）这一稿不改：刘海活动仍由用户自己打开。

建议的隐藏办法

一个键，只管界面。新增 WindowShade.Preview.WS2（Bool，缺省 false，不进 ReleaseDefaults 总账，按 ReleaseDefaults.swift:49「不在表里一律关」）。设置里没有开关；想看的人运行 defaults write com.windowshade.prototype WindowShade.Preview.WS2 -bool YES，重开设置窗口生效。

  1. 侧栏。枚举保留 10 个 case 与 rawValue（lastViewed 键和 SettingsNavigationTests 都靠它）。加一个 visibleCases，换掉 DuoSettingsWindow.swift:362、366 的 allCases；DuoSettingsWindow.swift:392、449 现在拿 rawValue 当行号，要改成在 visibleCases 里找下标；DuoSettingsWindow.swift:10-13 读到被藏的页就退回「卷帘」；DuoSettingsWindow.swift:197-199、509-511 不再建隐藏页。
  2. 页内。卷帘页三处加 if WS2Preview.isOn：Preferences.swift:317 的专注与输入、Preferences.swift:343-346 的 CarPlay 两行、Preferences.swift:356-357 的静音口令。手势页 Preferences.swift:1554 的中键。菜单 MenuBarController.swift:94 的编程会话行。
  3. 先搬后藏。WS2SupplementPane 里「锁屏开合效果」「欢迎使用 WindowShade…」是 1.0 的东西，要先搬到效果页和 高级 → 关于，否则整块藏起来时会一起消失。
  4. 隐私登记。registry.json 给 7 行 WindowShade 2 登记加 appearsWith: "ws2-preview"，旗标打开时放进 enabledFeatures（WS2PrivacyModel.swift:101 现成的机制）。
  5. 不丢设置，也不把人锁在外面。所有键原样保留。若某项 WindowShade 2 开关已经是开的（遥控模式、指挥模式、编程会话、中键、CarPlay、手柄），对应页或行照样显示，让人能关掉。1.0.16 里这些全默认关，实际很少人会碰到。
  6. 不动行为。运行时本来就由各自默认关的键控制（InputFeatureGate、WS2AppRuntime.syncHookServer、FaceScan），旗标不碰它们。探针和测试用 defaults 打开旗标即可。

估计改动：1 个新枚举、约 8 处 if、1 处下标映射、registry 7 行加字段、SettingsNavigationTests 更新。不改任何功能代码。

要 Aaron 拍板的事

  1. 编程会话算不算 WindowShade 2？我按 blueprint 行 5d 和 1.0.16 说明里的「还没上线」归 B 隐藏，但它是刘海里权重最高的活动（95）。你若想让它进 1.0.17，只缩小旗标范围。
  2. 离开就锁、有人在看时收起私人窗口、设备的电量，放进 高级 → 实验，还是留在原页？我建议搬进去，三项都是总账里「未验」。代价是安全类开关从隐私页挪走。
  3. 你自己要不要一个藏起来的入口？我建议只留 defaults 命令，不做界面；日常试用想要的话，可以做成按住 ⌥ 打开设置窗口时临时生效、不落盘。
  4. 要不要顺手把卷帘页里的「刘海」拆成独立一页（侧栏 8 页）？我建议这一版不做，它是排版调整，不是隐藏；瘦身后卷帘页只剩 15 组。
