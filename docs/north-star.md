# 北极星：公认范畴下的全面超越

2026-10-15 重写（第一版把重心放在「别人没有的东西」，那是标新立异——**这一版换成「众人都认可的那几项，每一顶都赢，而且赢到挑不出话」**）。依据：[功能碾压](dominance.md) 的逐格矩阵、[更新日志里的 real-world know-how](changelog-knowhow.md)（626 个 release）、[竞品深挖](competitive-deep-dive.md)、[重塑执行规格](product-reshape-spec.md)。

## 一、什么算「公认范畴」——不是我发明的

两条来源，都可核对：

1. **竞品自己用 626 个版本反复修的那几类**——那是**真实用户在真实机器上撞出来的**，所以是共识（[changelog-knowhow.md](changelog-knowhow.md) 的 A–O 十三个家族）。
2. **评测、对比页、用户抱怨里必然出现的那几项**——资源占用（Wins 官网专门自述「<30 MB、CPU ~0.1%」，说明**这是战场**）、权限（每家都要解释为什么屏幕录制）、兼容（睡眠/唤醒/多屏/全屏/台前调度）、价格与授权。

**判据就一条**：**任何一项，都找得到「比所有已知竞品都好」的可核事实**；找不到就还是欠账。**不靠「我们不一样」来回避对比。**

下面十一项就是这套公认范畴。每项给：**众人怎么评 → 我们现状 → 超越的定义（可核）→ 归到哪条任务**。

## 二、十一项逐项

### 1. 装得上、跑得起来
- **众人怎么评**：装不上就是零分，没有第二种评价。这是所有评测的第一道门。
- **现状（2026-10-15 重写）**：**没有 Developer ID、没有公证**（`codesign -dvvv` 是 Apple Development 凭证，`spctl` 判 `rejected`）——**九家竞品件全部 `accepted / Notarized Developer ID`，十家里只有我们被拦**。发布已恢复（1.0.16 于 2026-10-14 上 appcast），但代价在明细里：**同一版本号重发到第七次**，用户手里的「1.0.16」是多个不同包之一；主程序还是整包里唯一没有 hardened runtime 的执行体。
- **超越的定义**：`spctl -a -vv` 返回 **`accepted / source=Notarized Developer ID`**（就是那九份竞品件的样子）；旧版能通过 appcast 看到新版并装上。
- **归**：[production-maturity](production-maturity.md) B 组；**这是唯一一条「不解决，其余全部出不了这台机器」的。**
- **注意**：这条**没有技巧**——就是花那笔钱、走那个流程。任何「我们不一样」的说法在这里都不成立。

### 2. 不弄坏我的东西
- **众人怎么评**：窗口工具最大的差评就一句——「**它把我桌面搞乱了**」「我的窗口丢了/顺序乱了/留下幽灵」。竞品的更新史里这一类占最多（[changelog-knowhow.md](changelog-knowhow.md) C 族：幽灵窗口、陈旧条目、残留、误退出 App）。
- **现状**：收起走的是真窗口（领先 WindowMizer）；`FoldTransaction` 已有「销毁通知只当提示」这类不变量。**但**：窗口身份边界（orderOut／无标题浮层／静默退出／多实例）**没有系统验过**；没有崩溃上报。
- **超越的定义**：OmniWM 那 **18 个窗口分类夹具**逐条期望一致；`kill -9` 一个 App 后无残留；两实例互不干扰；**误退出 App 一次都不发生**；崩溃有本地报告且能选是否外发。
- **归**：**R20**（窗口身份边界）、**R9**（还原期压掉 App 的 `unhideAllWindows`，**先复现再改**）、**R10**（孤儿占位条）、**R13**（崩溃上报）。
- **Hater 会问**：「你这些功能靠私有 API 吧？系统一更新就废。」**可核的回应（2026-10-15 重写；上一版「没有一处写窗口服务器」是错的，错在只量了 `nm -u`）**：私有 API **确实在用，而且量不小**——`Private/` 四个桥接文件走 `dlopen`／`dlsym` 运行时载入（符号表和呼叫轮廓都看不见）：SLS 的 `SetWindowAlpha`／`MoveWindowsToManagedSpace`／`SpaceCreate`／`HideSpaces`／`ShowSpaces`、DisplayServices 亮度读写、CoreDock、`SACLockScreenImmediate`、`CGSHWCaptureWindowList`……和九家竞品摆在一起（十家同口径），**我们这张运行时清单是最全的**（Notchy／Droppy 只有同款子集）。
  **那还剩什么可说的**：① 私有面**全部隔离在 `Private/` 四个文件**、全部走软失败（`isAvailable` 拿不到就当功能不存在）；② **没有 entitlements 依赖、没有绕过 TCC、没有改别人的 App**；③ 每一处都登记在隐私登记表（66 条 `interfaces`）。**说辞不装**：「我们不用私有 API」是假话；「我们用得比竞品全，但每一处隔离、登记、可摘除」是实话——这才是经得起查的版本。

### 3. 不拖慢我的机器
- **众人怎么评**：菜单栏工具被攻击最多的一句。Wins **官网专门自述**「<30 MB、CPU ~0.1%」——说明这是战场，而且**它自己的两个数字还对不上（30 MB 与 70 MB）**。
- **现状**：常驻 **约 0.31%**（效果关）／**约 0.45%**（开），而且**是从 2.2–2.7% 降下来的**（加速度计轮询 1000 µs → 16000 µs，常驻 4.55% → 1.68%）。**物理占用约 100 MB**。bundle 只有 6.6 MB。三套仪器现成（`--duo-ax-bench`、`--window-browser-idle-probe`、静置口径）。
- **超越的定义**：**同口径下逐项对赢，并且把口径公开**——空载与「开着窗口浏览＋常驻面」两种状态各给 physical footprint 与 RSS；静置按「无操作、不锁不灭、同机、跑三次取中位」**每版一项数字**。**同时给出对外可复核的数字，因为没人公布过口径。**
- **归**：**E1**（静置例行化）、**E2**（查清 Wins 的 30 MB 是什么口径——**先查口径再谈输赢**）、**E3**（对 1.0.15 的长会话卡顿对比）、**E4**（两处 `tolerance`）、**H1**（`mirrorRoundCorners` 的标量循环换 vImage/Metal）、**H2**（QoS 复核）。
- **Hater 会问**：「100 MB，比 Wins 大 3 倍。」**先别辩解**——E2 就是要先把口径查清；**口径一致之后输就是输，赢就是赢。**

### 4. 权限问得少、问得明白
- **众人怎么评**：窗口工具的第二大攻击点，尤其是**屏幕录制**——「为什么一个窗口工具要录我的屏」。竞品为此专门做了「不要屏幕录制也能用」的降级路径（DockDoor「Skipping screen recording no longer **repeatedly** asks」、Ice「limited mode without screen recording permissions」）。
- **现状**：隐私登记（[privacy-page.md](privacy-page.md)；**代码侧 65 个登记项、66 个 `interfaces:` 数组**，连 `CGSession*` 与 `IOHID*` 都列了）；入口处有说明；**但我们确实用屏幕录制**（实时画面与缩略图）。
- **超越的定义**：**没有屏幕录制时，核心动作照常可用**（收起、还原、手势、分屏、窗口浏览的列表与动作），只有「实时画面」降级为静态/占位；**每一项权限都有一句「为什么」**，并且**拒绝一次之后不再反复问**。
- **归**：**R2**（权限被撤要告诉用户）、**R26**（权限弹窗还开着时启动）、**R12**（接管系统 HUD 要留「还给你」的开关）。**新增一条待补**：屏幕录制缺失时的降级路径要写成任务（见 §四）。
- **Hater 会问**：「你一个窗口工具凭什么要录屏？」**可核的回应**：能给出「不给屏幕录制时仍然能用的功能清单」，并且说清实时画面的那一部分**只在本机、不上传**（隐私登记可查）。

### 5. 跟系统和其他工具不打架
- **众人怎么评**：装上第二个窗口管理工具就出事，是所有对比页的第一段。竞品的做法是**检测并警告**（[功能碾压](dominance.md) 第 8 条；**四家**都做了，ChainYourMac 有一张 13 项名单，Wins 名单里还有 `apple.WindowManager`）。
- **现状**：只对 Rectangle 处理过一件事（`App/RectangleImport.swift`）。
- **超越的定义**：**检测＋说清＋协调**——报出名字与影响，**并且让出冲突**（比如快捷键归它时不去抢），而**不是只弹一句警告**。这是「四家只做到检测」之上的一步。
- **兼容矩阵同样算在这一项**：睡眠/唤醒（**Wins 是立即＋0.20s＋0.80s 三档**）、多显示器（接/拔/改分辨率/**两块同型号**）、全屏、Spaces、**台前调度**。
- **归**：**R8**（检测名单现成）、**R3**（唤醒三档）、**R19**（台前调度，**先验收后适配**）、**R27**（按屏落盘的键用 UUID）、**V9**（多显示器矩阵）。
- **Hater 会问**：「装了你会不会跟 Rectangle 打架？」**可核的回应**：V4——**在真装着 Rectangle 的机器上点过一次**（现在这一行 90:90 同分，而且「没点过一次」）。

### 6. 核心动作做得准、手感对
- **众人怎么评**：这一项是「喜欢的人」的来源——窗口工具的口碑几乎全在这里。我们最大的领先也在这里（**看一眼 95 : DockDoor 60**）。
- **现状**：看一眼 95、甩一下 94、侧拉 93、分屏/标题栏手势/收起本体各 92、启动台 90、刘海 88、窗口浏览 92。**但大量「领先」缺真机证据**（盒盖手感要你亲手确认；刘海没在签名构建上重跑；`--shelf-glance` 没在 build 16 上跑；真三指、Magic Mouse、罗技滚轮没人上手）。
- **超越的定义**：**每一项都有真机证据**，且**领先幅度可核对**（探针输出/亲手确认）。**没有证据的领先按定义不算数。**
- **归**：**V 系列 10 条**（尤其 V1 盒盖手感、V2 刘海重跑、V5 真三指、V6 鼠标）、**R4**（原生标签页——窗口浏览落后 Wins 1 分的直接原因）、**R6**（做不了就说一声）、**R7**（几何四级回退链）、**H1/H2**（手感与帧）。
- **Hater 会问**：「你凭什么说比 Swish 的手势好？」**可核的回应**：V5/V6 的真手指与真鼠标记录。

### 7. 学了就会、装了就知道
- **众人怎么评**：窗口工具的学习成本是常见差评（「手势太多记不住」「装了不知道能干什么」）。我们自己有优势：**一套动作多个表面**（收起/看一眼/卷轴/侧拉/刘海 共用一份设计文法），**学会一个就都会**——而竞品多是功能集合（Wins 是什么都能做的清单、Swish 是 30 个手势、DockDoor 是 Dock 增强）。
- **现状**：有教学与教练机制（`coach` 探针、手势教学）；文案有固定词汇表。**但没有「装了之后第一分钟」的完整路径验收**。
- **超越的定义**：**新用户不读文档就能上手**（第一次拖窗口、第一次收起、第一次悬停，各有一处不打扰的提示）；**同一件事在所有表面上的说法与手感一致**；设置里按类别分组（**R16**）。
- **归**：**R16**（手势按类别分栈）、**R17**（Secure Input 可见说明——「为什么快捷键没反应」正属于这一项）。

### 8. 扩展与自动化（市场已经认了这一项）
- **众人怎么评**：三家竞品都发了自动化面——OmniWM 的 `omniwmctl` NDJSON socket、ChainYourMac 的 URL scheme ＋ Raycast ＋ CLI、DynamicLake 的插件市集。**[niri.md](niri.md):91 把它列为「不追」是过时的判断。**
- **超越的定义**：**Apple 的原生答案（App Intents）**——用户免费得到快捷指令、Spotlight、Siri；**不必自造 CLI，也不给用户增加一套要学的方言**。这既满足市场期望，又**比自造的更省**。
- **归**：**N1**。
- **Hater 会问**：「连个 CLI 都没有，算什么自动化？」**可核的回应**：在快捷指令里能搜到并跑通（N1 的验收）。

### 9. 说人话、看得懂
- **众人怎么评**：文案乱、术语不一致，是口碑里最伤且最难改的一类。**我们已经有别人没有的纪律**：固定词汇表、388 行设计文法、12 个禁词、中英文棘轮。
- **现状**：纪律在，**但英文本地化在收尾**；**长语言下的布局裁切没验过**（Wins 栽在德/西/中/日；LaunchOS「text clipped in some languages」）。
- **超越的定义**：**每一种语言里设置面板与常驻面都不裁切**；数字、日期、时间的格式化与**读屏标签**都合当地习惯；同一样东西在所有地方一个名字。
- **归**：**R24**（多语言布局裁切，**德语最长最容易撑破**）、**N2**（系统日志里的诊断也说人话）。

### 10. 活着、越用越好
- **众人怎么评**：**「它还在维护吗」是用户装之前的最后一问**，也是老用户离开的第一原因。竞品的节拍：DynamicLake **79 版/两年**、ChainYourMac **两天三版**、WindowMizer **66 版**。
- **现状**：**170 提交 / 0 发布**。这是我们与所有竞品差距最大的一项，而且**它不需要新功能**。
- **超越的定义**：**按周发版**；**release notes 用用户的话写**（他们能看懂这版修了什么）；**回归零容忍**（发布清单每版必过）；**并让老用户每版能感觉到至少一件变好的事**。
- **归**：[production-maturity](production-maturity.md) A 组 1（发版列车）＋ 长效机制 2（生产就绪清单）；**E1**（静置数字进每版清单）。
- **这一项直接对应「本来就喜欢的人越来越喜欢」**——见 §三。

### 11. 价格与授权
- 免费 ＋ MIT。这一项 **100 : Wins 70**，没有对手，**也不需要做任何事**——**只要不把它做坏**（不做订阅墙、不做试用限制、不锁功能）。

## 三、让喜欢的人越来越喜欢（机制，不是口号）

老用户的感受来自三件事，全都可以制度化：

1. **节拍**：**按周发版**，不做例外。他们每周期待一次。
2. **零倒退**：**回归是唯一会流失老用户的错误**——发布清单里「探针全绿」是硬门槛，回归一次就回滚，不带病发版。
3. **每版一件他们能感觉到的事**：changelog 不写「优化了内部逻辑」，写**他们昨天遇到的哪个麻烦没了**（[copy-guide](copy-guide.md) 的规矩：说用户遇到的事、不说实现）。

**反例就在眼前（2026-10-15 更新）**：1.0.16 在一个版本号下重发了七次——**同一批改进，用户手里有七个不同的「1.0.16」，谁也说不清装的是哪个**；而 v1.0.15 到 10/14 之间的 326 个提交里，还有一批好事在等下一个版本号。R34 的版本号纪律，从「应该做」升级为「下不为例」。

## 四、由这一轮核对补出来的欠账（要变成任务）

重写这一份时逐项核对，发现**有一项公认范畴我们还没有任务**：

- **屏幕录制缺失时的降级路径**（§二第 4 项）：竞品都做了（DockDoor 的「跳过不再反复问」、Ice 的「limited mode」），**我们没有任务**。→ **补进规格：R29**。
- 其余各项的缺口都在已有任务里覆盖，不重复立项。

## 五、什么时候可以说那句话

**十一项全部超越 ＋ 每项都有可核事实**。不是「分数到了」，是**每一项都经得起逐条追问**：

- **装得上**（公证件）→ **不弄坏**（18 夹具全过 ＋ 无崩溃黑洞）→ **不拖慢**（同口径全赢）→ **权限明白**（降级清单公开）→ **不打架**（检测＋协调，且真在装着 Rectangle 的机器上验过）→ **做得准**（V 系列全有证据）→ **学得会** → **自动化面（原生）** → **说人话（全语言不裁切）** → **按周活着** → **免费 MIT**。

**按目前的账，最硬的三步依次是**：**① 让别人装得上**（没有它，其余十项外界看不到）；**② 按周发版**（不需新功能，只需要节拍）；**③ 把 V 系列的证据补齐**（否则一堆「领先」按定义不算数）。
