# 文案规则（产品与官网共用）

写给第一次用的人看。目标不是"显得专业"，而是让人一眼知道这是干什么的、点下去会发生什么。
每条新文案都按这份规则写；改文案时先问"用户会怎么理解这句话"，而不是"我们是怎么实现的"。

## 七条规则

1. **说用户遇到的事，不说我们怎么做的。** 权限、材质、层、几何、`pt`、bundle ID、内部状态名
   都不进用户界面。用户看到的是"窗口收起来了""画面暂时看不到"，不是"折叠事务已完成验证"。
2. **一个东西只有一个名字。** 同一个动作、同一个表面，全产品（应用菜单、设置、面板、官网）
   用同一个词。出现第二种说法就是缺陷，不是风格。
3. **一句话一件事。** 主句先说结果，条件跟在后面。不要三层从句、不要括号里再塞括号。
4. **术语先用日常说法，再给名字。** "收起窗口（卷帘）"可以；直接丢"卷帘条/原貌卷帘/材质"
   不行。非用不可的术语第一次出现时用一句大白话解释。
5. **删掉不改变理解的词。** 形容词、修饰语、"支持多种方式"这类空话一律删。奥卡姆剃刀：
   能少一个词就不多一个词，能少一句话就不多一句。
6. **不承诺做不到的事。** 不写"永远""保证""完全"，不写我们没验证过的数字。
7. **一个符号能说清，就不写一句话。**（Aaron 2026-10-03：“整个 app 多用 SF Symbols，不要大段大段文字。”）设置每一行前面放一个 SF Symbol 加名字；副标题最多一行（约 16 个字），说不完就不说，细节放进 `info.circle` 的小气泡或一段会动的示意。刘海里是“符号 + 不超过 8 个字的主句”，数字放副句。菜单项带符号。符号对照见 design-system.md §4.11。

## 台湾用词（繁体层，第39批）

繁体中文（zh-Hant）是**独立的一层**：字形转成繁体，用词按台湾习惯，跟上面那张简体表**不冲突**——
简体表里「不要用」的清单只约束简体层。例：简体层写「妙控鼠标」（并禁用「巧控滑鼠」），
繁体层就该写**巧控滑鼠**，因为那是 Apple 台湾的官方名。

生成方式：`tools/localize/zh-hant.py` 把目录里每条简体源句走 OpenCC `s2twp`（简体→繁体 +
台湾用词），再套脚本里的台湾专名表，写进 `Localizable.xcstrings` 的 `zh-Hant` 列。

**盲替换的防护**（借鉴 taiwan.md 转换器的做法，见 [taiwan-terminology-converter.md](../research/taiwan-terminology-converter.md)）：
词条表里可以写 `SKIP:` 把一条规则留档但不参与替换，对应他们的 `auto_convert: false`

## 英文用词（第27批起）

英文不是逐字翻译，是同一套规矩换英语写：一个东西一个名字、一句话一件事、术语先用日常说法、能删就删。中文表里的概念在英文里沿用 README 既有的动作词，不另造第二套同义词。第一批（设置外壳 + 「卷帘」页 + 「高级」页）已定下来的对照：

| 概念 | English | 不要用 |
| --- | --- | --- |
| 收起窗口 / 展开窗口（动词） | **roll up / unroll** | collapse、fold、shade、expand（窗口垂直展开的 expand 另说） |
| 收起后留在屏幕上的那条 / 收起后的窗口 | **the rolled-up window bar / a rolled-up window**（首次出现把 bar 解释成 rolled-up window） | strip、bar alone |
| 收起后的样子（设置项） | **What a rolled-up window looks like**；两个选项 **Keep as-is / One consistent bar**；第三种 **Thumbnail** | roll-up style、collapsed look |
| 看一眼 | **Glance** | peek、hover preview |

| 收进刘海 | **Tuck into the notch** | put in the notch、hide in the notch |
| 实时活动 | **Live activities** | widgets、notifications |

| 跟随系统（语言/外观） | **Follow the system** | Auto、System default |

英文行长按渲染实测定预算（`WS2SettingsInfo.englishLineBudget`），超出词边界截断并给 ⓘ；不按中文字宽拍脑袋。**大小写照 Apple 惯例（2026-10-12 定案）**：菜单命令用 Title Case（`Reset Defaults`），设置行、说明、提示、按钮以外的正文用 sentence case（`Reset defaults`）。未迁移的表面继续中文回退，等它那一批对齐这张表；新批只在表里加行，不改已定词。官网（`site/scripts/content.mjs`）与 README 双份随批滚动同步同一张表。

第二批（2026-10-12，静音流程散句）补充对照。静音页是刘海里的一块小表面：命令芯片沿用上表的动词，状态与结果句用短句，不写行话、不写进度黑话。刘海上每句不超过 8 个字的口径中英都守。

## 改前改后（真实例子）

| 改前 | 改后 | 为什么 |
| --- | --- | --- |
| 双击标题栏以折叠 | 双击标题栏收起窗口 | 用户不认识"折叠"，认识"收起" |
| 卷帘样式：原貌卷帘 / 标准标题栏 | 收起后的样子：跟原来一样 / 统一标题栏 | 两个选项名都要求用户先懂行话 |
| 每行一个 bundle ID。被排除的应用不会出现在 Dock 面板与窗口选择面板中。 | 一行一个应用标识。这里列出的应用不会出现在窗口浏览面板里。 | bundle ID 是给开发者看的；功能只有一个名字 |
| 目标无法确认：PID 复用 | 没能确认是哪一扇窗口 | PID 复用是实现细节 |
| 操作超时，底层事务可能仍在执行 | 操作超时，可能还在进行 | 删掉用户无法判断的部分 |
| 一个窗口约 312 × 236 pt | 只占一张卡片那么大 | pt 对网页读者没有意义 |
| 跟随系统（macOS 26 及以上使用真实系统玻璃） | 跟随系统外观 | 用户不需要知道我们调了哪个 API |
