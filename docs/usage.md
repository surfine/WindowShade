## 一句话

入口叫**用量**，长在已有的**编程会话实时活动**里。平时在刘海紧凑状态只看还剩多少；展开后才看恢复时间、
当前模型和思考强度。不做独立统计软件，也不叫「五小时倒计时」——那个名字一遇到周额度、月度额度、
按量付费就要不断加例外，**用量**能容纳这些差别。

## 两份口径要分开

- **用量按账户和实际额度池归属。** 同一个账户开三个终端，就是一份额度，不是三份各自倒计时。
- **正在做什么、用了什么模型按会话归属。** 两扇窗、两个项目是两个会话，共用一个账户的额度。

不能看见 ChatGPT Pro 就写「无限」，也不能给它硬套一个五小时倒计时。ChatGPT Pro 三档在 Work 和 Codex 里
目前没有五小时窗口，但仍有套餐包含的用量额度。

| 使用来源 | 显示什么 |
| --- | --- |
| Claude Code，用 Claude 订阅登录 | 五小时额度、七天额度及各自恢复时间。来源没有提供的项目就不显示 |
| Codex，用 ChatGPT 账户登录 | 按账户实际返回的限制显示。Plus、Standard Business 的五小时窗口要展示；Pro 不虚构五小时窗口，展示实际存在的其他额度 |
| Cursor 自己的 Agent | 按 Cursor 的账户额度与账单周期显示。Cursor 模型与其他模型是两个分开的池，不能因为选了 Claude 就套 Claude 订阅的倒计时 |
| GitHub Copilot | 先认账户实际计费类型。当前的 AI credits 与部分年付用户保留的旧版 premium requests 要分开，不统一换算成五小时 |
| Gemini CLI | 优先显示每日额度，短时请求限制另行提示。Google 账户、Gemini API key、Vertex AI 三种登录规则不同 |
| 自行填写 API key | 只显示可核实的费用、预算或限流恢复时间，不凭空造一个订阅倒计时。API 用量与订阅包含的额度分开 |

还有一件容易混的：**在 Cursor 里跑 Claude Code 扩展，和用 Cursor 自己的 Agent，不一定花同一份钱。**
前者用 Claude 账户登录时可以与其他 Claude 客户端共享订阅用量；后者要看 Cursor 的计费来源。
详情里要能直接写出「Claude 订阅」「Cursor 套餐」「API 按量付费」，不要求用户自己猜。

## 三种显示状态

跟着实际情况变，不让用户先配置一堆小组件。

| 情况 | 紧凑（刘海） | 展开 |
| --- | --- | --- |
| 还有额度 | 「Claude · 余 24%」，旁边一小段进度 | 五小时与一周分开写，各带恢复时间；见下 |
| 额度不足 | 「Claude · 18 分钟后刷新」，提供「恢复时提醒」 | 若真正挡住的是周额度，写「本周额度已用完」，不拿即将刷新的五小时窗口让人空等 |
| 没有五小时窗口 | 不显示这一行，可以显示周额度、剩余积分或当前任务状态 | 同上 |

展开后的示例（数字仅作示例）：

> **Claude**
> 五小时额度余 24% · 2 小时后刷新
> 本周余 61%
>
> **Codex Pro**
> 本周余 58% · 周五 16:00 刷新

几条硬规则：

- 同一屏始终用「剩余」，不要 Claude 显示已用、Codex 显示剩余。
- 五小时和一周分开，不能用一个没有标签的圆环代替。
- 数据没读到写「暂未读到用量」，不能把「没有数据」画成「无限」，也不写成 0 或 100%。
- 上下文占用和账户额度各是一个百分比，不共用一个数。

## 计时定死的行为

- **以服务端给出的恢复时刻为准。** 打开 App、切换模型、重启电脑都不能重新开始五小时。本机程序启动时间不是窗口起点。
- **不照搬手机计时器的暂停按钮。** 关掉 WindowShade、合盖或离开电脑都不会暂停远端额度周期。
- **可用操作只有「暂不提醒」「隐藏」「查看用量」。** 暂停当前任务属于会话控制，要和额度计时分开。
- **倒计时到零先确认一次真实状态。** 离线时写「预计已刷新，等待更新」；确认后才说「额度已刷新」。
- **还能继续用时如实说。** 额外付费仍可继续就写「套餐额度已用完，正在使用额外用量」，不宣布整个客户端不能工作。
- **读不到就留一条轻量退路：手动填写恢复时间**，旁边始终标「手动记录」。不能伪装成已同步的官方用量。
- 紧凑状态显示到分钟就够，不让几个小时的倒计时每秒跳动；展开后再给准确恢复时刻。

## 会话卡的一行

展开某个编程会话后，在项目名下面放一行：**当前模型 · 思考强度 · 是否开启加速**。

- 模型显示客户端实际报告的完整名称。
- 思考强度给容易理解的中文（例如「深入」），同时保留原生的小标签（例如 `high`），方便和客户端核对。
- 支持哪些档位就显示哪些，不强行给所有模型安排相同的低、中、高三档。
- 分清**正在用什么**和**下一轮准备用什么**：用户选了另一个档位但当前任务没切换，写「下一轮：深入」，收到客户端确认后再更新。
- 外部客户端没有可靠控制入口时，先只读显示并给「在客户端修改」，**不向任意前台终端输入命令**。
- 加速模式单独一个小标签（「加速已开」），不和 effort 合并成一个「性能档」；倍率从适用来源读，不写死在界面里。

## 模型构成与费用

放在展开后的「今天」里就够。

- 可以看今天用过哪些模型、各自记录了多少轮、主要用了哪些思考档位。多模型协作的会话再说明主任务和子任务分别用了什么。
- **不画「Opus 花掉了你 73% 的套餐」这样的归属饼图**，除非来源真的提供按模型归属的套餐消耗。
- 只有本机记录就标「本机已记录」；只有调用轮数就按轮数展示。手机上的聊天、另一台电脑的任务不算本机已掌握的记录。
- 估算成本不等于账单。**不能把按 API 标价估算的金额写成「今天已经花掉的钱」**，更不能据此推算「还可以问 37 次」。
- Token、缓存命中、上下文占用留在详情里。

## 和项目接起来

- **额度恢复后回到刚才的项目。** 确认恢复后刘海短暂显示「Claude 额度已刷新」，副句带之前的项目；点一下把那扇窗口放回来。不代提交任务，也不在后台开始花额度。
- **两边同时工作时说清谁在等。** 平时只写「2 个在做，1 个等你」，展开再看各自模型、用量、任务状态。需要批准的会话优先级更高，用量提醒不能盖住它。「完成了」「测试通过」必须来自真实结果，不能因为进程停了就报喜。
- **一边受限时让另一边容易找到。** 例如 Claude 暂时不能继续、已连接的 Codex 仍有可用额度，写「Codex 还有额度 · 过去」。这个动作只带路，不自动搬对话、不切换付费来源，也不宣称两个模型能无损接手。同一个共享额度池内部换个模型，不算额度恢复。
- **快用完只提醒一次。** 默认剩余低于 10% 提醒，每个额度周期一次。用户继续选高思考强度就尊重这个选择，不每条消息都劝，也不因触顶自动终止正在跑的任务。

不做烟花、宠物、消耗排行榜，也不鼓励「今天把额度全部用完」。

## 首版与后续

首版（v1）只交四件事：

1. Claude Code、Codex 的真实用量与恢复时间；
2. 当前模型和思考强度；
3. 额度恢复后回到对应窗口；
4. 上面那三个设置项。

随后再补模型使用构成；再之后补 Cursor、Copilot、Gemini CLI 的账户适配。
桌面客户端、IDE 扩展和独立 CLI 分别验收：接通一个官方接口，不等于已经能读取或控制同品牌的所有客户端。

## 数据来源与读取边界

两家已有可利用的官方能力，首版围绕它们接：

- **Codex app-server**：账户额度读取、变化通知、恢复时间（`account/rateLimits/read`，以及额度更新通知）。带窗口的 `used_percent`、`resets_at`；重置等以来源为准。
- **Claude Code 状态栏**：五小时、七天两个窗口的已用百分比与恢复时刻，以及当前模型等字段。

读取的边界：

- 只读，**不启动新的推理任务**，也不为了一个百分比扫描全部聊天记录或对话全文。
- 只读通道沿用现有那一条，不另开连接。
- 数据没读到就写「暂未读到用量」；读取失败时保留带更新时间的旧值，不阻断原客户端工作。
- 实际支持情况仍要按安装的客户端版本验证，不以文档写了就算能读。

## 连接与隐私

延续现有的明确授权做法：

- 说明要读什么、要改哪些配置；**先给看差异，先备份**；用户原来的状态栏和 hooks 保留。
- 能**干净断开**；卸载前提醒先断开。账户切换后清掉旧账户的显示。
- 浏览器 Cookie、密钥和对话全文都不作为默认采集对象。
- 用了私有接口就登记到隐私页，并留下系统更新后的退路。

## 设置

先只留三项：

| 设置项 | 作用 |
| --- | --- |
| 显示用量 | 是否在刘海紧凑状态显示剩余 |
| 不足时提醒 | 快用完时提醒一次（默认剩余低于 10% 时） |
| 恢复时提醒 | 恢复时提醒，点一下回到对应窗口 |

其他信息都随当前账户与会话变化，不让一般用户先学会各家的计费规则才能用起来。

## 不做

- 不做独立统计软件；不新开一个宿主，不占满持续活动的位置。
- 不做暂停按钮；不发明一套和远端额度周期无关的本机计时。
- 不把「没有数据」画成「无限」，也不写成 0 或 100%。
- 不把按 API 标价的估算成本写成账单，也不据此推算还能问多少次。
- 不自动搬运对话，不在两个模型之间宣称无损接手。
- 不因触顶自动终止正在执行的任务。
- 不向任意前台终端输入命令。
