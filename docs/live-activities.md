# 实时活动与刘海手势

这是本地开发版的功能，不代表已发布的 1.0.16 下载包包含它。

从菜单栏选择「实时活动」，或在启动台第一页向右轻扫，到负一屏查看卡片。时钟、日历、搜索仍在原处。刘海显示最多三个活动入口；左右轻扫切换，停在刘海上或长按展开。没有刘海的外接显示器使用顶部正中的同一入口。

首次使用音乐，先在音乐或 Spotify 中播放，再在负一屏点「音乐」，允许系统询问的控制权限。随后显示曲名、歌手、实际播放进度；展开后可以播放／暂停、上一首／下一首。没有进度信息时不画进度条。开启或停止音乐连接不会自动播放。

| 活动 | 已接入的真实来源 | 当前边界 |
| --- | --- | --- |
| 音乐 | Music / Spotify 的 Apple Events；后台串行查询 | 显式连接，未接浏览器与所有其他播放器；不使用失效的跨应用 `MPNowPlayingInfoCenter` 读取 |
| AirPods | Core Audio 的实际蓝牙音频设备、在线状态和声音输出 | 当前通过设备名称识别 AirPods；改名后不含 AirPods 的设备可能识别不到。没有电池数据时不显示电量 |
| 隔空投送 | 选择文件后调用系统 `NSSharingService.sendViaAirDrop`，跟随完成／失败回调 | 跟踪本工具发起的分享，不读取 Finder 发起或收到的所有传输；不编造传输百分比，也不把分享完成当成接收方已经打开文件 |
| 地图路线 | 输入出发地、目的地，用 MapKit 查询真实行车路线与预估时间，点卡片在地图打开 | 是本工具查询的路线；没有接管 Apple 地图逐向导航，没有伪造剩余距离或“已走过”的进度；可以移除路线 |
| 语音备忘录 | macOS 14.2 起 Core Audio 的进程输入状态；有辅助功能权限时读取明确的录音控件 | 明确且可用的暂停／停止录音控件才显示「正在录音」；继续录音控件显示「录音已暂停」。只能确认麦克风时显示「麦克风使用中」。未读取音频、录音内容或文件，未代替语音备忘录启动录制 |

三个位置优先用于语音备忘录、隔空投送、路线，再显示音乐、耳机；内容更新不打乱选中项。结束或移除的项会让出位置。分享完成／取消的提示停留四秒；路线查询失败停留六秒。设置 → 刘海 →「实时活动」可关闭两处显示与后台来源。睡眠、锁屏和用户会话退出各自暂停；一次唤醒不会越过仍未解除的锁屏暂停。

## 手势

| 输入 | 刘海 | 窗口标题栏 |
| --- | --- | --- |
| 单击／双击／三击 | 原有主屏幕／调度中心／这个 App 所有窗口；紧凑活动内容单击打开对应详情 | 保持现有窗口与系统点击行为 |
| 双指横向轻扫 | 活动之间跟手切换；启动台打开时仍翻启动台的页 | 沿用左半屏、右半屏及进一步排布 |
| 双指纵向轻扫 | 下拉拿回窗口，上推全部收进刘海 | 沿用收起、铺满及撤销 |
| 双指张开／捏合 | 沿用退出／回到主屏幕 | 沿用魔法平铺／撤销排布 |
| 双指轻点两下 | 收到系统的智能缩放事件时，展开／收回；无活动时进入负一屏 | 沿用铺满／还原；卷帘条展开 |
| 双指点按 | 系统设置为辅助点按时，打开活动操作菜单 | 保留 App 的辅助点按行为，不抢它自己的菜单 |
| 按住约半秒 | 有活动时展开详情，无活动时到负一屏 | 确认真实标题栏、窗口没移动且仍按住后，显示收起、半屏、铺满与魔法平铺菜单；不自动执行 |
| 拖动（鼠标或系统三指拖移） | 同一条横向切换／纵向拉出接线；移开或取消不会再触发长按或点击 | 沿用系统拖移、甩动与落点判断 |
| 系统投递的轻扫事件 | 可切换活动／启动台页面 | 系统三指切桌面、调度中心等仍交给 macOS |

触控板的“点按”“辅助点按”“智能缩放”“三指拖移”取决于系统设置。没有为每个手指数发明一套命令；只有 macOS 实际投递的事件才会进入接线。三指轻扫与辅助功能拖移仍需在用户实际设置下做硬件验收。

## 动画与检查

刘海继续使用原来的 Core Animation 外形、连续圆角、同步遮罩与弹簧。活动切换只改变三张常驻卡片的图层平移；独立的固定裁切区域避免相邻卡片露边。抓住动画时读取 presentation layer，从当前显示的位置继续；连续选择替换上一段弹簧，避免残余位移叠加。取消不提交选择，活动结束会撤销捕获的旧手势；减少动态效果时不加弹簧。

设备查询、Apple Events 与子进程都在串行后台队列，轮询间隔两秒且不重叠；脚本有超时、停止令牌和有界输出，快捷连续控制不会无限排队。没有逐帧设备查询或图像下载，也没有采集麦克风声音。符号图像缓存供图层复用。窗口合成由 Core Animation 和 WindowServer 完成，不为简单卡片额外运行 Metal 渲染循环。

已检查纯活动状态、既有标题栏手势、AppKit 全套回归及活动视图边界。首轮 3,150 次拖动事件 CPU 处理耗时 p95 0.003 ms，最大 0.050 ms；并发构建时一次复核 p95 0.005 ms、最大 26.805 ms。这是事件处理耗时，不是 GPU 帧率。

`tools/activity-frame-probe/run.sh` 会显示六秒带「测试数据」标记的本地检查窗口，报告显示链接间隔与主线程处理耗时。构建结束后的首次复核得到 360 次显示回调，间隔中位数 16.67 ms、p95 16.72 ms、最大 47.27 ms，有一次超过中位数 1.8 倍的间隔；手势处理 p95 0.117 ms。探针用 `-O` 编译活动生产视图，测的是主线程与显示链接交付，不能据此判定 GPU 实际呈现帧数或承诺零掉帧。可变刷新率、机器负载、设备驱动和第三方 App 都会影响现场结果。

原生来源的真实只读检查收到快照并通过停止／重启和停止后不交付验证；当时没有对应的活动设备或录音，未请求音乐授权、未采集声音。音乐授权后的播放控制、实际 AirDrop 接收、语音备忘录录音状态，以及用户系统设置下的触控板手势仍需现场验收，视图测试不能替代这些结果。

截图来自生产视图与明确的测试数据，见 `.build/appkit-tests/activity-shots/`。运行：

```sh
bash tests/run-notch-activity-tests.sh
bash tests/run-gesture-tests.sh
bash tests/run-appkit-tests.sh all
bash tools/activity-frame-probe/run.sh
cd prototype && ./build.sh --check
```

## 第一方依据

[Apple Live Activities HIG（中文）](https://developer.apple.com/cn/design/human-interface-guidelines/live-activities)：紧凑内容可扫读，展开延续同一信息；负一屏的大卡片提供必要操作；状态不变时不重复动画或提示，及时结束活动。这里是 WindowShade 的 macOS 活动视图，不把它宣称为 iOS ActivityKit 或系统锁屏组件。HIG 提到配对 iPhone 的活动在 Mac 菜单栏由系统呈现并打开 iPhone 镜像；这不等于第三方可以枚举全部其他 App 活动。

[Apple NSSharingService](https://developer.apple.com/documentation/appkit/nssharingservice) 与[隔空投送服务](https://developer.apple.com/documentation/appkit/nssharingservice/name/sendviaairdrop)用于本工具发起的分享；[MapKit MKDirections](https://developer.apple.com/documentation/mapkit/mkdirections)用于路线计算；[AppKit smartMagnify](https://developer.apple.com/documentation/appkit/nsresponder/smartmagnify(with:))用于系统识别的双指轻点两下。

借鉴 [Alcove 的实时活动与手势入口](https://notch.macmenubar.com/alcove)的组织方式，沿用 WindowShade 自己的窗口收纳、启动台与动画实现，没有复制 Alcove 的私有实现。
