## 我们的做法

### 离开就锁

| 信号 | 用法 |
| --- | --- |
| **手机断开** | 主信号。Mac 和绑定的 iPhone 保持一条蓝牙连接（Mac 主动连，照 PhoneKey 的路），每隔一会儿读一下确认连接活着；读不到回应 2 秒，也算断开 |
| 手表断开 | 绑定了手表时，规则是“**手机和手表都走远了**才锁”（Aaron 9 月 30 日定），只走一样不锁 |
| 摄像头看不到你 | 辅助。只在停手 30 秒后每秒看 2 帧；看不到人一段时间，也进入同样的倒数 |
| 信号强度 | **不用来锁。**Near Lock 的教训 |

断开以后：

1. **先静默宽限 1.5 秒**，挡掉 iOS 蓝牙的瞬间断开。这段时间里重连上，就什么都不发生。
2. 然后刘海亮出 `figure.walk` **手机走远了 · 10**，开始倒数。碰一下键盘或触控板、手机重连上，都会取消。
   因为碰一下而取消时，说明人还在，只是手机不在身边：这之后停手 1 分钟，才会再开始倒数。
3. 倒数完：桌面折进刘海，锁屏。先把私人 App 收进刘海，再锁。
4. 离开时如果有音乐在放，就暂停；回来解锁后继续放（BLEUnlock 的做法）。

比 Windows 快：最多 11.5 秒，而不是 60 秒。而且锁之前，刘海一直写着“马上要锁”。

### 回来就开

只在下面几条**全部满足**时才代填密码：

1. 这次锁屏是“离开就锁”锁上的。手动锁的、屏保锁的、刚开机的，都不自动开（PhoneKey 的规矩）。
2. 手机**重新连上**，并且读到了回应。只收到广播不算。
3. 信号强度**连续 2 秒**都高于靠近阈值（默认 −60 dBm，设置里有三档：近、中、远）。
4. 刷脸解锁打开时，**脸也要认出来**：每次刷脸解锁都要手机，回来就开也要脸（Aaron 定的多因素）。

密码放在钥匙串里，用 Touch ID 保护的钥匙加密，不像 PhoneKey 那样用本机 UUID 派生的密钥存成文件。一次锁定最多试 3 次（和刷脸解锁一样），之后只能用 Touch ID 或密码。

> 待 Aaron 定：**没开刷脸解锁的人，能不能只靠手机回来就开？**这就是 Near Lock 和 PhoneKey 的做法，方便，但别人拿着你的手机走近也能开。建议做成选项，默认关；打开前先看一页风险说明。

### 从 iPhone 远程锁

照少数派那篇的专注模式做法，WindowShade 提供一个能被快捷指令调用的动作 `windowshade://lock`（URL）：

- 锁屏前先把私人 App 收进刘海；
- 锁屏后，刘海的“离开期间”摘要里写“从 iPhone 锁上的”。

设置里给一张三步的图示：在 iPhone 上建一个专注模式，在 Mac 上建一个快捷指令自动化，调用这个 URL。

## F1 实验现在怎么做

PhoneKey 证明了一件事：Mac 主动连 iPhone、读“设备信息”服务、靠断开判断离开，不需要手机端 App。但“连得上”不等于“是你的手机”。F1 要补的是**身份**：

1. **连接与保持**：照 PhoneKey 的路，测连接稳定性；测手机在兜里、握在手里、锁屏、低电量模式下，多久会被断开。
2. **证明是那台手机**：读一个**需要加密**的特性，迫使系统用配对时的长期密钥加密连接。只有配过对的那台手机做得到。候选是 iPhone 只对配过对的配件开放的系统服务，比如 ANCS（通知中心服务）。要实测：它是否需要 Mac 扮成外设，以及配对弹窗怎么出现。
3. **手表**：照 BLEUnlock 的说法，手表也能被看到。实测它是广播还是连接、地址是否固定。
4. **能耗**：手机端每天多耗多少电、Mac 端唤醒次数。

做不到第 2 条时，蓝牙只能算“在场”信号，不能算“身份因素”。这时如实写下来，再和 Aaron 定替代办法（face-unlock.md 硬要求 3）。

## 能耗

- 锁屏只看连接事件：不轮询，不读信号强度。
- 信号强度只在锁屏期间每 0.5 秒读一次（判断回来没有），平时不读。
- 连接保持的“读一下”间隔：先用 5 秒，按 F1 实测再调。

## 隐私登记

- 绑定的手机、手表的设备标识（只存本机）。
- 蓝牙连接和信号强度（只在内存里用）。
- 登录密码（钥匙串，Touch ID 保护）。

日志不写设备标识全文，不写密码，不写读到的特性内容。

## 做的顺序

| 步 | 做什么 | 谁 |
| --- | --- | --- |
| L1 | 在场状态机（纯逻辑）：断开 → 1.5 秒宽限 → 10 秒倒数 → 锁；任何输入或重连取消；手机加手表都走远才锁；回来就开的四个条件；3 次上限 | DeepSeek |
| L2 | 蓝牙监视（App 层）：绑定、连接、保持、读回应、锁屏期间读信号强度；断开的 2 秒判定 | DeepSeek 写，主模型复核 |
| L3 | F1 身份实验（加密特性、手表） | 主模型 + Aaron 的手机 |
| L4 | 刘海倒数、锁前收起私人 App、暂停 / 继续播放、`windowshade://lock` | DeepSeek 写，主模型复核 |
| L5 | 回来就开：接刷脸解锁的代填密码会话 | 主模型（安全核心） |
