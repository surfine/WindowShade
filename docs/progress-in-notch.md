2026-10-06。Aaron 的话：拷贝和移动文件的进度，天然适合放在灵动岛（实时活动）里，Apple 官方已经在这么做。
本文先记录范围：**没有改产品代码，没有接任何来源，没有真机读数。** 状态一律 `planned`，不写 `hardware_pass`、不写 `qualified`。

这份文件正面回答 [notch.md](notch.md) 的「下一步」里留着的结论：**「提醒目前只看标题。进度（下载、导出）没有统一的公开来源，暂不做。」**

## 一句话与范围

**一句话：有起点、有终点、现在到哪的事，才进刘海；它已经到哪，就画到哪，读不到就不画。**

只收**进度类**：一件有开始、会结束、中间有量可报的事。

不收**状态类**：电量、时间、信号、来没来电、连没连上。这些没有「进度」，也没有终点，本文一概不碰；
它们各有各的线（[device-battery.md](device-battery.md)），也不要借这一条挤进来。

刘海在这里的位置只有一句：**它是眼平高度那一格。** 系统已经有位置的地方不重播——
Dock 图标上的进度、Finder 窗口标题里的进度、菜单栏上镜像过来的 iPhone 实时活动，都各在原地，刘海不抢、不抄。

## 第一方依据

**Apple 官方已经在做**（这一条是本文的起点）：

- iPhone 动态岛会显示 **隔空投送连接**；Apple 支持页写明可长按展开看更多详情。[Apple 支持页《在 iPhone 上查看动态岛里的实时活动》][apple-la]
  （「展开后就是传输进度」这一步来自第三方介绍，未见 Apple 官方页，按「未核」记。）[beebom]
- **Safari 下载**在 iOS 18.2 起也进了实时活动，锁屏与动态岛都能看。（同样只有第三方报道，按「未核」记。）[macreview]
- macOS 26 起，**iPhone 的实时活动出现在 Mac 菜单栏**：菜单栏放不下时缩成一个小图标；点一下展开看详情，双击经 iPhone 镜像打开源 App。
  可在「系统设置 › 通用 › 隔空投送与接力 › iPhone」里开关。[apple-mac][apple-newsroom][9to5]
- 但 **macOS 27 仍没有给第三方 Mac App 的原生实时活动 API**。Mac 侧只有 iPhone 镜像进来的那一类；第三方（含本工具）都是自己做覆盖层。
  这一条同样来自第三方整理，要按「未核」处理。[droppy]

**公开接口确实存在**（本文判定「来源可以真读」的依据）：

- **跨进程进度**：`NSProgress.addSubscriber(forFileURL:withPublishingHandler:)` 能听见另一个进程 publish 出来的同一份进度；
  对方必须自己建 `NSProgress`、把 `fileURLKey` 指向目标文件、再 `publish()`。[apple-sub][apple-pub]
  关键是：**观察方要能看见那个文件，也要对方真的 publish。** 对方不 publish，这条路就没有数据。
- **iCloud 的百分比**：`NSMetadataQuery` 对云盘项目提供上/下载状态与百分比键。**这些键在 macOS 27 的真实行为要探针确认。**[apple-mdq]
- **我们自己发起的传输**：`URLSession` 的下载进度回调、自己写的分块拷贝，进度都是我们自己报的，最干净。

**对表：**第三方宿主 Droppy 的 `LiveActivityProviding` 把「发布是请求、不是命令；高优先级的活动可以抢走名额」写成公开契约，
正好对上本工具协调器「最多三条、被占时不改名单」的取舍，可作旁证。[droppy-api]

## 来源五层

每一件想进刘海的进度，先落层。层的分法是**「这个数是谁给的」**，不是「谁在跑」。

| 层 | 数从哪来 | 例 | 准入 | 读不到时 |
| --- | --- | --- | --- | --- |
| **A 自己发起** | 我们自己报的进度 | 本工具自身的更新下载、刘海自己发起的拷贝 | 无额外条件 | 不会有「读不到」，只有失败 |
| **B 公开 API 可观察** | 系统的公开接口 | `NSProgress` 订阅、`NSMetadataQuery` 的 iCloud 百分比 | 先探针证明能读到；先登记读取 | 退回不画不确定弧 |
| **C 命令或文件可读** | 命令列输出、别处写出的清单文件 | 备份、加密这类系统长任务 | 要授权、要登记、要有超时与有界输出 | 退回不显示，不猜 |
| **D 读别的 App 的界面** | 辅助功能读控件 | 读第三方传输软件的进度窗口 | **默认拒收。**要收先过探针，写明版本与语言依赖、降级路径 | 整条不做 |
| **E 明确拒绝** | 没有真来源、或系统已有位置 | 编造百分比、轮询私有 XPC、抄 Dock 的进度 | 见「不做」 | — |

三条贯通规则：

1. **没有总数，就没有百分比。** 只画不确定弧（`progress = nil`），不拿已传字节数除一个猜出来的总数。
2. **读到的数原样放，不改口径。** 来源给的是「已用」就写已用、给「剩余」就写剩余，但同一屏内部保持一种说法（见下）。
3. **一层不成立，就往下一层退，不往上一层编。** 退不了就回到「什么都不显示」，并在探针清单里记一笔。

## 场景目录

固定字段：**场景 / 谁发起 / 来源层 / 紧凑两耳 / 展开看什么 / 能不能暂停或取消 / 现在结论**。
「现在结论」只有四种：`已在做`（已经接上）、`可做`（来源明确、结构支持）、`待探针`（来源存在但要验）、`不做`（见「不做」）。
本文不把这些写成已实现；最右一列是本文的判断，不是代码状态。

| 呈现 | 进度在这里长什么样 |
| --- | --- |
| 最小 | 一侧一个点或图标，仍带进度量或语气色，不退成空标 |
| 紧凑 | 岛的两耳：**左耳是谁，右耳是量**（沿用既定排法，不另做一版） |
| 短暂提醒 | 开始与结束各一次（完成、失败、取消），约 2.6 秒，走 `alert.hold` |
| 展开 | 半岛下鼓：目前是哪一项、已完成/总数、剩多少、速度（有就写）、暂停或取消 |
| 交互 | 本文件不新增；取消确认这类动作仍归已有的交互形态 |

**空位不够时**退成下巴或最小，不挤掉别的持续活动：同一时刻最多三条的老规则不变。

### 两耳写什么

- **左耳 = 是谁。** 动作 + 对象名字，例如「拷贝 · 报告.docx」「备份 iPhone」。名字长了就只留动作 + 类型，
  例如「拷贝 3 项」。**不把完整路径放进刘海。**
- **右耳 = 量。** 三种择优：有百分比写百分比；只有项目数写「第 k / n」；两项都没有，画不确定弧。
- **同一个动作只有一个词，全产品一致。** 统一说「拷贝」，不混用「复制」；统一说「移动」，不混用「搬移」。叫法以 [copy-guide.md](copy-guide.md) 的固定词表为准，进界面前再核一遍。

### 进度可以缺席

`NotchActivity.progress` 本来就允许 `nil`，本文件把这条用起来：

- 只有「已传字节数」、没有总数 → 不画百分比，画不确定弧。
- 总数会变（压缩率未知、云端返回的总量在涨）→ 宁可退回不确定弧，也不要百分比来回跳。
- 暂停时**不**把进度条清零，也不继续走；写「已暂停」。
- 完成后不把条走到 100% 再停在那里很久，按 `alert.hold` 报一次就退。

### 多件事排在一起

- 同类合并成**一条**排队活动，右耳写「第 k / n」，不一件占一个名额。
- 一件开始时建一条活动；整个过程 `generation` 不变，进度刷新只改 `progress` 与 `detail`。
- **普通进度更新不重排**持续活动顺序（沿用 `NotchActivities.swift` 的排序规则：只看优先级与开始时间，不看 `updatedAt`）。

### 候选句（还没进词表）

真正进界面前按 [copy-guide.md](copy-guide.md) 过一遍。当前候选：

- 动作：「拷贝」「移动」「压缩」「解压」「备份」「还原」「下载」「上传」「导出」「转档」「安装」
- 紧凑：「拷贝 · 3 项」「备份 iPhone · 62%」
- 展开：「已完成 4 / 7」「还剩 8 分 20 秒」「每秒 12 MB」
- 状态：「已暂停」「正在收尾」「已完成」「已取消」「没读到现在到哪」
- 动作按钮：「暂停」「继续」「取消」「在 Finder 里看」（能交回原 App 时一律交回，不自己重做一遍）

写这些句子的三条自检：**有没有总数才写百分比**；**有没有把实现说出来**（不写 XPC、不写 API 名）；
**同一个动作是不是只用一个词**。

## 仲裁与让位

### 名次

建议新增一个 kind：`transfer`，权重 **75**。理由：

- 低于 `airDrop`（80）：空投本来就是转账的一种，本工具发起的空投仍走空投那条，不抢自己的名额。
- 高于 `route`（60）与 `music`（40）：转账有明确的终点和可报的数，比播放和路线更需要「还剩多少」。
- 高于 `airPods`（20）：它比一个连接状态更是「正在进行的事」。
- 仍低于 `recording`（90）与 `focus`（85）：录音和番茄钟是用户此刻在做的事。

要不要真的加这个 kind、权重取多少，等有画面稿时再定；本文只给出建议与理由。

### 让位

- **放行类最高。** 刷脸解锁、Touch ID 确认、审批占住时，进度不展开、只留小点，让出后按现在的事实回来，不补播。
- **先让开系统。** 展开前先看那段菜单栏上有没有系统的东西（系统状态图标、iPhone 镜像来的实时活动）；有就不展开，只标点。
  这是 [notch.md](notch.md) 已有的规则，进度类沿用，不新开一条。
- **和「有变化时提醒」不打架。** 同一件收起的窗口，标题变了走「有变化时提醒」；它触发的下载 / 导出走进度类。
  两条同时撞上时，**进度优先**（它有终点、会自己结束），标题提醒退成点，不两条一起播。

## 能耗与隐私

### 能耗

- **有活动才订阅，空活动零成本。** `NSProgress` 订阅、查询、轮询都只在确实有活动时建立；活动一结束就撤掉。
- **不逐帧。** 沿用现有节奏：后台串行队列、轮询不重叠、有间隔；长任务（备份、加密）间隔更长、带退避。
- **订阅有界。** 同时订阅的进度对象有上限，超了就不再接新的，不无限长。
- **看门狗。** 来源迟迟不更新就按未知处理，不无限重试；不因为一条来源卡住，拖慢整个活动列表。
- **可量。** 上机时按「同一颗二进制、开与不开」比一次能耗；本文不给数字，也不承诺「更省电」。

### 隐私

- **只读大小与状态，不读文件内容。** 不打开、不解码、不抽样。
- **文件名不进日志。** 日志只记「哪条来源、什么时刻、读到没有」，不写路径与文件名（沿用既有日志规则）。
- **每一个新读取先登记。** 走信号登记表，「读到的」一页每新增一项就是一行：读什么、为什么、去了哪、能不能关。
- **不碰私有 XPC 与私有框架。** C 层只走公开命令与公开文件；D 层默认不做。
- **TCC 边界写明白。** 需要授权才能读的（例如受保护目录），明说不授权就整条退到「不显示」，不用别的数顶替。

## 探针清单

**先做探针，才决定做不做。** 每条写：探什么、怎么算过、不过退回哪一层。

| 编号 | 探什么 | 怎么算过 | 不过就退回 |
| --- | --- | --- | --- |
| P1 | Finder 拷贝 / 移动会不会 publish `NSProgress` | 对目标目录 `addSubscriber`，拷贝一个真实文件，能收到连续 `fractionCompleted` | 文件与磁盘整组退回 `不做` |
| P2 | `NSMetadataQuery` 的 iCloud 上/下载百分比键在 macOS 27 的真实行为 | 真实上传与下载各一次，读到会变的百分比 | iCloud 三条退回 `不做` |

探针不通过就**记一笔**：写明探了什么、为什么不过、退到哪。不因为「差一点」就先接一个假的。

## 不做

- **不编造百分比。** 没有总数就不画进度条（沿用 [live-activities.md](live-activities.md) 既有规则）。
- **不轮询私有 XPC、私有框架、私有图形接口。**
- **不抄 Dock 图标和 Finder 标题上的进度**——那是系统自己的位置。
- **不在菜单栏已经有系统 iPhone 实时活动时再播一遍。**
- **不代替来源做操作。** 只有本工具自己发起的任务（A 层）才自己暂停 / 取消；别人的任务交回原 App。
- **不做独立下载管理器，不新开宿主，不占满持续活动的位置。**
- **不读文件内容，不把文件名写进日志。**
- **不把状态类信息（电量、时间、来电、连接）做成进度。**
- **不因为一次进度更新就重排活动顺序、跳选、重播进场。**
- **不把「完成」写成「对方已打开 / 已使用」。** 传完就是传完，收件方做了什么，我们不知道，也不说。
