# 欢迎使用 WindowShade

首次打开时出现，菜单里的“欢迎使用 WindowShade…”随时能再打开。2026-09-29 按 [direction.md](direction.md) 的决定从七页缩成三步：
一句话说清它是什么；问“你之前常用哪个？”；授权。收起、看一眼、标题栏手势、刘海、侧拉这些不再在这里一页页讲，交给刘海在他卡住时教
（规则见 [stuck-habits.md](stuck-habits.md)）。设计要求见 [design-system.md](design-system.md) §5.11。

**三步之前可能多一步：放进“应用程序”文件夹。** 只在从“下载”、磁盘映像等地方直接打开、而且这是带更新器的版本时出现（开发版不问），
不算在三步里、没有页码点。标题“放进‘应用程序’文件夹”，一句话“Mac 上的 App 都放在这里。放进去以后，才能在菜单里更新 WindowShade。”；
舞台位置上是这个 App 的图标 → “应用程序”文件夹的图标（都是系统给的图）。按“移到‘应用程序’”，图标朝文件夹滑过去、变小、变淡
（减少动态效果时只变淡），放好后从新位置重新打开、接着从第一步走；没移成就说“没能移过去……”，主按钮换成“在访达中显示”，“继续”进第一步。
“跳过”（或 →）之后欢迎窗口不再问，更新小窗里位置不对时还会再给这一步。“应用程序”里已经有不比它旧的那一份时，这一步变成“打开它”。
流程和保护见 [update.md](update.md)，文案在 App/UpdaterCopy.swift。授权页在标准账户下多一句“打开这两项时，要输入管理员的名字和密码。”；
装好新版本后两项授权没了时，授权页换成“再打开一次这两项”那组文案。

## 第一步

- 一句话（direction.md）：先说“你会的在 Mac 上照样有”，再说 WindowShade 替你做什么。不替 Apple 的硬件下定义（不说“刘海是一个入口”），也不说“像 iPad 一样”（design-system V1、V6）。
  **候选，由 Aaron 挑**（代码里暂用 A）：
  - A：你熟悉的操作 Mac 上照样有，卡住时刘海告诉你怎么做。
  - B：卡住时，刘海告诉你 Mac 上怎么做。（只说它做什么，最短）
  - C：卡住时，刘海帮你一把。（design-system V6 里的候选；帮什么交给下面的动画）
- 动画里刘海说的两句照卡住时的真提示写：菜单里那一项叫“拷贝”，副句“常用快捷键把 ⌃ 换成 ⌘”；键帽上印着 control、command，
  第一次见到 ⌃ ⌘ 的人知道是哪个键。刘海是纯黑、从刘海本身往下长，字白色、副句白 0.6（design-system §4.3）。
- 没有刘海的屏（外接屏、没有刘海的 Mac、“避开刘海”模式，按窗口所在那块屏的顶部安全区判断）：舞台不画刘海，平时顶上什么都没有；
  开口时菜单栏正中浮出一颗胶囊（四角都圆、顶上留缝、没有摄像头那一截所以矮一些，两行字在正中），说完缩回、淡掉
  （design-system V1、§8 问题 2）。窗口挪到另一块屏、有没有刘海变了，当页重画。
- 舞台的 VoiceOver 名字是这段动画演了什么，和下面那句话分开读。

## 第二步

- 点一下就存进 `SwitcherOrigin`（`prototype/Core/SwitcherOrigin.swift`），关窗口、跳过都不丢；选中的一格加强调色的边和一个勾，不只靠颜色。
- 选了才能“继续”；不想答就“跳过”，算没答（直接到授权页）。再打开欢迎窗口时画的是存着的答案；设置里改了、刘海问过之后他点了，开着的欢迎窗口也跟着变。
- 键盘：Tab 进到三个选项（有焦点环），← → 换一个并选中，空格选中，回车是“继续”。用鼠标点不接焦点（按下鼠标那一下选项说“不接”，
  窗口就不挪焦点；不能在接焦点时再拒绝，那样焦点会落到窗口自己身上，← → 没人接），所以点完 ← → 照常翻页。
  焦点本来就在某个选项上（用键盘进来过）时，点哪个焦点跟到哪个，焦点和选中还是同一个。
- VoiceOver：三个选项是一组单选按钮，组名是“你之前常用哪个？”。
- 设置里的同一件事：“卷帘”页“刘海”一组的“之前常用”，Windows / iPad / 一直用 Mac 三段，没答时一段都不选。

**给别的模块用的接口**

- `SwitcherOrigin.current`：`.windows` / `.ipad` / `.mac` / `.unanswered`。存在 UserDefaults 的 `SwitcherOrigin` 键里，值是 rawValue；
  没答就是没有这个键（新装、老用户升级都是没答）；认不出的值当没答。
- `SwitcherOrigin.didChangeNotification`：答案真的变了才发（同一个答案再点一次不发），总在主线程发：在主线程改的当场发，
  在别的线程改的排到主线程再发（订阅的都是界面）。`current` 哪个线程都能读写。
  `userInfo[SwitcherOrigin.previousKey]` 是原来的 rawValue，新的直接读 `current`。
- `SwitcherOrigin.answers`、`title`：界面上的顺序和名字，欢迎窗口和设置共用。
- 单测：`tests/run-switcher-origin-tests.sh`。

## 第三步和其它照旧的

- 任何一步都能“跳过”（直接到授权页）；← → 翻页，回车是“继续”。
- 动画全是 Core Animation 图层，由系统的渲染进程播放，不占主线程；跟随浅色、深色（切换外观时当页重画）。窗口收起来、整个被挡住或在别的桌面上时循环动画停下，又看得见了从头播。
  看不见的这段时间里切外观、改辅助设置都不重建循环动画（点了“开始使用”后窗口一直留着，到退出才释放），只记下该播哪一步。
- “减少动态效果”打开时不动，摆出刘海说出 Mac 上那一下的那一帧；中途打开、关掉，当页重摆。
- 关窗口、点“开始使用”或“稍后再说”都算看过，下次启动不再自动弹出。
- 首次打开和菜单项从第一步开始。缺权限时的提醒（按快捷键没权限、刘海里点“需要权限”、换显示器时的恢复）
  直接打开到授权页，一打开就看得到授权行。窗口已经开着时不重建、不挪位置，只拿到最前面；缺权限的提醒才翻到授权页。
- 授权页的每秒刷新只在窗口看得见、停在这一页、还没全部授权时跑；授权行没变就不重画。

代码在 `prototype/App/Welcome.swift`（页面、页码点、三个选项、舞台和那段动画），窗口由 `Preferences.swift` 的
`showPermissionOnboarding(toPermissions:)` 打开（授权行沿用 `refreshOnboardingState()`，刷新开关在 `updateOnboardingRefresh()`）。
