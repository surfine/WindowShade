# 窗口的去与回：WindowShade 人机与多任务交互检讨（2026-10-29）

画面稿：[窗口的去与回](../../design-drafts/%E7%AA%97%E5%8F%A3%E7%9A%84%E5%8E%BB%E4%B8%8E%E5%9B%9E.html)（[线上](https://claude.ai/artifact/3WRxSztGw12xB4HgpEPm6t)）。这一轮**只调研、不改代码**。

## 结论

WindowShade 的方向是对的，底子也比多数同类好：投影落点、橡皮筋、刘海变形的速度衔接、落点小岛「画结果」、看一眼从格子原位长出来，都已经照《Designing Fluid Interfaces》做了。问题不在单个手势，而在**整体**：

1. **窗口「不在眼前」有十一种去处，回来有七个动词。**「看不见的每一扇窗都在刘海里」只兑现了一半：去处都进了那一排，回来的路却各走各的。
2. **大多数排布在手指动的时候不动，松手后瞬移。**跟手、改道、画结果这三条在刘海上做到了，在真窗口上大多没有。动画进行中的窗口不接任何手势。
3. **手势没有替身。**状态栏菜单没有半屏、铺满、撤销；新装没有快捷键；只能拖的功能没有 VoiceOver 路径。HIG 要求每个手势都有菜单或键盘的另一条路。
4. **和系统抢同一块地。**标题栏双击盖掉系统设置；拖到菜单栏在 macOS 15 起就是系统的「填满」，而落点小岛正长在菜单栏中央；10 月 28 日发布的触控 MacBook Pro 把 **Dynamic Island 搬上了 Mac**，刘海那块地有了系统的正式住户。
5. **同一个输入在不同表面意思不同**（捏、张、上、下、点、长按、拖到边），停留时间有十几种。

建议的主线是三件事：**一个「去与回」的空间模型、一个「代理先动、真窗后到」的跟手架构、一张手势文法表**。三件都不需要新令牌，全部落在 design-system 现有的 §2 十二条与 §4.6 弹簧里。

## 发现与建议

严重度：**高** = 伤信任或挡人用；**中** = 不顺、不一致；**低** = 文档或细节。

### F1 · 高 · 十一种去处，七个回来的动词

- **现在**：收起（卷帘条 / 缩略图）、收进刘海、侧拉收边、画中画藏起、卷轴屏外，加上系统的最小化、隐藏、别的桌面、全屏，再加「让开这个 App」。回来是展开 / 放回 / 还原 / 拉出 / 去 / 回到原处 / 拿回画中画，外加撤销。「让开」一个词又用在五处（Dock 隐藏、晃一晃、⌃⌘↑、侧拉、窗口浏览）。
- **原则**：803 空间一致（从哪去就从哪回）；copy-guide 第 2 条「一个东西只有一个名字」；direction.md「看不见的每一扇窗都在刘海里」。
- **建议**：一个「去与回」模型。离眼前三种距离——**原处**（卷帘条、缩略图）、**屏幕边**（侧拉、画中画、卷轴屏外）、**刘海**（收进刘海；系统的最小化、隐藏、别的桌面也在那一排里显示）。规则只有两条：① 每一种都出现在刘海那一排里；② 在那一排里点一下，一律「回到原处」，回来的路是去时的反方向。各处原有的动词（展开、放回、拉出）保留给它们自己的表面，那一排上只用一个词。「让开」只留给「让开这个 App」。**动词收敛要 Aaron 定**。

### F2 · 高 · 手指动的时候窗口不动

- **现在**：标题栏两指左右、角、张、捏，键盘与菜单排布，魔法平铺：过程中只有一条 HUD 进度条，松手后用辅助功能写两次外框，窗口瞬移（TrackpadGestures.swift:1913-1932、2044-2049）。甩一下要等落地才出 HUD；拖到窗口上并排明写「没有预览」（DropSplitRun.swift:5）。
- **原则**：803 跟手与持续反馈（Marcos 52:50）、顺着手势暗示（Chan 13:28）；design-system 原则 7「画结果，不画参数」。
- **建议：代理先动，真窗后到。** 第三方 App 不能 60 帧地移动别人的窗口（辅助功能写外框有往返延迟），所以由我们自己的一层代理跟手：有屏幕录制就用窗口截图，没有就用和窗口一样大的描边。代理 1:1 跟着手指，目标外框从当前外框长向终点（画结果）；松手按投影选终点，代理用同一根弹簧落定，**落定那一刻**才写真窗口外框，代理淡出。键盘和菜单触发同一个排布时走同一条动画。这和现在的「收起时截图飞进刘海」是同一个做法，只是推广到所有排布。

### F3 · 高 · 动画中的窗口不接手势

- **现在**：`isSettling` 为真时什么手势都不接（TrackpadGestures.swift:931-936）；飞进刘海的途中不能接住（Notch.swift:2246-2262），而总稿 §六写着「没松手前改方向，窗口跟手回来」。
- **原则**：803 随时打断、改道（Chan 06:51–11:33）；design-system §4.6「换目标时用当时的速度作初速度」。
- **建议**：有了 F2 的代理，打断就是改代理的目标：从代理当下的位置与速度出发（刘海变形已有的 `MorphRetarget` 同一套数学），真窗口只在最后一次落定时写。飞行中的截图可以被指针接住，变回拖动。

### F4 · 高 · 和系统抢同一块地

| 地方 | 系统 | WindowShade | 风险 |
| --- | --- | --- | --- |
| 标题栏双击 | 系统设置「双击标题栏」：缩放 / 最小化；触控 Mac「双击窗口铺满屏幕」 | 默认收起；吞掉第二下，第三下才交给系统；主线程判断超过 500 ms 就放行（EventTapCallback.swift:51、105-118）；按任何修饰键都跳过，文档只说 ⌥ | 时灵时不灵；和系统设置、触控手势打架 |
| 拖到菜单栏 | macOS 15 起「拖到菜单栏 = 填满桌面」；拖穿顶边打开调度中心（[Tile windows on Mac](https://support.apple.com/guide/mac-help/tile-app-windows-mchlef287e5d/mac)） | 落点小岛长在菜单栏中央的刘海下 | 代码里没找到对这两条的处理：可能两套预览同时出现。**要真机看** |
| 拖到左右边 / 四角 | 系统平铺 | 贴边 3 点内让给系统（TrackpadGestures.swift:1578-1584）；侧拉区内缩 8 点 | 已处理；启动台拖出图标的分区顺序相反（最外圈 = 侧拉，LaunchpadModel.swift:176-209） |
| 绿色按钮 | 悬停出 Move & Resize / Fill & Arrange / 全屏 | 卷帘条 0.55 s 后转给系统菜单；窗口浏览卡片的绿灯只进入全屏（10-29 定） | 一致性可接受 |
| 快捷键 | Fn-⌃-方向键是系统平铺；HIG「Avoid using the Control key as a modifier」 | 可录 ⌃⌘ 系列；README 写 ⌃⌘C（与「复制格式」同键），⌃⌘↑ 与 Finder 同键 | 默认不占是对的；录制时要提示冲突 |
| 调度中心里 ⌘W / ⌘Q | 系统发给前台 App | 全局 tap 改成「关指着的那扇」（MissionControlKeys.swift） | 改了系统键的意思，要讲清楚、默认关更稳 |
| 刘海 | 2026-10-28 发布的 MacBook Pro：「The Dynamic Island comes to the Mac, serving as the new home for Spotlight, Live Activities, and Siri AI」 | 刘海那一颗岛、实时活动、点一 / 二 / 三下 | **战略级**，见 F14 |

- **建议**：① 双击：首次打开 A1 页明说「双击标题栏改成收起窗口（原来是缩放）」，设置里给「照系统设置」一项；判断放到 tap 线程，不再有 500 ms 放行。② 落点小岛只在指针真的进入刘海那一格时出现，进入前让系统的填满预览照常；真机核对两套预览会不会叠。③ 启动台分区顺序与标题栏一致。④ 录快捷键时查系统快捷键冲突表。

### F5 · 高 · 手势没有替身

- **现在**：状态栏菜单只有收起、收进刘海、置顶、整理▸（MenuBarController.swift:118-150），没有半屏、铺满、上下半屏、四角、三分、撤销、晃一晃；新装零个全局快捷键（GlobalShortcuts.swift:162-190）；甩一下、晃一晃、落点小岛、分屏把手、拖到窗口上并排只能拖；分屏把手只有名字没有「调整」动作（SplitView.swift:668-670）；HUD 只在完成后播报。
- **原则**：HIG Gestures「Offer alternatives to gestures」；HIG Menu bar（每个命令都在菜单里，不能用时变灰而不是藏起来）；design-system V5「每个手势都有菜单或快捷键可以代替」。
- **建议**：状态栏菜单加「排布▸」子菜单列出全部排布与「撤销上次排布」，不适用时变灰；每项右边显示对应手势的小图示（教一次，见 F10）。快捷键照旧不预设（direction.md 定），但菜单项可以就地录。卷帘条、缩略图、侧拉把手、画中画、分屏把手补辅助功能自定义动作，分屏把手做成可调整（左右箭头按三分之一走）。

### F6 · 中 · 同一个输入，几种意思

- **现在**：捏 = 撤销 / 回主屏幕 / 画中画变小；张 = 魔法平铺 / 卷轴概览 / **全部收进刘海** / 画中画变大；上、下、点、长按也各有三四种意思（盘点 §3.4）。拖到屏幕边在标题栏、窗口浏览卡片、启动台、卷轴概览四处各算各的（§3.7）。
- **原则**：HIG Gestures（手势要有区别、可预期）；design-system 原则 4。
- **建议：一张手势文法表**——方向和大小在全 App 只有一种意思：**上 = 离开（收起、收进刘海）；下 = 回来（展开、放回）；捏 = 变小或撤销；张 = 变大或铺开；点 = 看或回到原处；长按 = 更多选项**。按这张表，刘海上「张开 = 全部收进刘海」与「张 = 铺开」相反，建议改成「张开 = 展开那一排」，全部收进刘海交给「上推」。屏幕边由外到里统一：最外 8 点让给系统平铺 → 侧拉带 → 四角画中画 → 顶部中央刘海。**刘海张开的意思要 Aaron 定**。

### F7 · 中 · 意图靠计时器

- **现在**：0.12（刘海悬停）、0.15、0.16、0.18、0.20（看一眼）、0.22（文档）、0.25（窗口浏览、侧拉 / 画中画待命）、0.3（刘海单双三击）、0.5、0.55（标题栏长按）……共享的只有两个令牌（Motion.swift:34-42）。
- **原则**：803「判断停顿看手指的加速度，不用计时器」，「停得越快、认得越快」；「避免双击造成的延迟」（Marcos 55:00）。
- **建议**：一个共用的「指针停稳」判定：速度降到阈值以下且减速度出现尖峰即算停，停得快认得快；计时只作上限。停留令牌收成三个（快 0.12、看一眼 0.20、按住 0.5），写进 §4.7。刘海单击按下就给反馈，抬起即执行，不等三击窗口（design-system §6-14 已写，代码未做）。

### F8 · 中 · 撤销太窄

- **现在**：每扇窗一格、只记外框，手动挪过就丢（TrackpadGestures.swift:943-952、2130-2147）；菜单里没有；收起、收进刘海、侧拉、画中画各有各的回来方式。
- **原则**：HIG Undo（多层、看得到结果）；803 轻量、可逆。
- **建议**：一份排布历史（本次开机内，最近若干步），覆盖所有「去」的动作；菜单项写出要撤的那一步（「撤销 左半屏」）；捏合仍是手势入口。

### F9 · 中 · 隐藏的模式与状态

- **现在**：魔法平铺放不下时自动接成卷轴，标题栏手势随之改意思，只剩 10 点的边条提示（MagicTilingRun.swift:143-185）；收进刘海的窗口完全看不见；侧拉、画中画把窗口停在屏幕外只留 4 / 2 点；晃一晃只记一扇；一个「标题栏手势」开关同时关掉甩一下、晃一晃、落点小岛、侧拉 / 画中画提示、拖到窗口上并排、长按菜单（TrackpadGestures.swift:219-249）；「之前常用」的答案悄悄改默认值（DockClickGuard.swift:93-100）。
- **建议**：进入卷轴时刘海说一次「放不下了，接成卷轴」；设置把「标题栏手势」拆成按手势族的几行，每行带演示；「之前常用」改了哪些默认值，在那一页写明。

### F10 · 中 · 可发现与教学

- **现在**：长按标题栏 0.55 s 的菜单、刘海张开、上下晃也算晃一晃，三处没有文档；手势教学停 2.6 s（Notch.swift:1555-1570 用 `Motion.Hold.alert`），与 §4.7 `coach.hold` 6.6 s 不符；动手练的只有双击收起。
- **原则**：803 教学段（Chan 57:38）：动画方向对齐手势、只解释会反复用的手势、互动原型胜过静态稿；HIG Gestures。
- **建议**：带演示的提示一律 6.6 s；「用菜单做三次 → 刘海演示一次对应手势」的教一次规则；把三个没文档的行为写进 gestures.md，或删掉。

### F11 · 中 · 减少动态效果与触感

- **现在**：减少动态效果时真窗口滑行仍在滑（Motion.swift:126-130，§4.6 写的是「原处淡出、目标处淡入」）；卷轴概览缩放没有 reduced 分支；触感只在 7 处。
- **建议**：真窗口在减少动态效果时改成代理的交叉淡化（有了 F2 才做得到）；每个吸附阈值都给 `.alignment`（分屏把手到三分之一、侧拉 / 画中画待命、卷轴列吸附）。

### F12 · 中 · 自制窗口外观

- **现在**：HIG Windows：「Avoid creating custom window UI… can make your app feel broken.」卷帘条就是在别人的窗口上画一条标题栏；窗口浏览的红黄绿用写死的 sRGB；macOS 27 起「every window on macOS now has the same tighter corner radius」（WWDC26 Keynote），Apple 没有公开读取窗口圆角的接口。
- **建议**：卷帘条、缩略图、画中画的圆角按系统版本取实测值（14/15、26、27 三档，照 feedback-verify-real-ui 在真机量）；卷帘条跟随窗口的 key / inactive 状态变化（HIG 三种窗口状态）；我们自己面板里的红黄绿改用系统按钮（`NSWindow.standardWindowButton`），不再自绘。

### F13 · 低 · Liquid Glass 细节

- 分层规则已写进 §4.2，基本合规。可补：WWDC25 219（Chan 段）说玻璃出现与消失是「materialize」而不是淡入淡出——AppKit 没有对应接口，保留现在的短淡入，记进对照账；macOS 27 新增透明度滑块与「显示边框」环境值，浮层要跟随。

### F14 · 高（战略）· 触控 Mac 与 Mac 上的 Dynamic Island

- **事实**（[新闻稿 2026-10-28](https://www.apple.com/newsroom/2026/10/apple-unveils-groundbreaking-macbook-pro-with-proled-xdr-display/)）：MacBook Pro 首次支持触控；「double-tap a window to fill the screen, or flick to tile it into place」；Dynamic Island 成为 Spotlight、实时活动与 Siri AI 的新家；11 月 6 日上市，随 macOS 27。Tech Talk「[Design for touch on Mac](https://developer.apple.com/videos/play/tech-talks/111456/)」的章节写着悬停交互要另行适配、系统手势另有规则、控件与触控目标要重新定尺寸；更细的说法（触控没有 mouseMoved、系统多指手势不开放给 App、触控目标 36 pt、macOS 27 起 Mac App 能直接建 Live Activities）来自调研代理，主模型没能拿到逐字稿核对，标为待核。旧的刘海机型会不会得到 Dynamic Island，Apple 没说。
- **影响**：① 「刘海是 Mac 的新入口」遇到系统的正式住户：在这些机型上我们的岛会和系统的岛抢同一个位置。② 触控没有悬停：看一眼、刘海悬停展开、窗口浏览在触控下都没有入口。③ 系统的「双击窗口铺满、轻撥贴齐」和标题栏双击收起、甩一下重叠。
- **建议**：先做一次真机调研（11 月 6 日后），再定策略。设计上的候选：有系统 Dynamic Island 的机型上，WindowShade 不在系统的岛上自己画；如果 macOS 27 确实开放 Mac App 发 Live Activities（待核），活动改走它进系统的岛；看一眼在触控下改成长按；标题栏双击在触控时让给系统。**要 Aaron 定**。
