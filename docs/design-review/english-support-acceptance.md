# WindowShade 2 英语支持

2026-10-11 用户要求英语支持，纳入当前完整设计接管目标。中文继续受 copy-guide 固定词汇约束；英文用自然、简短的动作与状态文案，统一一个概念一个名称。与动效共同验证，不能依赖中文字宽。

现有入口 `prototype/Core/WSL10n.swift`：锁保护的进程语言，默认中文；英文资源在 `Resources/Localization/en.lproj`，目前只由代码显式设为英语。`Localizable.xcstrings` 有206键，构建检查键/中英文/源句/占位符并编译资源；它证明这些键齐全，不证明全产品覆盖。部分设置已接入口，但隐私页等仍直接写中文。先沿用入口，不另造翻译系统。

交付应覆盖菜单、设置、欢迎流程、刘海与窗口浏览、错误/空状态/权限说明、提示与辅助功能标签；用户资料、文件名、系统提供的App名称保留原值。数字、日期、时间与复数按语义处理，字符串插值不能靠拼接中文语序。选择规则需要一致，并对打包后实际资源路径检查；未明确的默认语言与切换方式在最小贯通样件时具体定案。

先完成一条真实生产表面的中英文贯通，检验长英文、窄宽、浅深色、换内容及减少动态效果。后续批量迁移按表面交付，检查漏译与退回中文的真实原因；不把单纯206键check0写成“英语已支持”。当前QA合成资料不写用户持久语言偏好，不触发真实权限/网络/产品启动。

迁移边界：`WS2SettingsCopy.short` 以中文源句选短副标题，`symbol(for:)` 以显示名称查图标（Preferences与DuoSettingsWindow都调用）。若先翻译显示名称再套这两个表，会丢失现有缩写与图标选择。本地化必须在语义身份或已选文案之后进行，逐项保持原功能/图标，不用英文显示字符串作为路由身份。

先沿README既有英文用词：收起/展开用 Roll up / Unroll，置顶/取消置顶用 Pin / Unpin，看一眼用 Glance，窗口浏览用 Window browsing，卷帘条首次解释为 rolled-up window bar。名称定案时再对照全部菜单、设置与官网，避免另外造 Shade/Collapse/Fold 三套同义动作。隐私说明要译出读什么、为何、去哪里，权限名沿macOS官方英文，不扩充尚未验证的联网承诺。

实现注意：`WS2PrivacyData.rows/groups` 当前是静态let，若在初始化时按当前语言翻译，后来切换语言不会自然重建；需要明确启动时定语言/重新启动生效或显式重建策略。语言读取不得藏进所有静态copy初始化，避免QA在构造纯视图时意外读取标准偏好。当前只记录约束，尚未改变语言默认或持久偏好。

## 第27批定案（2026-10-12）

**首个贯通表面**：设置窗口外壳（标题、9 个侧栏分节名、副标题）+ 「卷帘」页全部行 + 「高级」页（语言开关的住处）。其余表面（菜单栏、其它设置页、欢迎、刘海、隐私页）按批迁移，未迁移处保持中文回退——是本批预期的中间态，不写成"英语已支持"。

**默认语言**：跟随系统。解析规则：系统首选语言列表第一项以小写 `zh` 开头（zh、zh-Hans、zh-Hant 都算）→ 中文，否则 → 英文（`InterfaceLanguagePreference.resolve`，纯函数、可注入）。用户在设置「高级 → 语言」可覆盖为 跟随系统 / 简体中文 / English；覆盖值存 `UserDefaults` 键 `WindowShade.InterfaceLanguage`，跟随系统 = 删键。语言只在两处读取：产品启动时 `applyAtLaunch()` 一次、设置里读当前选择；不藏在静态 copy 初始化里。

**切换方式**：立即生效（不重启），采用契约允许的显式重建策略。`InterfaceLanguagePreference.set` 写偏好 → 设 `WSL10n.language` → 主线程发 `didChangeNotification`；`DuoSettingsWindow` 收到后整窗重建（标题、副标题、侧栏、`pages` 缓存整批作废、当前页重装），状态菜单 `rebuildMenu()`。已显示的刘海句子不回溯改写，下一句起就是新语言（证据里如实记录）。「减少动态效果」下重建同样执行，只是不做淡入。

**语义身份路由**：迁移行改用 `WSL10n.setting(_:zh:) -> SettingsText`（key=目录键，zh=中文源句即稳定身份）；短副标题沿用 `WS2SettingsCopy.short` 以中文源句查表，英文走 `shortEn` 按 key 查表；图标仍按 zh 身份查 `symbol(for:)`。英文行长预算按渲染实测定（`WS2SettingsInfo.englishLineBudget = 34` 字符，词边界截断），不按中文字宽。

**本批验收**：中英 × 浅深 × 696/560pt 原生帧 + 同进程 zh→en→zh 重建帧（`SettingsShadeLanguagePreview` 夹具 + 消费者脚本）；`InterfaceLanguageSwitchTests`（真 DuoSettingsWindow 走通知重建，zh 往返文案集合一致）；全目录 371 键经 `xcstringstool` 编译后逐键走 `WSL10n` 解析实测；`build.sh --check` 全优化零漂移。QA 用合成假资料：只直接设 `WSL10n.language`/`englishBundle`，不写持久偏好、不触发权限弹窗、不读标准域。


**2026-10-12 用户追加定案（范围，覆盖"中间态"措辞）**：英语要**全量完全适配、不留手尾**。"未迁移表面保持中文回退"只允许作为某批证据里如实记录的事实，不是可停留的终点。完成标准（满足前不宣布"英语已支持"）：①所有用户可见字符串（含菜单、提示、错误/空状态、权限说明、更新提示、辅助功能标签与 tooltip）经 `WSL10n` 出当前语言，en 完整无汉字；②切换立即生效覆盖全部驻留界面（各自显式重建或声明"下一句起新语言"）；③语义身份路由不退化（不用英文显示串反查行为）；④打包资源路径实测，并给 `tests/check-localizable.py` 加"防漏网"扫描——用户可见代码里的中文字符串字面量命中不在白名单（语义身份表/QA 探针/内部键/系统权限名）即失败；⑤每表面验收按定案档位——2026-10-12 定为**默认轻量档**（见本文末尾两轮问答定案②），第27批自己那套全套夹具按原样收尾。剩余表面清单、粗扫行数与建议顺序见 [第27批交接 §9](../handoff/BATCH27-ENGLISH-HANDOFF-2026-10-12.md)。

**2026-10-12 两轮问答定案（补充，优先于本文其他旧口径）**：①**覆盖含官网与 README**（`site/` 中文首页 + `/en/`、`README.md`/`README_CN.md`），**随批滚动同步**——每批表面过门后同步 `site/scripts/content.mjs` 与 README 双份并跑 `cd site && npm run build && npm run check`（只本地构建检查，不部署）；②验收**全部轻量档**（纯测试 + 全目录检查 + 防漏网扫描 + 2–4 帧抽查 + 图片实看），仅"布局风险轻量档覆盖不了"才升档且证据写理由；③推进顺序按交接 §9 建议；④卡点 B 授权修生产布局，但**改前先把前后对比图给用户确认**；⑤英文大小写照 Apple 惯例（菜单 Title Case、设置行/说明 sentence case，已入 copy-guide）；⑥繁体本次不做，架构留余地（`resolve` 注脚标明扩展点）；⑦**证据过即收尾**，不设统一亲自验收环节，真机观感归发版流程。
