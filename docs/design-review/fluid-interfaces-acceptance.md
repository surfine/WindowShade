# 动效验收：Designing Fluid Interfaces

2026-10-11 用户追加要求：动画必须纳入设计，追求丝滑流畅和 Apple 官方水准。这个要求补充现有画面稿与动效方向，不撤销静态与行为目标。

依据：[Apple WWDC18 · Designing Fluid Interfaces](https://developer.apple.com/videos/play/wwdc2018/803/) 的即时响应、随时改向、空间一致、惯性与连续反馈；[Apple HIG · Motion](https://developer.apple.com/design/human-interface-guidelines/motion) 的有目的、可取消及减少动态效果。iPhone 的触摸案例用于提炼机制；WindowShade 是 macOS 指针与触控板产品，不能直接照搬触屏手势阈值。

| 场景 | 要看到的行为 | 当前证据与下一项检查 |
|---|---|---|
| 刘海展开途中收回、收回途中再展开 | 从当下形状继续，方向与速度自然衔接；旧退场不能随后清空新内容 | 第18批只验证隐藏宿主的路径和取消回调。下一批检查实际动画起点、速度符号与各轴连续性 |
| 同一活动更新数量或正文 | 原位变化，不整块消失重建，稳定内容不陪着闪 | 已有同身份更新逻辑证据；动态合成与视觉时序未验 |
| 不同内容接替、丰富内容退回紧凑 | 外框与内容节奏有层次，途中打断即时生效，无空白闪烁 | 有退场 generation 防旧回调；需当前帧序列与实际合成 |
| 窗口收起、展开、甩动或拖动后放手 | 跟手段直接映射；放手承接方向和惯性；返回路径清楚 | 下一批先核对真实路径入口及状态，不启动真实窗口操作 |
| 减少动态效果 | 不飞移、不过冲，反馈仍可理解；取消与终态完整 | 第18批仅逻辑与隐藏静态证据，不等于可见效果通过 |
| 性能与输入延迟 | 不漏响应；目标刷新率下无持续长帧，压力下记录真实卡顿 | 必须当前构建、真机、显示刷新率与帧时序。隐藏 cache、平均 FPS、工具退出0均不构成流畅度通过 |

现有 `prototype/App/Notch.swift` 的 `morphVelocity` 使用两次目标调用间的中点位移长度估算标量速度。长度不保留方向，也没有单独表示宽高变化速度；因此现有代码不足以证明“中途反向保留速度”。这是一项待动态探针核对的源代码发现，尚未宣称真机上已复现跳变。不得只调短 duration 或加大 bounce 来掩盖它。

验收要保存输入时刻、每次目标变更、动画/呈现层起点与终点、过期回调、实际帧间隔，以及与同一份源码绑定的画面。静态准确、连续行为正确、可见动势合适、真机性能合格分别记录；未取得的证据明确未验。“Apple 水准”是质量目标，不能由一组弹簧数值或固定60fps自行认证。

速度方向依据：[CASpringAnimation.initialVelocity](https://developer.apple.com/documentation/quartzcore/caspringanimation/initialvelocity)：负值表示背离弹簧附着点，正值表示朝向它。中途反向不能把所有速度都写成正数。仍需核对当前实际动画接口，不把纯公式检查当作呈现层速度实测。

第二项源代码风险：丰富内容退场时pendingExitMorph存下调用时presented，淡出0.10+gap0.04后performMorph仍传pending.presented。若旧形状在这段时间继续走，新动画会用早先位置接续；需要在真正开始收形状时重新取当前呈现位置，并以富内容中途收回场景核对。当前简单配置探针使用空内容、不触发该延迟，因此不能覆盖这一项。
