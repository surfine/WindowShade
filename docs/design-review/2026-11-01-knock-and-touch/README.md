## 一句話

**整個螢幕只有九個「位置」，手指、觸控板、鍵盤、敲機身都講同一種話：敲在哪裡，視窗就去哪裡。**
觸控 MacBook Pro 用手指點，其他 MacBook 用「敲上蓋」點（一種粗觸控）。兩邊學的是同一套肌肉記憶，換新機時不用重學。

## 核心：一套擺放文法，三種精度

### 九個位置

每個螢幕分成 3×3：四個角是四分之一，四條邊是半邊，正中是填滿。這就是 macOS 15 起系統貼齊的那幾個位置，也是 iPad 甩一下會落到的位置，不是新發明，只是**把它當成唯一的擺放語言**。

「收起」不是擺放，是另一條軸：沿用 10-29 檢討 F1 的「去與回」三種距離（原處、螢幕邊、刘海），規則不變——每一種都出現在刘海那一排，在那一排點一下就回到原處。

所以每個輸入方式只需要回答四件事：**擺到哪個位置、收起、放回、選哪一扇窗**。

| | 擺到位置 | 收起／放回 | 選一扇窗 | 精度 |
| --- | --- | --- | --- | --- |
| 指標 | 拖到邊／角（系統）；落點小島畫出九格 | 卷帘條、刘海那一排 | 直接點 | 1 pt |
| 觸控板 | 甩一下，按投影選位置（已有） | 兩指手勢（已有） | 窗口浏览 | 1 pt |
| 鍵盤 | 九宮快捷鍵（⌃⌥ + 數字鍵盤的排列） | 現有快捷鍵 | 窗口浏览 + 方向鍵 | 離散 |
| 手指（觸控 MBP） | **系統的**甩一下、點兩下填滿；我們不搶 | 卷帘條往下拉、刘海那一排點一下 | 點卡片 | 約 44 pt |
| **敲（其他 MacBook）** | **敲哪一格，最前面的窗就去哪一格** | 敲上蓋背面 = 全部收起／全部放回（待驗證） | 兩下式：敲一下叫出卡片，再敲卡片所在那一格 | 2×2 到 2×3 格 |

最後一列是新的。它讓沒有觸控螢幕的 MacBook，用和觸控 MacBook Pro 同一種「點在哪、去哪」的直覺操作視窗。

## 敲：Mac 的「輕點背面」

### 敲在哪裡

不建議敲螢幕玻璃中間（LidTap 自己也提醒用力按可能留壓痕，畫面也會晃）。建議的目標是**邊框和背面**：

| 位置 | 對應 | 物理上為什麼可能分得開（**推論，待量**） |
| --- | --- | --- |
| 上邊框左／中（刘海）／右 | 左上、填滿或收進刘海、右上 | 離轉軸最遠，力臂最長，扭轉訊號最強；左右靠繞垂直軸的扭轉方向分 |
| 左／右邊框中段 | 左半、右半 | 左右對稱軸的符號 |
| 下方靠轉軸的位置 | 不放動作 | 力臂最短，訊號最弱，最容易和打字混在一起 |
| **上蓋背面（蘋果標誌那面）** | 一個全域動作：全部收起／全部放回 | 沿螢幕法線的加速度方向和前面相反——**這是最需要先量的一條** |

背面那一下就是字面上的「Mac 的輕點背面」，和 iPhone 的 Back Tap 一樣只給一兩個高價值動作，不給一整排。

### 不確定就退一格

LidTap 對沒把握的敲擊直接丟掉。我們多一層：分類器給的是每一格的機率，把同一側的格子加起來，就是「左邊還是右邊」的機率。

- 格子和側邊都有把握 → 執行那一格（例如左上四分之一）。
- 只確定左右、不確定上下 → 退成左半邊。
- 連左右都不確定 → 不動作，只在畫面上閃一下「沒認出來」。

錯誤因此變成「稍微粗一點但方向對的動作」，再敲一下就能修正。這比整個拒絕更順，也比猜錯格子傷害小。擺放動作一律可以撤銷。

### 兩下式粗觸控：選一扇窗

要讓敲擊做到「某種程度的觸控」，就把畫面上的目標做得和敲擊的解析度一樣大：

1. 敲上邊框中間（刘海）一下 → 窗口浏览展開，最多 4（2×2）或 6（2×3）張卡片，**每張卡片剛好佔一格**。超過就分頁，敲背面翻頁（待驗證）。
2. 再敲卡片所在那一格 → 那扇窗到最前面。
3. 4 秒沒動作就自己收回。

畫面上只有幾個目標時，分類器只需要在這幾個目標之間選，空格的機率直接歸零，所以實際準確度會比 LidTap 在 2×2 全滿時的 95% 高（**推論，要量**）。這也是 AssistiveTouch 和 Switch Control 的老做法：目標少、目標大、分兩步選。對手部不便的人，它同時是一個新的輔助輸入。

### 回饋與閘門

- 敲下去約 170 ms 內，被認出的那一格先亮一下（Watch 的 Double Tap 也是先高亮被觸發的控制項），再執行；不支援的畫面，那一格輕輕抖一下。
- 閘門照 LidTap 的做法，再加上我們有的資訊：最近 0.3 s 有打字、點擊、捲動就忽略；上蓋角度在動就忽略；闔蓋、接外接螢幕當主螢幕時不聽；全螢幕播放影片時不聽。
- 校準不另開一個兩分鐘的畫面，放進 1.0.18 的開機導覽：「敲左上角試試」就是在收集第一批樣本。之後每次執行完 5 秒內沒撤銷，就算一筆正確樣本；撤銷了就算錯誤樣本，模型自己慢慢變準。

## 融合 iPad 和 Mac 的多工：各拿什麼

| 從 iPad 拿 | 從 Mac 留 |
| --- | --- |
| 位置少而且叫得出名字（九格） | 視窗可以自由重疊，不強迫每扇窗都貼齊 |
| 直接對視窗本身做手勢（甩一下就貼齊） | 精確指標、選單、鍵盤、多螢幕 |
| Slide Over：一扇窗暫時從邊上滑出來（我們的侧拉已經是這個） | 刘海那一排：所有看不見的窗都有一個地方可回 |
| 卡片式的 App 切換，目標大 | 菜單和快捷鍵當每個手勢的替代路徑（10-29 檢討 F 系列的「手勢沒有替身」） |
| 預設只做一件事，進階才給重新指定 | Mac 使用者要的可自訂 |

一句話：**擺放用 iPad 的格子，內容保留 Mac 的自由。** 重疊的窗照樣重疊，但只要你想整理，九個位置和「去與回」兩條規則就夠了，而且每一種輸入都一樣。

## 觸控 MacBook Pro 上要準備的

決定 #18 照舊：系統的 Dynamic Island、點兩下填滿、甩一下貼齊都讓給系統。我們要補的是：

1. **不能靠懸停。** 觸控沒有懸停：看一眼、刘海的懸停預覽在手指下要有替身（長按，對齊 #33 的長按展開）。
2. **目標夠大。** 卷帘條、刘海那一排的格子、窗口浏览的卡片都要量過手指點得中（Mac 的實際尺寸 11-06 後真機量，不先拍腦袋定）。
3. **同一套文法。** 卷帘條往下拉＝展開；刘海那一排點一下＝回到原處；從螢幕邊拉出侧拉。和舊 MacBook 上「敲」的位置意思一致。
4. **新機也有感測器嗎？** PROLED 機型有沒有同一顆 SPU 動作感測器還不知道。有的話，背面那一下在觸控機上也能用。**上市後 `ioreg` 查一下。**

## 耗電：最大的風險

本輪在 M5 Air 上量（同時開加速度計和陀螺儀、回呼裡只計數、每檔跑 5 秒）：

| 回報間隔 | 每秒筆數（加速度＋陀螺） | 這個行程的 CPU（一顆核心的百分比） |
| --- | --- | --- |
| 1000 µs | 806 + 805 | 2.7%–5.1%（兩次量差很多） |
| 2500 µs | 403 + 402 | 3.8% |
| 5000 µs | 201 + 201 | 2.3% |

這還沒算特徵抽取和分類。降低取樣率能省的不多，大部分成本是固定的。和合盖效果那次的教訓一樣（加速度計曾是「解鎖空閒時最大的常駐開銷」），**常駐聽敲擊不能預設開**。可以試的方向：

- 只開加速度計、不開陀螺儀當觸發，觸發後再開陀螺儀抓那 200 ms（要量：陀螺儀從醒來到有資料要多久）。
- 一次處理一批回報，而不是每筆一次回呼。
- 只在「使用者正在用內建螢幕、上蓋開著、沒在打字」時聽。
- 看 SPU 或感測器本身有沒有硬體敲擊中斷可以用（Bosch 同系列晶片有這種功能，但 Apple 有沒有開出來完全不知道）。

完成標準先定成：**常駐時一顆核心的 1% 以下**，達不到就只當實驗開關。
