### 2. 两个架构的发布包

```sh
cd prototype
./build.sh --release
WINDOWSHADE_ARCH=x86_64 ./build.sh --release
cd .. && bash scripts/notarize.sh .build/release/WindowShade.app
bash scripts/notarize.sh .build/release-intel/WindowShade.app
```

打包（名字里**不带** build 号，和以前一样）：

```sh
cd prototype
VERSION=$(/usr/libexec/PlistBuddy -c "Print CFBundleShortVersionString" Info.plist)   # 1.0.21
ditto -c -k --sequesterRsrc --keepParent ../.build/release/WindowShade.app "dist/WindowShade-v${VERSION}.zip"
(cd dist && shasum -a 256 "WindowShade-v${VERSION}.zip" > "WindowShade-v${VERSION}.zip.sha256")
ditto -c -k --sequesterRsrc --keepParent ../.build/release-intel/WindowShade.app "dist/WindowShade-v${VERSION}-intel.zip"
(cd dist && shasum -a 256 "WindowShade-v${VERSION}-intel.zip" > "WindowShade-v${VERSION}-intel.zip.sha256")
cd .. && bash scripts/make-dmg.sh
```

注意：zip 名字和 `v1.0.21` 那次**完全一样**。上传到新 tag `v1.0.21.1` 之下，名字相同不会覆盖旧包（tag 不同）。
但 `prototype/dist/` 里旧的同名 zip 会先被覆盖，所以打包前先确认 `.build/release/WindowShade.app` 里是
`CFBundleVersion=20261110.01`（`/usr/libexec/PlistBuddy -c "Print CFBundleVersion" ../.build/release/WindowShade.app/Contents/Info.plist`）。

### 3. 清单（两份，都要先加条目、再签名）

`sign_update` 在 `.build/sparkle/bin/sign_update`。两份清单各加一条，保留最近三条：

```sh
.build/sparkle/bin/sign_update prototype/dist/WindowShade-v1.0.21.zip
.build/sparkle/bin/sign_update prototype/dist/WindowShade-v1.0.21-intel.zip
```

条目要点（写法照 `site/public/appcast.xml` 现有那一条）：

- `<sparkle:version>20261110.01</sparkle:version>`，`<sparkle:shortVersionString>1.0.21</sparkle:shortVersionString>`。
- `<pubDate>` 用发布那一刻的 RFC 822 时间。
- `<link>` 指向 `https://github.com/surfine/WindowShade/releases/tag/v1.0.21.1`。
- `<enclosure url>` 用 `.../download/v1.0.21.1/WindowShade-v1.0.21.zip`（新 tag）。
- `length` 是 zip 的实际字节数，`sparkle:edSignature` 是 `sign_update` 的输出。
- 描述取 `docs/releases/v1.0.21.1.md` 的「一句话摘要」。
- 旧的两条（build 21、20）**保留**，否则用过 beta 频道的人降不回来。
- **这次直接去掉 `<sparkle:channel>beta</sparkle:channel>`**：Aaron 已经用着 beta 频道，这个包就是正式发的那一个。
- 改完两份都要重新签名（文件末尾的 `sparkle-signatures` 块），再 `curl` 线上确认。
