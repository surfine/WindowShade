# 1.0.18 发布关 runbook

用途：把 1.0.18 从「候选源码」推到「可发布」。门内全过 → 走文末「发布日流程」；任何一项 inconclusive / fail → 停，按本项目惯例记档。格式沿用 [1.0.17 runbook](v1.0.17-release-gate.md)。

**这一版特殊在四处**：

1. **同一张 Developer ID 证书**（Team `DQ45KFVHJ8`，1.0.17 起不再变）。发布关第 3 步回到「DR 与上一版逐字相同」，**不带 `--cert-change`**。1.0.17 用户一键更新。
2. **默认值翻开的十三个键**（[v1.0.18-defaults.md](v1.0.18-defaults.md)，Aaron 拍板 2026-10-17）。验收因此更重：默认开了更要跑（刘海 20、home 3、habits 7），OOBE 要真的走一遍新装与升级。
3. **首次下载改用 DMG**（`scripts/make-dmg.sh`）：Release 页挂 DMG，Sparkle 更新照旧用 zip（docs/update.md）。release-gate 多一步 `--dmg`。
4. **OOBE 重做**（A1／A2／T／U1／N1）＋设置八页讲解带＋设置侧栏搜索。真机路径见 Phase 1。

## Phase 0 · 建发布候选并过包级门禁（约 25 分钟）

先决条件：钥匙串里有 Developer ID Application 证书（Team `DQ45KFVHJ8`），notarytool profile `windowshade-notary` 已存（DEVELOPMENT.md 第 3 步）。

```sh
git worktree add /tmp/ws-b18 <要发布的提交>        # 标签=源码=包：必须是已提交的干净检出
cd /tmp/ws-b18
bash scripts/check-release-version.sh                # 必须 PASS（build 18 > appcast 已发过的 17）
cd prototype
./build.sh --stage                                   # 开发证书隔离构建，先验：更新器接齐、--self-check 过
./build.sh --release                                 # Developer ID 签名，产物 ../.build/release/WindowShade.app
cd .. && bash scripts/notarize.sh                    # 送公证、钉票据、Gatekeeper 核
scripts/make-dmg.sh                                  # 首次安装 DMG（先做排版模板，见下）
cd prototype && mkdir -p dist
VERSION=$(/usr/libexec/PlistBuddy -c "Print CFBundleShortVersionString" Info.plist)
ditto -c -k --sequesterRsrc --keepParent ../.build/release/WindowShade.app "dist/WindowShade-v${VERSION}.zip"
(cd dist && shasum -a 256 "WindowShade-v${VERSION}.zip" > "WindowShade-v${VERSION}.zip.sha256")
```

**DMG 排版模板（一次性）**：`assets/dmg/DS_Store` 还没提交。在能开 Finder 的 Mac 上跑 `scripts/make-dmg.sh --capture-template`（短暂弹 Finder 排版后把 DS_Store 提交）；没有模板也会做出能用的 DMG，只是没排版。无人值守流程里放不进 Finder 自动化授权，所以这步在有屏幕的会话里做。

### 包级门禁（同一证书的一版，**不带 `--cert-change`**）

先把草稿条目插进 `site/public/appcast.xml`（放在 1.0.17 条目前）并填完 TODO（url、`length` = zip 字节数、`sparkle:edSignature` 用 `sign_update` 签 zip；重新签整份清单），再跑：

```sh
bash scripts/release-gate.sh prototype/dist/WindowShade-v1.0.18.zip --dmg prototype/dist/WindowShade-v1.0.18.dmg
```

与 1.0.17 的差别：

| 步骤 | 1.0.17 | 1.0.18 |
| --- | --- | --- |
| 3 DR | `--cert-change DQ45KFVHJ8` | **回到与上一版（1.0.17 zip）逐字相同** |
| 7c | informationalUpdate | 仍有：`belowVersion=17`（1.0.16 及以前只提示手动下载） |
| 9 | 状态兼容 | 同做：1.0.17 的 `--self-check --read-state` 读得懂这一版的状态 |
| 12 | 无 | **`--dmg`**：DMG 已签名公证钉票据、挂载后恰好一个 .app 加一个指向 /Applications 的链接、build 号与 zip 一致 |

手动核对并记证据：`spctl -a -vv -t exec <App>` 是 `source=Notarized Developer ID`；`xcrun stapler validate <App>` 通过。

## Phase 1 · 核心窗口路径（真机，约 20 分钟）

同 [1.0.17 runbook](v1.0.17-release-gate.md) Phase 1 的基础四样（单文档收起／展开、同 App 两文档、菜单栏路径、浅色与深色）。**这一版加验**：

1. **默认值翻开**：装好后不动任何开关——刘海能收窗口、实时活动出得来、文件架能拖、再点 Dock 图标让开、停在 Dock 图标看得到窗口。
2. **OOBE 三条路各走一遍**：新装（A1 → A2 → T，A1 里真的双击练习窗口）；从 1.0.17 升级（一键更新装完 → N1「这一版新开了这几样」，只列真变了的）；从 1.0.16 手动装（U1「再打开一次这两项」→ N1）。
3. **讲解带**：八个设置页各指两行，演的东西和行说的对得上；开关关着演「关着」；「减少动态效果」开着重摆。
4. **设置侧栏搜索**：打「刘海」「liuhai」「窗口」各搜一次，跳转正确。
5. **Dock 预览卡红黄绿**：关窗、最小化、全屏各点一次；窗口浏览面板里 ⌘W／⌘M／⌃⌘F。
6. 启动不再弹系统授权框（全新装第一次启动只有欢迎窗口）。

每个动作：截图＋备注时间；说不清就记 inconclusive，不许猜成 PASS。能机器做的（探针、computer-use、VM）都先机器做，剩下的列成给 Aaron 的十分钟清单（`v1.0.18-aaron-checklist.md`，随候选包一起出）。

## 发布日流程（门过后；Aaron 点头、Aaron 按发布）

1. 冻结 zip＋`.sha256`＋DMG＋证据目录。
2. `sign_update` 签 zip，把[草稿条目](appcast-item-1.0.18.xml)插进 appcast 并填 url／length／`edSignature`、改 `pubDate`，**重新签整份清单**；`check-release-version.sh` 此时应失败（build 18 已在清单里）——预期。
3. 站点：`cd site && npm run build && npm run check`；**先上传包、后发清单**。
4. `git tag v1.0.18` → `gh release create v1.0.18 … --notes-file docs/releases/v1.0.18.md` → 上传 zip、`.sha256` 与 DMG → 下载回来核对哈希。
5. 下载大小数字：README 三份、官网 `site/scripts/content.mjs`（中英两处）与 `zh-hant.json` 的 1.0.17 数字改成 1.0.18 实际值；下载口径如有「ZIP」措辞的地方补 DMG 一句。
6. `docs/releases/v1.0.18.md` 去掉草稿说明；`docs/releases/README.md` 的「已发布」表补一行。
7. Homebrew cask 若仍分发 zip：按 DEVELOPMENT.md 更新 cask 一节。
