# WindowShade 1.0.22（build 20261115.01）

已发布（2026-11-16）。build 沿用日期制 `20261115.01`。

## 中文

### 一句话摘要（appcast 用）

刘海边界的几处毛病一起修了：真刘海两侧放不下时不再往下长一截挡住窗口内容，外接屏放不下时退成系统灵动岛那样的最小圆，甩进刘海的窗口拿出来回到拖动起点。台前调度下的三处边界也一并收进来：在别的桌面收起不把你带走、不能最小化的窗口换到另一侧停靠、副屏卷帘条被系统挪过仍回到原处。收起捷径和标题栏双击不再误伤桌宠、放大的影片窗这类浮动窗口；设置里四个永远开不起来的开关拿掉了，1.0.22 起新装的带上官网列的那几组快捷键。另有一个默认关的实验：接着外接屏时，指针离开内屏就把它遮住。

### 这一版改了什么

刘海与岛：

- **真刘海两侧放不下时不再往下长下巴。** 刘海上放着收起的窗口、正在播放或计时器，而左右任一侧的菜单栏空位不到 26 点时，以前岛会往下多长 8 点，比菜单栏低，像门牙挡住窗口内容；现在停在刘海本身。个数照旧在菜单栏图标旁边，正在播放在系统控制中心里。
- **外接屏放不下时退成官方最小圆。** 以前画成 72×12 的扁条，还把标题、进度环塞进 12 点高里。现在按 HIG 画 36.67 的最小圆，里面只画点：一扇窗一个，最多五个。没有菜单栏的屏没有东西可撞，直接画胶囊。
- **甩进刘海的窗口，拿出来回到拖动起点。** 上一包（build `20261110.01`）的一个回归：防台前调度偷挪卷帘条的那条守卫，把刘海自己挪回起点的动作也当成了偷挪。
- **标题栏目标统一成一条规则。** 非一般 App（桌宠、放大的影片窗、浮动的设置面板）的非第 0 层或非标准窗口，不再被当成标题栏目标：双击缩放、触控板标题栏手势、收起捷径三条路都走同一个纯判定，不再误伤，也不会把整个辅助 App 藏起来。一般 App 的浮窗行为不变。

离开就锁：

- **蓝牙授权能向系统要了。** 以前只查状态不申请：从没决定过的用户在系统设置的蓝牙隐私列表里找不到 WindowShade，离开就锁打不开。现在那一列给「允许蓝牙…」，按下才向系统要授权；拒绝过的直接打开系统设置那一页。

设置与开箱：

- **1.0.22 起新装的带快捷键。** ⌃⌘C、⌃⌘0、⌃⌘P、⌃⌘G、四个方向键与 ⌃⌘1…9，和官网列的一致。从 1.0.16 到 1.0.21 之间装上的保持不变，不会升级后突然多占一组键。
- **拿掉四个永远开不起来的开关**：平滑滚动、鼠标滚动方向、三指轻点、四指轻点。事件来源还确认不了，开关只会停在「还没确认」。
- **写死的简体界面文字接进本地化**（12 处）。英文与繁体界面不再夹着简体中文。

修好的小毛病：

- 刘海关着时，音量／亮度键不再被吞掉却没有任何反应。
- 画面源低于 15fps 时，镜像层收不到帧。
- 权限引导卡的通知登记到了错的通知中心。
- 番茄钟休息的呼吸动画每秒重绘时被掐断重来。
- 文件架拖出标记的写入和判定用了两个不同的字符串。
- 终端「看一眼」的说明条在没有 layer 时被画上圆角和底色。
- 开关关掉后跟着停：手势总开关或输入增强关掉时拆掉用力按监听；分屏关掉时收起把手；刘海关掉时音乐轮询、正在播放流、下载与拷贝监看一起暂停。

实验（默认关）：

- **指针离开内屏就遮住。** 设置 → 高级 → 实验。接着外接屏时，指针移到别的屏，MacBook 内屏盖上不透明黑色，指针回来揭开。事件驱动、不需要任何权限；只有一块屏、内屏镜像、合盖时不遮。它不替代系统锁屏——离开电脑仍然走系统锁屏。

### 上一包的内容（原 build `20261110.01`）

这一版把 2026-11-10 那个包的内容一并收进来。它原来单独挂在 tag `v1.0.21.1` 下，已随这一版撤下，只留这一份说明。

台前调度与多桌面：

- **在别的桌面收起，不带走你。** 窗口在另一张桌面时收起不再借「隐藏整个 App」（那会让系统换桌面找继承人）；兜底回位守的是「收起那一刻你在看的那张桌面」。
- **当前桌面看不到卷帘条时，会说一句它去了哪。** 例如「已收起到桌面 2」，编号和调度中心一致。刘海开着时出在刘海上，刘海不在时退回菜单栏标题。
- **不能最小化的窗口，收起时换到另一侧。** 台前调度只看守左侧侧条边缘，缩进侧条失败时改停到右边缘，系统不会把它拽回来。
- **副屏上被系统挪过的卷帘条，展开回到原处。** 台前调度会把贴边的辅助窗往里挪（实测 164 点）；系统自己的挪动不再被当成你拖动，展开不再横跳。
- **卡住的 App：** 窗口服务器已经证明停到屏外、或透明度落到 0.05 以下，这次收起算做成，不再弹「收起状态未确认」。其余情况仍保留恢复入口。

分屏：

- **认得出系统的左右、上下半屏。** 系统自己留的那道空档通常 8–10 点，以前 6 点容差认不出来，把手不出现；现在认到 12 点，缝落在空档正中。

手感与外观：

- 提示浮窗终点图标、文件架个数的弹一下，起始缩放从 1.22 / 1.28 收到 1.12；阻尼比不变，仍在 Mac 的上限内。
- 拖窗口到刘海时，落点小岛接上当时的拖动速度，位置和速度都连续。
- 卷轴概览的玻璃不再叠一层：内容放进玻璃里。
- 侧拉那一圈边框和它的挖空蒙版改成连续曲率角，和系统窗口一样。
- 次要字统一到 11 点、次要白统一到 0.6；教学台面圆角与岛同心。
- 菜单栏 OSD 那个位置的提示浮窗，增强对比度时边线 1 点、用 `labelColor`。

权限：

- 打开「隐私与安全性」里还没允许的那一栏时，清单下多一张可拖的卡片：写清在清单里打开哪一项，没有的话把 WindowShade 拖进去。允许了就自己收起。

### 需要 macOS 15 或更新版本。

### 已知

- Intel 实验版仍是 Rosetta 冒烟加交叉编译，没有真 Intel Mac 实测。
- 副屏上展开一扇收在别的桌面的窗口时，系统可能把那块屏切到窗口所在的桌面（探针允许两种结局）。这是系统行为，不是这一版引入的。
- 内屏遮罩实验目前只在 M5 加 Studio Display 上真机看过；多屏与镜像的组合没有逐一验过。
- 收起条绿灯上的悬停转发只能人工确认，没有自动探针。

## English

### Summary (for appcast)

The notch's edges are fixed in one pass: when neither side has room on a real notch it no longer grows a chin over your window content, an external display falls back to the system island's minimum circle, and a window thrown into the notch comes back to where you started dragging. Roll-up and title-bar double-click no longer grab floating windows from non-regular apps, four settings switches that never worked are gone, and new setups from 1.0.22 carry the shortcuts the site lists. There is one new experiment, off by default: with an external display attached, the built-in screen turns black when the pointer leaves it.

### What changed

Notch and island:

- When a real notch has something on it and either side has less than 26 points of menu bar left, the island used to grow 8 points downwards, below the menu bar, over the window content. It now stays the notch itself.
- An external display with no room used to draw a 72×12 bar with titles and progress rings crammed into 12 points. It now uses the HIG minimum circle, 36.67 points, holding only dots, one per window up to five. A display without a menu bar gets the capsule directly.
- A window thrown into the notch and taken out again returns to where the drag started, which 1.0.21.1 broke while guarding against Stage Manager nudging strips.
- One rule now decides what counts as a title-bar target. Non-regular apps' windows that are not layer 0 or not standard (pets, enlarged video windows, floating settings panels) are no longer targets for double-click zoom, title-bar trackpad gestures or the roll-up shortcut. Regular apps' floating windows behave as before.

Presence lock:

- The Bluetooth row can now ask for permission instead of only reading it. A user who never decided could not find WindowShade in the Bluetooth privacy list, so presence lock never turned on. The row offers Allow Bluetooth and asks the system only when pressed; a denied user is sent to the right pane in System Settings.

Settings and setup:

- New setups from 1.0.22 carry ⌃⌘C, ⌃⌘0, ⌃⌘P, ⌃⌘G, the four arrows and ⌃⌘1…9, matching what the site lists. Setups first installed with 1.0.16 to 1.0.21 keep none of them, so an update does not suddenly claim a set of keys.
- Four switches that never worked are gone: smooth scrolling, natural scrolling direction, three-finger tap and four-finger tap. Their event sources cannot be confirmed, so the switch only ever sat at "not confirmed yet".
- Twelve hardcoded Simplified Chinese strings went through the localization layer; English and Traditional Chinese interfaces no longer mix in Simplified.

Smaller fixes:

- Volume and brightness keys are no longer swallowed with no effect when the notch is off.
- The mirror layer now receives frames from sources below 15 fps.
- The permission card registered its notification in the wrong notification center.
- The pomodoro rest breathing animation no longer restarts when it is redrawn every second.
- The file shelf's drag-out marker wrote and read two different strings.
- The terminal glance caption no longer gets a corner radius and background when there is no layer.
- Turning things off actually stops them: the pressure monitor when gestures or input enhancements are off, the split handles when split view is off, and music polling, now-playing and download/copy watching when the notch is off.

Experiment (off by default):

- With an external display attached, the built-in screen turns solid black when the pointer moves to another display and uncovers when it comes back. Driven by pointer and display-configuration events, with no permission needed; it does not cover when there is only one display, when the built-in screen is mirrored, or when the lid is closed. It is not a replacement for the system lock screen.

### From the previous package (build `20261110.01`)

This release folds in the 2026-11-10 package that used to sit under its own tag `v1.0.21.1`; that release is gone, and this note is the only copy.

Stage Manager and desktops:

- Rolling up a window on another desktop no longer hides the whole app (which made macOS switch spaces to find an heir). The fallback return guard protects the desktop you were looking at, not the window's own.
- When no strip is visible on the current desktop, it says where the window went, using Mission Control's own numbering.
- A window that refuses to minimize flips to the other edge, where Stage Manager does not guard.
- A strip nudged inwards by the system on a second display expands back to where the window was folded.
- A stalled app's roll-up counts as done when WindowServer proves the window is parked off screen or fully transparent; everything else still keeps a recovery entry.

Split view:

- The divider now recognizes the system's left/right and top/bottom halves, whose own gutter is wider than the previous 6-point tolerance.

Feel and appearance:

- Smaller bounce on the HUD endpoint and the file-shelf count (1.12 instead of 1.22 / 1.28), same damping.
- The drop island carries the drag velocity.
- The scroll-strip glass no longer has a second layer behind it.
- The Slide Over ring uses the same continuous corners as system windows.
- Secondary type unified at 11 pt, secondary white at 0.6; the teaching stage radius is concentric with the island.
- The menu bar HUD keeps a 1-point border in `labelColor` under increased contrast.

Permissions:

- Opening a privacy pane that is not yet allowed shows a draggable card under the list, saying which row to turn on and letting you drag the app in if it is missing.

### Requires macOS 15 or later.

### Known

- The Intel build is still a Rosetta smoke test plus a cross-compile; no real Intel Mac has run it.
- Expanding a window that lives on another desktop can make the system switch that display to the window's desktop. That is system behavior, not new in this release.
- The built-in screen curtain has only been checked on an M5 with a Studio Display on real hardware; multi-display and mirrored combinations are not covered yet.
- The hover-forwarding on the strip's green light has no automated probe; it needs a human look.
