# 1.0.18 默认值总账

> 2026-10-17。依据 Aaron 拍板（见 [1.0.18 计划](v1.0.18-plan.md) 第 1 条、设计稿“首次打开 1.0.17 小样”的决定记录）：**刘海主功能、刘海实时活动、Dock 悬停查看窗口、文件架和再点 Dock 让开，1.0.18 起默认开；新装和没动过这些开关的老用户都开。**
> 这一页接 [1.0.16 默认值总账](v1.0.16-defaults.md)；1.0.16 那页的 B、C 两节在 1.0.18 不变。

## 纪律改了一句

1.0.16 起是“只有真机验过的才默认开”；1.0.18 起是“**验过的，或 Aaron 拍板的**，才默认开”。[`ReleaseDefaults.Entry`](../../prototype/Core/ReleaseDefaults.swift) 多了一个字段：

```swift
Entry(key: "Notch.enabled", designed: true, deviceVerified: false, ownerDecided: true),
// release = designed && (deviceVerified || ownerDecided)
```

- `deviceVerified` 照实记：这一批都没在真机上验过，仍是 `false`。账上看得出是拍板开的，不是验过开的。
- 拍板改的是默认值，不是验收：刘海 20、home 3、habits 7 探针照样要在真机上跑，默认开了更要跑。
- 不分新装和升级：显式存过值的照旧（他自己开过或关过的不动），没存过的新老一律按这张表。升级上来的人用“这一版新开了这几样”（N1）一页告诉他一次，只列对他真变了的（[`WhatsNew1018Changes`](../../prototype/Core/WhatsNew1018Changes.swift)）。
- 改一行后跑 `bash tests/run-release-defaults-tests.sh` 和 `bash tests/run-whats-new-1018-tests.sh`。

## 读设置的出口

和 1.0.16 一样都走 `ReleaseDefaults.value(_:)`；1.0.18 只多了 `WindowBrowserSettings.dockEnabled`：没设过时读总账（原来是 `bool(forKey:)`，没设过就是关）。

## N1 的规则

13 个键里，没显式存过值（存的不是 Bool 也算没存过）、1.0.17 发出去是关、1.0.18 是开的，才算“真变了”。分三组：刘海（10 个刘海键）、Dock 悬停查看窗口、文件架和 Dock 图标（`FileShelf.enabled` + `Dock.clickToHide`）。他自己关过刘海（`Notch.enabled` 显式存了关），刘海那一行和文件架都不算；三组都没变就不弹。只弹一次（`WhatsNewShown.1.0.18`）。

启动时走哪条路（[`LaunchOnboardingRoute`](../../prototype/Core/WhatsNew1018Changes.swift)）：

| 情形 | 弹什么 |
| --- | --- |
| 新装（这次启动之前没有安装记录） | 欢迎窗口 A1；不看 U1、N1，直接记成看过 |
| 升级上来、缺辅助功能、这一版没看过 U1 | “再打开一次这两项”（U1），关掉后接 N1（有变化、没看过时） |
| 升级上来、授权都在、有变化、没看过 N1 | N1 |
| 升级上来、还没看完欢迎窗口 | 照旧从第一页看起 |

“升级上来”认的是这次启动之前就有 `InstallHistory`（1.0.16 起第一次启动就存）或认出是 1.0.15 及以前的老安装，不靠更新日志，所以手动下载装上来的也认得出。更新日志那条路（装好新版本后授权没了）落到同一个 U1；同一次启动里已经弹过就不重弹。
