## 容器字节不可复现（发布关发现，已核实）

同一次 `--stage`、同一 app 树，两次 `ditto -c -k --sequesterRsrc --keepParent` 产出**容器字节不同**（`47930319…` 与 `f28c9677…`，大小同为 9,858,449）。解包后 `WindowShade.app` **文件清单与逐文件 sha256 完全一致**（`/tmp/tree-a.txt` vs `/tmp/tree-b.txt` diff 为空），差异只在 zip 容器层的元数据（时间戳）。

处置：**以最终上传的那一份为准**（`f28c9677…`，包级门禁在同一份上重跑、全 PASS；VM 内的 Phase 1–3 验收跑在容器 `47930319…` 的 app 树上，与发布件 app 树逐文件相同）。结论：*验收内容 == 发布内容*；但"zip 哈希"不是可复现的身份，"app 树逐文件哈希"才是。以后发版把这两件事分开记。

### 勘误 1（重要，先前结论更正）

[phase123-results.md](phase123-results.md) 1.3 曾写"**同 App 两文档：历史雷未复现**"。复核既有帧后确认**该判读不成立**：当时那张"doc-B 卷帘条"画面里同时有打开中的**改名浮层**（Name/Tags/Where），而 doc-B 的标题条带交通灯完整可见——无法与"窗口未折叠、双击只是弹了浮层"区分，属**证据不足**。0-B 轮的直测（折叠后窗口离屏、原位置无条、`on_screen=false`）与历史缺陷描述（"菜单计数增加但卷帘条没有出现"）**形态一致**。

这不是断言"仍有缺陷"：策略 `hiddenIfSingleWindowElseMinimized` 表明多窗口走"最小化"分支可能是**有意设计**（最小化窗口由刘海排列出、条目文案"还原"）。但**本次工具条件下无法驱动刘海排的显示**，因此判读保持 inconclusive，并把"两文档收起后的可见/可恢复入口"列入用户真机清单（第 1 条）。

### 过程勘误 2

`#39` 首次测试（run 184702 b7–b9）用了 `"modifier":"option"`（字符串），且未加 `delivery_mode:"foreground"`——驱动 schema 要求 `modifier` 为**数组**，且**带修饰键的点击必须 foreground**，否则 macOS 观察不到物理修饰键状态。该次为**无效测试**（结论"仍然收起"不作数），已按正确参数重测（c3–c6，pass）。原始事件全部保留。

4. 设置 → 高级 → 界面语言切 English → 确认设置界面立刻变英文且不跳页。
5. 动画手感（收起/展开的"跟手"与时长）——单张截图与合成输入都不能替代。
