# WindowShade 1.0.14 · 与系统浑然一体

[产品官网](https://windowshade.pages.dev/) · [互动考古](https://windowshade.pages.dev/history/) · [English website](https://windowshade.pages.dev/en/)

1.0.13 让窗口浏览上线；1.0.14 把整个应用的表面接到同一份系统外观策略上，补齐代理应用缺失的 AppKit 契约，修掉三处“颜色被冻结”的真实缺陷，把可访问性补到能操作、能听见、能理解，并让窗口浏览可以像系统 Quick Look 一样先看一眼原窗口。

## 中文

### 与系统一致的外观

- **一套策略管全部表面。** 卷帘条、悬停缩略图、置顶预览、窗口浏览面板、设置与引导页共用同一份 `SystemAppearancePolicy`：材质、边线、薄纱、阴影、动画与字号都由它决定，不再各写一份。
- **动态颜色不再被冻结。** `NSColor.cgColor` 必须在视图自己的 `effectiveAppearance` 里解析；修好之前会出现“浅色行 + 深色面板”的错配。现在深色下选中的卡片行背景依次为 `1.000 → 0.118 → 1.000`（浅→深→浅），回归里有断言。
- **设置页在深色下可读。** 分组盒填充曾是被冻结的静态颜色，深色下仍是浅底、文字几乎看不清；改为绘制时解析的动态颜色，并逐页检查内容区平均亮度（浅深差 0.744–0.842）。
- **经典卷帘条跟随外观。** 配色改为持有 pid + `refreshPalette()`；“浅色下创建 → 切深色 → 刷新”与“直接在深色下创建”逐项一致，且与浅色配色不同（探针 `classic-strip-palette PASS`）。
- **回退都在。** 减少透明度用不透明底，提高对比度加粗边线、选中不只靠颜色，减少动态效果不做位移与缩放；四类系统设置变化都会刷新已经打开的表面。
- **字号跟随系统。** 窗口浏览与设置页的字号改为“相对正文字号”，随系统“文字大小”缩放；默认外观下设置页内容区与改动前逐像素零差异（`differing pixels=0`）。
- **圆角和 macOS 27 的窗口对上。** 以前每个表面各写各的（面板 16、卡片 12、图片 8、经典条整块直角、设置卡片 10、chip 3），曲线也一半正圆。现在统一读一份 `SystemCornerRadius`：窗口级 13 pt、内容级 12、控件级 6，图层一律连续曲率；卡片里的窗口画面按 HIG 的同心规则取“外圆角 − 内边距”（12 − 8 = 4 pt）。13 pt 是本机实测值：Finder 与 ChatGPT 窗口左上角弧长 26 px @2x，轮廓比正圆更平。经典卷帘条从整块直角改成“上面两角圆、下边缘直切”，与截图条的窗口 chrome 一致，纸面阴影跟随同一条轮廓。
- **面板贴着内容，也贴着 Dock 图标。** 单窗口 Dock 面板以前在卡片下方留一块空白（“下巴”）：页脚就算没有状态文字也占 19 pt、卡片标题无条件按两行预留、面板高度还多算了一圈没人使用的内边距。现在标题按实际行数取高、卡片没有状态就不留状态行、操作按钮浮在画面右上角而不占卡片高度，单窗口面板从 **312 × 329 pt 收到 312 × 236 pt**（有状态时 312 × 253 pt，带 120 ms 过渡）。底部 Dock 的面板整体贴近图标（图标区域上方 4 pt），最下方留 38 pt 标签带：指针停在图标上时，系统自己的应用名气泡正好落在带里成为面板的标签，指针移进面板、气泡收起后由面板的标签在同一位置接替，两者从不同时出现，应用名不再写第二遍。Dock 面板的页眉因此只留窗口数与显示方式（32 pt），单窗口不占页眉。玻璃路径的阴影改用系统窗口阴影，四角与玻璃圆角重合，不再露出自绘阴影的楔形边。
- **液态玻璃按 HIG 只用一层，内容就挂在玻璃里。** 以前面板背景是一层玻璃、控制层又叠一层玻璃，两层互相抹掉折射与高光，看起来就成了普通毛玻璃。现在全应用只保留一层 `NSGlassEffectView`（`regular` —— HIG 给文字多的弹窗/侧栏的默认档），并且按 AppKit 的约定把整个界面放进它的 `contentView`（头文件只保证这棵子树在玻璃效果里）；控制层玻璃、`NSGlassEffectContainerView` 协调容器和每张卡片自己的材质视图全部删除，卡片、列表行与详情栏只用系统填充色（静止 quinary、悬停/选中 quaternary、按下 tertiary）加一圈强调色描边。旧系统回退材质改用 `state = .active`，非 key 面板也照样透出背景；玻璃始终不上色。真实观感见 `docs/visual-qa/system-appearance/liquid-glass-panel.png`（屏幕截图，面板后方是确定性对照板，底部同一帧有系统 Dock 作原生对照）。

### 补齐 AppKit 契约

- **代理应用有了主菜单。** `LSUIElement` 应用原本没有主菜单，⌘X/⌘C/⌘V/⌘A/⌘Z 与 ⌘W 全部无效；现在有“关于 / 编辑 / 窗口”菜单。对照探针：无主菜单时 `handled=false searchText=""`，装好主菜单后 `handled=true searchText="粘贴内容"`。
- **协作式激活。** 8 处 `activate(ignoringOtherApps:)` 换成 macOS 14 起的 `NSApp.activate()`；两种方式在探针里都是 `active=true key=true`。
- **不再被系统并成标签页。** 设置、引导与面板显式 `tabbingMode = .disallowed`。
- **深链按本机能力排序。** 权限与“减少动态效果”的跳转先看本机有没有 ExtensionKit 面板，旧标识保留兜底（`hasModernPane=true hasModernAccessibilityPane=true`）。

### 可访问性

- 卡片与列表行：标签、值、帮助、自定义动作共用同一份能力模型；VoiceOver 焦点跟随方向键与搜索；**VO-Space 与鼠标点击走同一条激活路径**（不可用的动作返回 false，不会被朗读成可用）。
- 卷帘条（截图条与经典条）、悬停缩略图、菜单缩略图、置顶预览：朗读“这是哪个窗口”，提供“展开窗口 / 预览”动作，并有 tooltip。
- 动作结果与页脚结果状态各播报一次，不打断连续输入。

### 看一眼原窗口（Space）

- Space 打开当前窗口的**只读大图预览**：不激活、不展开、不移动源窗口。
- Escape 分层为「关大图 → 取消排布预览 → 关闭面板」，点大图也能关闭。
- 取图顺序固定为「新鲜服务缓存 → 过期快照（标注“快照（画面可能已过期）”）→ 折叠快照 → 应用图标 + 原因」；画面按比例放进可见区域并**整体钳回**，极小屏幕、负坐标与退化可用区域都有断言。
- 搜索框 Escape 先清空文本，⌘F 聚焦；键盘面板可以拖背景移动。

### 面板与菜单栏

- 单窗口面板紧凑，窗口截图与标题优先；动画 100–120 ms 并遵守减少动态效果。
- 左/右 Dock 的面板网格列数上限收紧到 2 列、宽度不超过 640 pt；底部 Dock 仍是 3 列。
- 首次显示只做一次整面板刷新（Dock 与键盘两条入口合并），说明文字只改页脚。
- 三个窗口的 Dock 面板改单行三列（912 × 286 pt），左/右 Dock 的列数上限在面板级与内容级布局共用同一份 `columnCap(edge:)`，列表不再溢出滚动区。
- 卡片画面 144 pt，圆角按画面本身取 8 pt；列表行 52 pt、行距 4 pt，用 `.plain` 样式不再画系统选中灰块，选中行是系统列表式的强调色实心底（面板非 key 时显示非强调灰底，不只靠描边环）；详情栏把画面放在标题上方；操作按钮 28 × 28、间距 4。次要说明字号下限从 9 pt 提到 macOS 的最小字号 10 pt。
- 键盘面板：Tab 在搜索框 → 列表/网格 → 显示方式之间循环，PageUp/PageDown 翻页，搜索框取系统固有高度。Dock 面板不画键盘选中环，当前项跟随指针；非 key 面板用 `.activeAlways` 追踪悬停，真实的进入/离开都能收到。
- 选中 100 ms、首图 80 ms、面板尺寸 120 ms 淡变，键盘面板整体淡入；减少动态效果下都不动。动作执行中操作条前方显示系统转圈。
- 搜索没有结果时列表区写明“没有匹配的窗口”；缺少屏幕录制权限时卡片只留应用图标，原因与“打开‘屏幕录制’设置…”入口在页脚出现一次；排布预览清掉页脚，描边内缩、连续曲率并随外观刷新。
- 菜单栏：折叠窗口前 9 个带 ⌃⌘1…9，其余进“更多”子菜单；置顶列表去掉误导性编号；菜单标题统一截断；临时提示只显示短标题（完整文案在 tooltip 与可访问性值里）。

### 本次一并修好的问题

- 动态颜色在错误外观下解析，窗口浏览在深色下出现浅色行。
- 设置页分组盒填充被冻结，深色下不可读；经典卷帘条配色不随外观更新。
- 首次显示时 Dock 与键盘入口各做一次整面板刷新，重复重建视图。
- 左/右 Dock 面板列数过多、面板过宽。
- 大图预览只查视图侧缓存（滚动即淘汰，且用错了缓存代），永远取不到最新画面。
- 大图预览不能点击关闭、VoiceOver 角色不是图像、极端尺寸下会超出可见区域。
- 卡片里的窗口画面是直角，和圆角卡片对不上；同一屏里正圆角与连续曲率混用。
- 截图归档里的示例画面每次渲染颜色都不一样（用了按进程随机播种的 `String.hashValue`），归档图无法逐像素比较；现在用稳定哈希，两次渲染逐字节一致。
- 单窗口 Dock 面板在卡片下方留 51 pt 空白：面板高度多算一圈无人消费的内边距、空页脚仍占位、短标题也按两行预留。
- 面板背景与控制层叠了两层 Liquid Glass，互相抵消折射与高光，观感退化成毛玻璃。
- 界面挂在玻璃的兄弟层里，玻璃宿主还裁掉了玻璃边缘；现在界面就在 `NSGlassEffectView.contentView` 内，宿主不再裁切。
- 每张卡片、每一行和详情栏各叠了一层 `.contentBackground` 材质视图，把玻璃盖成了白块；现在这些表面只用系统填充色。
- 截图服务的完成回调在锁内执行、计数在锁外统计；控制器释放后目标解析仍会回调；旧实时预览租约失败会给新选中的窗口报错；排布预览计时器与令牌脱钩。四项都已修好并有断言。
- 截图探针按 `NSScreen.main` 算屏幕坐标，多显示器时错位；改用原点在 (0,0) 的主显示器。
- 展开 / 收起侧栏不再改变窗口大小：设置窗口的最小尺寸曾写成 `splitController.view` 的 required 宽度约束，AppKit 只好在展开侧栏时把整扇窗口撑宽一个侧栏（实测 900 → 1115 pt）。现在最小尺寸只写在 `window.contentMinSize`，切侧栏只重新分配窗口内部宽度。
- 界面文案统一并简化：一个动作只有一个名字（收起 / 展开、置顶、窗口浏览、卷帘条），把实现术语（bundle ID、底层事务、PID、材质）从用户可见文字里拿掉，官网同步改成"用户会遇到什么"的说法。规则写在 `docs/copy-guide.md`。
- 设置页内容列贴着详情区左边，收起侧栏（详情区变成整窗宽）后右半边整片空白：窗口 1115 pt 宽时内容列只占 640 pt、右侧留白 447 pt。现在按 Apple 分组表单的摆法在详情区居中（900 × 680 窗口左右各 28 pt、1115 × 680 各 131 pt），截图探针每次渲染都会打印居中自检。

## English

### One appearance policy for every surface

- The shade strip, hover thumbnail, pinned preview, window-browser panel, settings and onboarding all read the same `SystemAppearancePolicy` — materials, hairlines, veils, shadows, animation and type scale.
- Dynamic colours are now resolved inside each view's `effectiveAppearance`. Before the fix a light row could sit on a dark panel; the selected row background now walks `1.000 → 0.118 → 1.000` and a regression asserts it.
- The settings group box no longer keeps a frozen light fill in dark mode (page-by-page brightness delta 0.744–0.842), and the classic strip recomputes its palette on appearance changes (`classic-strip-palette PASS`).
- Reduce Transparency, Increase Contrast, Reduce Motion and light/dark switches refresh already-open surfaces. Type sizes are relative to body text, and the settings content area stays pixel-identical to the previous release at the default appearance.
- **Corner radii now match the macOS 27 window.** Every surface read its own number before (panel 16, card 12, thumbnail 8, square classic strip, settings card 10, chip 3) and mixed circular with continuous curves. They now share one `SystemCornerRadius` scale — 13 pt for window-level surfaces, 12 for content, 6 for controls, always continuous — and the thumbnail inside a card follows the HIG concentric rule (outer radius minus the margin: 12 − 8 = 4 pt). The 13 pt figure is measured on this machine: Finder and ChatGPT windows show a 26 px @2x corner span with a flatter-than-circular profile. The classic strip gained rounded top corners with a straight bottom cut, matching the screenshot strip's window chrome, and the paper shadow follows the same outline.
- **The panel hugs its content, and the Dock icon.** A single-window Dock panel used to keep an empty band under the card: the footer reserved 19 pt even with nothing to say, the card title always reserved two lines, and the panel height counted an extra inset nobody consumed. Titles now take the height they actually need, a card without a status keeps no status line, and the actions float over the picture instead of holding a row of their own, so one window measures **312 × 236 pt** instead of 312 × 329 pt (312 × 253 pt when a status line does appear, with a 120 ms transition). Under a bottom Dock the panel sits 4 pt above the icon and keeps a 38 pt band at its foot: the system's own app-name bubble lands in that band while the pointer is on the icon, and once it fades the panel's label takes the same place, so the name is never written twice. The Dock header keeps only the window count and the display style (32 pt), and a single window has no header at all. The glass path now takes the system's window shadow, so the shadow's corners match the glass corners instead of showing the wedges of the drawn shadow.
- **Liquid Glass follows the HIG's layer discipline, and the interface lives inside it.** The panel used to stack two glass layers (panel background plus a glass control strip), which cancelled each other's refraction and highlights and read as ordinary frosted glass. The app now keeps exactly one `NSGlassEffectView` — the `regular` variant, which the HIG prescribes for text-heavy popovers — and hangs the whole interface off its `contentView`, the only subtree the header guarantees sits inside the glass. The control-layer glass, the `NSGlassEffectContainerView` coordinator and every per-card material view are gone: cards, rows and the detail pane use system fills only (quinary at rest, quaternary on hover or selection, tertiary while pressed) plus an accent ring. The pre-glass fallback uses `.active` so non-key panels stay translucent, and the glass is never tinted. Real appearance: `docs/visual-qa/system-appearance/liquid-glass-panel.png`.

### AppKit contracts

- The agent app now installs a real main menu, so ⌘X/⌘C/⌘V/⌘A/⌘Z and ⌘W work. Probe: without a menu `handled=false searchText=""`; with it `handled=true searchText="粘贴内容"`.
- Cooperative `NSApp.activate()` replaces `activate(ignoringOtherApps:)` in eight places; settings, onboarding and panels opt out of system tabbing; settings deep links prefer the modern ExtensionKit panes with the legacy identifiers kept as fallback.

### Accessibility

- Cards and rows share one capability model for label, value, help and custom actions; VoiceOver focus follows arrow keys and search; VoiceOver-Space and a mouse click take the same activation path.
- Strips, hover thumbnails, menu thumbnails and pinned previews announce which window they belong to and expose their actions; results are announced once without interrupting typing.

### Space: take a look

- Space shows a read-only large preview without activating, unfolding or moving the source window; Escape layers as "close preview → cancel arrangement preview → close panel", and clicking the image closes it.
- Image order is fresh service cache → stale snapshot (labelled as possibly out of date) → folded snapshot → app icon plus a reason; the frame is proportionally fitted and clamped back into the visible area.

### Panel

- Three windows on the bottom Dock now sit in a single row of three columns (912 × 286 pt); the left/right Dock column cap is shared by the panel-level and content-level layout instead of being written twice, and the list no longer overflows its scroll area.
- The card picture is 144 pt with an 8 pt radius that follows the picture itself, rows are 52 pt with 4 pt spacing in a plain table with no system selection block, the selected row uses the system list's solid emphasis fill (a non-emphasis grey when the panel is not key, rather than a ring alone), the detail pane puts the picture above the title, and the action buttons are 28 × 28 with 4 pt gaps. The secondary type floor moves from 9 to the 10 pt macOS minimum.
- Tab cycles search → list/grid → display style, PageUp/PageDown page through the list, and the Dock panel tracks the pointer instead of painting a keyboard ring; a non-key panel tracks hover with `.activeAlways`, so real pointer enters and exits both arrive.
- Selection fades over 100 ms, the first picture over 80 ms, the panel resize over 120 ms, and the keyboard panel fades in as a whole; none of it moves under Reduce Motion. A running action shows the system spinner in the action bar.
- An empty search says so, a missing screen-recording permission keeps the icon only and puts the reason and the "Open Screen Recording settings…" entry in the footer once, and the arrangement preview clears the footer, insets its outline and follows appearance changes.

### Also fixed

- The interface hung off a sibling of the glass, and the glass host clipped the glass edge; it now sits in `NSGlassEffectView.contentView` with no clipping.
- Every card, row and the detail pane carried its own `.contentBackground` material view, which flattened the glass into a white block; those surfaces now use system fills only.
- The thumbnail service ran its completion callbacks inside its lock and counted outside it, a released controller still resolved targets, a failed live-preview lease reported an error against the newly selected window, and the arrangement preview's timer outlived its token.
- The shots probe computed screen coordinates from `NSScreen.main`, which is wrong with several displays; it now uses the display whose origin is (0, 0).
- Toggling the sidebar no longer resizes the window. The settings window expressed its minimum size as a required width constraint on the split view, so AppKit satisfied it by widening the whole window by one sidebar (900 → 1115 pt measured). The minimum now lives in `window.contentMinSize`, and toggling the sidebar only redistributes width inside the window.
- The interface copy now uses one name for one thing (roll up / unroll, pin, window browsing, the bar) and drops implementation words (bundle ID, PID, materials) from anything a person reads; the site says what happens rather than how it works. The rules live in `docs/copy-guide.md`.
- The settings pages pinned their 640 pt content column to the leading edge of the detail pane, so hiding the sidebar (which widens the pane to the whole window) left 447 pt of blank space down the right side of a 1115 pt window. The column is now centred the way Apple's grouped forms are (28 pt each side at 900 × 680, 131 pt at 1115 × 680), and the shots probe prints a centring self-check on every render.

### Performance

120 windows fill and lay out in 24.2 / 30.4 ms (p50/p95) against 271.8 / 342.8 ms on the baseline commit, measured back to back in one session on the same machine; warm refresh stays inside the 4 ms p95 budget (0.95–2.82 ms). The machine was busy during this run, which pushed even the baseline from its earlier 200 ms — the relative improvement is what the two runs agree on.

## 安装与已知边界

下载下方 **WindowShade-v1.0.14.zip**，解压后将应用移入“应用程序”。需要 **macOS 14+、Apple Silicon**；本包不包含 Intel 二进制，附带 SHA-256 校验文件。

沿用现有 **Apple Development** 签名及 bundle 标识，**尚未公证**。若首次启动被 macOS 阻止，请使用系统“隐私与安全性”里的“仍要打开”。

窗口浏览需要**辅助功能**权限，缩略图与实时画面还需要**屏幕录制**权限。面板是临时窗口：它不替换系统 Dock，也不接管原生 Command-Tab。
