# 锁屏小窗口探针（阶段 1B）

只为一个问题存在：**这台机器、这个系统构建上，私有空间配方能不能让一个普通窗口出现在真正的锁屏上，
而且不影响系统认证、解锁后自己消失。** 它不是 App 的一部分，单独编译、单独运行，不随包发布。

## 跑法

```sh
bash tests/run-lock-probe.sh                       # 只查六个私有符号在不在（安全）
bash tests/run-lock-probe.sh --level-only          # 对照组：同样的小窗口，只提高窗口层级
bash tests/run-lock-probe.sh --space               # 实验组：上游的私有空间配方
bash tests/run-lock-probe.sh --space --pre-create  # 锁屏前就把窗口建好（对照组之二）
```

按提示按 ⌃⌘Q 锁屏，看右上角 240×48 的小条有没有在数数，然后用**系统认证**解锁。
日志写到 `.build/lock-probe/probe-<时间>.log`。

## 安全规矩

- 非 key、非 main、整窗 `ignoresMouseEvents`，放屏幕右上角，不进认证区域正中——**不挡认证**。
- 自己到期撤场（`--seconds`，默认 90 秒），外面还有一层父进程硬超时（`perl alarm`，不用 root）。
- **探针绝不尝试解锁。** 锁是你按的，解锁是你用系统认证做的；这个仓库里不会有替用户解锁的代码。
- 只在真锁屏上动手；没锁上就什么都不做（退出码 3）。

## 一次实验要观察什么

至少这几条同时成立才算「能看见」：系统锁屏界面还在；计数确实在更新；认证入口照常可用；
解锁后小条自己消失；退出探针后没有残影或空间异常。

**单项不算证据**：`isVisible == true`、alpha 为 1、SLS 返回 0、drawable 已呈现，任何一条单独成立都不说明问题。

## 已知不确定（照 ChatGPT Pro 的审查）

- 这组符号的**声明（`Int32`／参数含义／返回类型）没有核定 ABI**，这里照上游配方原样用，只记录原始返回值；
  现有 `prototype/Private/SkyLightBridge.swift` 里的空间编号是 `UInt64`，**不要**为了这个实验去收窄它。
- 符号存在 ≠ ABI 对 ≠ 锁屏可见 ≠ 生命周期可恢复。这个探针只回答第三层里最基础的那一问。
- 未验证的系统版本与架构一律默认关闭新能力。
