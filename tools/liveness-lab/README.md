# 活体时序小样

`LivenessChallenge.swift` 是独立的实验状态机，尚未接相机、身份模型、注视模型或系统解锁。
它检查输入时序，不能凭合成样本通过就声称真人活体通过或抵御录像。

```sh
bash tests/run-liveness-tests.sh
```

每次交易随机选眨眼、点头、向左或向右转头。指令实际呈现后建立基线，动作跨新帧持续，
回正、睁眼并恢复注视后生成一次性证据。换人、丢脸、多人、相机/目标显示器与校准/锁屏代次变化、过期、
重复帧、乱序和取消均不能沿用结果；不可用的图像或关键点会清掉动作进度。

所有时间须在同一单调时钟域。接线时从采集 PTS 映射时间，不能填推理完成时间；
同一轨迹的身份必须由身份适配器持续验证。头部姿态需统一镜像坐标方向。
displayTargetReference 必须由适配器核定显示器及注视校准配置；不能为空。
状态机限定在一条串行队列/actor 内使用，未来异步回调在该处汇合。

`LivenessTuning` 的数值仅供合成测试；不能直接作为发布阈值。
后续必须采集本人、眼镜、光照、照片、预录视频等真机数据，分别评估错误接受、错误拒绝、
攻击通过率和延迟，再接设备因素。`takeEvidence` 仅交付动作证据，不触发任何解锁。
